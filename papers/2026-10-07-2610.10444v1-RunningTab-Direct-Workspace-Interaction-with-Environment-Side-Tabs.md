# RunningTab: Direct Workspace Interaction with Environment-Side Tabs

**Authors:** Jinheon Baek, Soyeong Jeong, Yumin Choi, Dongsu Han, Sung Ju Hwang
**Published:** 2026-10-07 | **arXiv:** [2610.10444v1](http://arxiv.org/abs/2610.10444v1)

## Summary
This paper addresses a critical limitation in LLM agents performing knowledge work: they lose track of task requirements and file provenance as they search through workspaces. RunningTab solves this by maintaining an environment-side "tab"—a persistent record of what the task requires, what files have been read, and what remains unopened—allowing agents to reliably complete multi-file deliverables without dropping critical information from their context window.

## Theoretical Background
The paper builds on two converging ideas. First, recent work shows LLM agents can interact directly with corpora (collections of files) via terminal-like interfaces, searching and reading documents without pre-built indexes. Second, there is a known problem in agent design: as context windows fill, agents forget constraints and commitments. The work also relates to classical memory and planning literature—the core insight is that offloading task state to the environment (not the model) creates a reliable external anchor, similar to how humans use checklists or notebooks during complex work.

## Core Contributions
1. **RunningTab framework**: A formalized way to track per-task state on the environment side (not in the LLM's context), recording task requirements, read file excerpts with provenance, and unopened file candidates.
2. **Finish-check mechanism**: A validation step that prevents agents from submitting deliverables with unresolved requirements.
3. **Empirical validation**: Consistent improvements over plain direct workspace interaction (DWI) and baseline approaches that keep state in the model, tested across three benchmarks and three LLMs.

## Connections to Other Work
RunningTab extends the emerging paradigm of [[direct workspace interaction]] for LLM agents. It relates to broader work on [[agents]] maintaining state and grounding in external tools—similar to how [[RLHF]] and memory-augmented systems help models stay on task. The environment-side record is conceptually adjacent to systems like tool-use frameworks and prompt engineering techniques that externalize reasoning (e.g., chain-of-thought), but with formal task accounting.

## Practical Applications
- **Research synthesis**: Automatically compiling literature reviews from document collections, tracking which papers contributed to which sections.
- **Contract analysis**: Reviewing multiple legal documents, identifying clauses, and producing summaries with exact file and line references.
- **Report generation**: Gathering data from multiple spreadsheets and logs, ensuring all required metrics appear in the final output.
- **Audit workflows**: Tracing compliance evidence from a file corpus, maintaining a record of what was checked and what gaps remain.

## Product & Startup Ideas
1. **AI Research Assistant**: A paid SaaS tool for academics and analysts that packages RunningTab with a document corpus ingestion layer, auto-generating literature reviews and research summaries with full citation provenance.
2. **Enterprise Compliance Engine**: Internal tool for legal/audit teams that uses RunningTab to orchestrate multi-document review, auto-populating compliance checklists and flagging unchecked requirements.
3. **Smart Knowledge Base Agent**: A Slack/Teams bot that maintains workspace tabs across stored files and tickets, letting teams ask multi-document questions with guaranteed completeness and traceability.
4. **Data-Driven Report Automation**: White-label service for consulting firms that uses RunningTab to auto-generate client reports from mixed data sources (dashboards, raw files, external APIs), with built-in quality assurance.
5. **Open-Source IDE Plugin**: Developer tool (VSCode, JetBrains) that augments coding agents with RunningTab to ensure they address all TODO comments, code review notes, and architectural requirements before committing.

## Technical Limitations
- **Scalability of tab state**: As task complexity grows (hundreds of requirements, thousands of candidate files), the tab itself may become unwieldy; no analysis of performance degradation.
- **Environment-side assumptions**: Assumes the environment can reliably store and retrieve the tab; doesn't address failure modes (crash, corruption, lost state).
- **Excerpt quality**: The value of the system depends on search quality and excerpt length; poor retrieval will pollute the tab with irrelevant matches.
- **Model generalization**: Tested on three models; unclear how the approach scales to future architectures or significantly smaller/larger models.
- **No cross-task learning**: Each task gets its own fresh tab; no mechanism to transfer knowledge from past task structures to new ones.

## Open Questions
- How does performance scale with task complexity (number of requirements, file count, deliverable size)?
- Can the tab be shared or transferred between agents, or across sequential tasks?
- What is the optimal strategy for excerpt length and candidate ranking—is it task-agnostic or adaptive?
- Does RunningTab improve agent robustness to adversarial or malformed input files?
- How does the approach compare on tasks where the workspace structure is hierarchical or highly unstructured (e.g., email archives, chat logs)?
- Can the environment-side tab be used to guide the agent's search strategy proactively, rather than just recording what was found?

## Key Takeaway
Offloading task tracking to the environment, not the LLM, lets agents reliably complete multi-document work without losing context.
