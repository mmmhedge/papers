# Handover of In-Context Learning State Across Session Boundaries

**Authors:** Masahiro Kato, Taka Kato
**Published:** 2026-08-14 | **arXiv:** [2608.14528v1](http://arxiv.org/abs/2608.14528v1)

## Summary
This paper addresses a practical problem: when an LLM task spans multiple sessions (due to context limits, restarts, or handoffs to other agents), what information must be preserved to maintain the model's understanding? The authors develop a theoretical framework showing that handover can be characterized by predictive equivalence, derive memory requirements for different scenarios, and propose a three-part record structure that balances fidelity with efficiency. This matters because multi-session workflows are common in real applications, yet there's no principled way to decide what to save.

## Theoretical Background
The paper builds on two foundational ideas: *in-context learning* (ICL)—the ability of LLMs to learn patterns from examples in the prompt without updating weights—and *sufficient statistics* from classical statistics, which capture the minimal information needed to make optimal predictions about a future outcome. The authors frame session handover as a state-transfer problem, drawing on information theory and statistical decision theory. They invoke an exogeneity condition (loosely: the task structure doesn't depend on how information was written down) and use predictive equivalence—the idea that two descriptions of past data are interchangeable if they yield identical predictive distributions for future queries—as their central organizing principle. This connects to classical work on sufficient statistics and extends it to the LLM setting.

## Core Contributions
1. **Formal problem definition**: Handover is cast as the transfer of a task-relative ICL state, distinguishing exact recovery (reproducing the prior session's prompt) from distribution preservation (maintaining predictive equivalence).
2. **Theoretical characterization**: Under exogeneity, predictive equivalence determines the coarsest deterministic sufficient handover, and the authors derive fixed-length bit requirements for this handover.
3. **Practical three-part record structure**: A concrete proposal storing (a) exact decisions and constraints, (b) task-justified summary statistics for repeated evidence, and (c) original observations not captured by those statistics.
4. **Finite-dimensional bounds**: For Gaussian linear regression, an exact finite-dimensional handover is possible with finite-bit perturbation bounds; for nonparametric regression, upper and lower bounds relating memory to prediction error.
5. **Isolation of effects**: Quantifies separately the cost of memory constraints, the writer's choice of representation, and the continuation procedure.

## Connections to Other Work
This work relates to [[Attention Is All You Need]] and transformer-based LLMs in that it assumes in-context learning as a mechanism. It shares intellectual roots with [[RLHF]] and alignment research insofar as it concerns control and consistency of agent behavior across boundaries. The sufficient statistics framework echoes classical work in statistics and decision theory. The multi-agent aspect (when one agent hands off to another) connects to [[multi-agent-systems]] literature on coordination and state transfer. The memory-accuracy trade-off resonates with quantization and compression work in deep learning.

## Practical Applications
1. **Long-document processing**: When summarizing or analyzing documents exceeding token limits, intelligently compress prior context so the continuation model resumes without losing critical details.
2. **Multi-turn customer service**: Hand off conversations between agents (human or AI) without requiring the new agent to re-read the full history; pass only task-relevant summaries and unresolved facts.
3. **Collaborative AI workflows**: When tasks span multiple LLM calls (e.g., research, coding, planning), deterministically decide what intermediate results and reasoning to retain for the next stage.
4. **Mobile/embedded LLM applications**: Persist in-context state across sessions when the model or app restarts, minimizing storage while preserving task understanding.
5. **Federated/distributed inference**: Coordinate multiple model instances working on the same task; handover protocol ensures each instance receives sufficient information to remain synchronized.

## Product & Startup Ideas
1. **Session State Manager for LLM APIs**: A middleware service that automatically optimizes and compresses handover state for any LLM application (Claude, GPT, open-source models), reducing token costs and latency in multi-session workflows.
2. **Long-Document Intelligence Platform**: A product that lets users upload huge PDFs, books, or codebases, then query them iteratively without token-limit errors by automatically managing context handover and preserving only relevant information across sessions.
3. **Agentic Workflow Orchestrator**: A framework/SaaS for building complex multi-agent systems (QA + summary + decision-making), with built-in handover logic that ensures each agent receives the exact minimal state needed to do its job.
4. **Memory-Efficient Fine-Tuning for Edge Models**: A developer tool that optimizes which observations and statistics to retain when adapting a small LLM to new tasks across device boundaries, minimizing storage and latency.
5. **Enterprise Agent Governance**: A compliance/audit layer for business LLM applications that provably logs which information was handed over between agents/sessions, with formal proofs of information preservation for regulatory requirements.

## Technical Limitations
1. **Exogeneity assumption may break**: In adversarial or adaptive settings, the way information is written *can* affect downstream behavior; the theory doesn't cover this.
2. **ICL as assumed mechanism**: The framework assumes in-context learning is the primary learning mode; doesn't address systems with memory retrieval, external databases, or fine-tuning.
3. **Gaussian linear regression as the "solved" case**: Nonparametric bounds are looser; real LLM tasks are far more complex than either case, so gap between theory and practice is large.
4. **Static task assumption**: The theory assumes the continuation task is drawn from a fixed distribution; if the goal shifts mid-session, the handover may be suboptimal.
5. **No empirical validation**: The paper is theoretical; no experiments showing whether the three-part record actually works in practice on real multi-session LLM tasks.
6. **Context quality unknown**: Assumes the new session can use whatever handover is provided; doesn't account for LLM degradation when context is compressed or reformatted.

## Open Questions
1. **Empirical validation**: Does the three-part record structure actually preserve performance on real tasks (e.g., long conversations, multi-step reasoning, domain-specific QA) compared to naive baselines?
2. **Adaptive task settings**: How should handover change when the continuation task is uncertain or adversarial at the time of handover?
3. **Scaling to real task complexity**: Can the Gaussian/nonparametric analysis extend to deep learning or transformer feature spaces, or are there fundamentally different regimes?
4. **Multi-agent bargaining**: When multiple agents compete for limited handover budget, what is the game-theoretic equilibrium, and who decides the allocation?
5. **Failure recovery**: If handover is lossy or corrupted, can the system detect and repair the state, or should continuation happen differently?
6. **Interaction with prompting strategies**: How do prompt engineering, chain-of-thought, and other in-context strategies change the optimal handover structure?

## Key Takeaway
LLM multi-session tasks need principled rules for what information to save; this paper gives theory and methods for minimal sufficient handover state.
