# AgentDiscover: Autonomous Discovery with Minimal Search Scaffolding

**Authors:** Mahdi Farahbakhsh, Ilan Sela, Fatemeh Doudi, Vishnu Teja Kunde, Krishna Narayanan et al.
**Published:** 2026-10-04 | **arXiv:** [2610.05334v1](http://arxiv.org/abs/2610.05334v1)

## Summary
This paper presents AgentDiscover, a system where an AI agent autonomously plans and conducts scientific searches rather than following a fixed human-designed algorithm. Instead of treating the language model as merely a proposal generator, the system lets it own the entire search strategy, using a persistent database as working memory. The approach outperforms existing frameworks on diverse tasks—kernel engineering, biology, algorithm design, and mathematics—while being more cost-efficient.

## Theoretical Background
The work builds on two key concepts: (1) **Large language models as agents** — systems where LLMs don't just generate text but make decisions, plan sequences of actions, and interact with external tools and memory; and (2) **Classical search algorithms** like MAP-Elites (a quality-diversity evolutionary algorithm) and Monte Carlo tree search (which balances exploration and exploitation). The paper also invokes the "Bitter Lesson" from AI research—the observation that hand-crafted structure tends to lose to general methods given sufficient compute. Prior scientific discovery frameworks used LLMs as "proposers" within human-designed scaffolding; AgentDiscover flips this by letting the model itself choose the search strategy.

## Core Contributions
1. **Agent-driven search planning**: The agent uses its context window as working memory to decide what to explore next, rather than following a predetermined algorithm.
2. **Database-as-long-term-memory**: A persistent, queryable database of all candidates, experiments, and relations allows the agent to learn from prior work and accumulate knowledge across long runs.
3. **Algorithmic flexibility**: Classical search operations (MAP-Elites selection, MCTS queries) reduce to single database queries that the agent can invoke, combine, or replace with its own logic.
4. **Empirical validation**: Demonstrated improvements over baselines on real tasks (AtCoder contests, mathematical optimization, systems problems) at lower computational cost.

## Connections to Other Work
This extends research on [[Agents]] and [[Large Language Models]] for scientific discovery. It relates to broader work on LLM-based planning and reasoning (chain-of-thought, tool use), and echoes principles from [[Reinforcement Learning]] where agents learn exploration strategies. The database abstraction connects to meta-learning and curriculum learning ideas—the agent builds its own curriculum by querying what to explore next. It also bridges classical AI search methods (MCTS, evolutionary algorithms) with modern LLM capabilities, addressing a gap where prior work treated these as orthogonal.

## Practical Applications
1. **Automated kernel optimization**: Discovering faster algorithms for computational kernels in systems software and machine learning libraries.
2. **Drug discovery and molecular design**: Autonomous search for novel compounds or protein sequences without exhaustive enumeration.
3. **Algorithm design competitions**: Heuristic optimization for combinatorial problems (as demonstrated in AtCoder contests).
4. **Mathematical problem-solving**: Automated discovery of proofs, constructions, or counterexamples for open conjectures.
5. **Hardware design space exploration**: Finding efficient circuit designs or microarchitectures by iteratively proposing and evaluating candidates.

## Product & Startup Ideas
1. **Scientific Research Automation Platform**: A SaaS tool where researchers upload problem specifications and AgentDiscover runs autonomous discovery pipelines, reporting novel solutions and explaining the search trajectory.
2. **Competitive Programming Copilot**: Real-time assistance for AtCoder-style contests, generating high-scoring heuristics and explaining the reasoning behind proposed approaches.
3. **Drug Discovery Accelerator**: A platform for pharmaceutical companies to run autonomous molecular design searches, with database tracking of candidates and learned patterns to guide future runs.
4. **Mathematical Proof Assistant**: An IDE-like tool where mathematicians sketch conjectures and AgentDiscover explores proof strategies, candidate lemmas, and counterexamples autonomously.
5. **Kernel Optimization Service**: Enterprise offering for HPC centers and ML companies to continuously discover and deploy faster implementations of critical operations (linear algebra, convolutions, etc.).

## Technical Limitations
1. **Context window constraints**: The agent's working memory is bounded by the LLM's context length; long discovery campaigns may lose access to early insights.
2. **Database query design**: The system assumes the database schema and queries are sufficient; mismatch between what the agent wants to find and what queries can express could bottleneck performance.
3. **Steering overhead**: The server must continually steer the agent to keep it "on course"—unclear how robust this is to agent drift or novel search patterns the designers didn't anticipate.
4. **Model dependency**: Performance is tightly coupled to the underlying LLM's reasoning and planning ability; weaker models may struggle to use the flexibility effectively.
5. **Cost accounting**: While the paper claims cost-efficiency, fine-grained cost breakdown (API calls, database operations, server overhead) is not detailed; true cost curves over longer runs are unclear.
6. **Evaluation scope**: Tasks are mostly algorithmic or mathematical; generalization to domains requiring extensive real-world experimentation (e.g., wet-lab biology) is unproven.

## Open Questions
1. **Long-horizon scaling**: How does performance degrade as search depth increases? Does the agent's ability to use the database effectively decay over dozens or hundreds of iterations?
2. **Transfer and generalization**: Can an agent trained on kernel optimization learn to transfer patterns to, say, mathematical proof search? Or is each domain discovery task de novo?
3. **Failure modes and robustness**: What happens when the agent gets stuck in local optima? Does server steering reliably unstick it, or are there systematic failure modes?
4. **Interpretability of agent search**: Can we extract and understand the implicit search strategy the agent learned? What heuristics does it converge to?
5. **Scaling to real experiments**: Tasks here involve cheap computation. What changes when experiments are expensive (lab time, compute cost)? Does the agent learn to be selective?
6. **Comparison to human-in-the-loop**: How does AgentDiscover compare to interactive systems where humans periodically inspect and redirect the search? When does autonomy win?

## Key Takeaway
Autonomous agents planning their own search outperform fixed human-designed algorithms on diverse discovery tasks, using a persistent memory of prior attempts.
