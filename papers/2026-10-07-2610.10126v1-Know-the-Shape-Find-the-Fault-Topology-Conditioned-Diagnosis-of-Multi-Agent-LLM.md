# Know the Shape, Find the Fault: Topology-Conditioned Diagnosis of Multi-Agent LLM Failures

**Authors:** Xinwen Liu, Zhuocheng Pan, Isabella Zhu, Jawei Zhang, Xudong Liu et al.
**Published:** 2026-10-07 | **arXiv:** [2610.10126v1](http://arxiv.org/abs/2610.10126v1)

## Summary
This paper addresses a critical problem in multi-agent LLM systems: when coordinated task execution fails, different underlying causes can produce identical-looking failure symptoms. The authors show that the communication topology—the structure of how agents exchange information—is a strong signal for distinguishing failure types, and propose MAScope, a two-stage framework that recovers this topology from execution traces and uses it to diagnose failures more accurately and cheaply than existing methods.

## Theoretical Background
Multi-agent systems rely on structured coordination, where agents communicate via message passing to accomplish complex tasks. Prior work in multi-agent diagnostics typically treats execution traces as flat sequences of events, missing the relational structure of how information flows. This paper builds on two key insights: (1) graph-based representations capture agent interactions as nodes and edges, which can encode communication patterns, and (2) conditional classification—using structural context to improve predictions—is a well-established technique in machine learning. The novelty is grounding these ideas in the specific problem of LLM agent failure diagnosis, where explicit topology labels are unavailable but can be inferred from message evidence in traces.

## Core Contributions
1. **Empirical finding**: Demonstrates a statistically significant association between communication topology and failure type (χ² = 409.9, p = 1.2 × 10⁻⁷⁰), establishing topology as a diagnostic signal.
2. **Trace Structural Extractor (TSE)**: A method to recover implicit communication topology from heterogeneous execution traces by grounding an interaction graph in observable message evidence, without requiring explicit labels.
3. **Topology-Conditioned Judge (TC-Judge)**: A classifier that incorporates predicted topology, empirical failure priors, and topology-specific failure patterns to improve diagnosis accuracy.
4. **Cost-efficiency**: Shows the pipeline achieves 94% of GPT-5.4 diagnosis quality at only ~6% of the cost when topology is reused across executions under fixed orchestration.

## Practical Applications
1. **Real-time multi-agent system monitoring**: Deploy MAScope in production LLM orchestration systems (e.g., ReAct agents, tool-calling pipelines) to quickly identify whether failures stem from miscommunication, agent confusion, or trust/verification issues.
2. **Post-mortem incident analysis**: Use recovered topology to understand root causes of multi-agent system outages, informing system redesign.
3. **Automated agent choreography improvement**: Suggest topology rewiring based on failure patterns to reduce coordination failures.
4. **Cost-optimized LLM diagnostics**: Replace expensive repeated GPT-5.4 calls with lighter models augmented by topology context, suitable for high-volume trace analysis.

## Product & Startup Ideas
1. **Multi-Agent Debug Dashboard**: SaaS tool that ingests execution traces from LLM agent systems, auto-recovers topology, and surfaces root-cause failure diagnoses with recommended fixes—target: enterprise LLM orchestration platforms.
2. **Topology-Aware Agent Testing Framework**: CLI/SDK for developers building multi-agent LLM systems; automatically injects failures, recovers expected topology, and validates diagnosis accuracy before deployment.
3. **Agent Reliability Analytics**: Continuous monitoring service that tracks communication topology evolution and failure modes over time, providing ops teams predictive alerts when topology drifts toward failure-prone configurations.
4. **Lightweight Diagnostic Copilot**: Lightweight LLM proxy that learns topology-conditioned failure patterns for a customer's agent system, then diagnoses new failures 10–20× cheaper than using full-scale models.
5. **Failure Pattern Marketplace**: Platform where teams share topology-conditioned failure models (learned from their labeled traces), allowing new systems to bootstrap diagnosis with transfer learning.

## Technical Limitations
1. **Requires labeled traces for prior estimation**: The framework needs a corpus of already-labeled failures to estimate empirical failure priors; cold-start scenarios without labels are not addressed.
2. **Fixed orchestration assumption**: Topology recovery is reusable only under fixed orchestration; dynamic agent spawning or topology changes would require re-extraction.
3. **Message evidence dependency**: TSE relies on observable message evidence in traces; if agents communicate via side channels (e.g., shared state, external APIs) not logged in traces, topology recovery fails.
4. **Limited failure granularity**: The paper does not clarify how fine-grained failure classification can be (e.g., can it distinguish between "agent A ignored agent B's message" vs. "agent A misunderstood agent B's intent"?).
5. **Generalization across domains**: Experiments use a single benchmark (MAST-clean); unclear whether topology-conditioned diagnosis generalizes to radically different agent coordination patterns (e.g., hierarchical vs. peer-to-peer, synchronous vs. asynchronous).

## Open Questions
1. How does TSE perform when traces are partial or corrupted (e.g., dropped messages, timeouts)? Can it still recover meaningful topology?
2. Can topology-conditioned diagnosis scale to systems with hundreds of agents, or does computational complexity of graph extraction become prohibitive?
3. How sensitive is the framework to misspecification of failure priors? What happens if the prior distribution shifts post-deployment?
4. Does the approach work for *emergent* failure modes (failures not seen in the labeled training set)? Can it flag unknown unknowns?
5. Can the framework provide *actionable* recommendations (e.g., "rewire agent B to communicate with agent C instead of agent A") to prevent future failures, or only diagnose retrospectively?

## Key Takeaway
Communication topology between agents is a strong signal for diagnosing multi-agent LLM failures; recovering it from traces enables cheap, accurate diagnosis.
