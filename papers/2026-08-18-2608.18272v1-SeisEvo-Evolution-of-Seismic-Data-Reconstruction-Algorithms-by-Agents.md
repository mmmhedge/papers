# SeisEvo: Evolution of Seismic Data Reconstruction Algorithms by Agents

**Authors:** Yingjie Xu, Siwei Yu, Jianwei Ma
**Published:** 2026-08-18 | **arXiv:** [2608.18272v1](http://arxiv.org/abs/2608.18272v1)

## Summary
This paper presents SeisEvo, a system that uses LLM-driven agents to automatically discover seismic data reconstruction algorithms rather than manually designing them or training neural networks. The key insight is that agents search through the design space of algorithm components (while respecting physical constraints), producing interpretable, standalone algorithms that outperform classical methods by 3–7 dB in signal-to-noise ratio without requiring any agent or neural network at inference time.

## Theoretical Background
Seismic data reconstruction is a classical signal processing problem: sensor arrays often record incomplete data (missing traces, noise, or both), and reconstruction fills gaps. Traditional approaches use manually designed priors (e.g., sparsity, smoothness) combined with iterative solvers — for example, POCS (Projections Onto Convex Sets) and MSSA (Multichannel Singular Spectrum Analysis). Deep learning has become an alternative: it learns reconstruction rules from data but produces black-box models that are hard to inspect or modify. This paper sits in between: it uses LLMs as agents to search the design space of explicit, modular reconstruction operators — treating algorithm design itself as a search problem rather than a manual or end-to-end learning task.

## Core Contributions
1. **Agentic algorithm evolution**: Frames seismic operator design as an LLM-guided search task over modifiable algorithm components, not as neural network training.
2. **Two discovered algorithms**:
   - *Evo-POCS*: A residual-gated, phase-aligned dip-consistency projection that improves POCS by 3.49 dB (SNR) on interpolation tasks across 30–70% missing data.
   - *Evo-MSSA*: A reliability-grouped singular-value shrinkage achieving 7 dB improvement over classic MSSA and 3 dB over rank-reduction baselines on joint interpolation-denoising.
3. **Generalization**: Both discovered algorithms retain gains on held-out test data, suggesting the search found genuinely useful structures, not overfits.
4. **White-box output**: The final product is a standalone, human-inspectable algorithm—no agent or neural network needed at runtime, enabling simple deployment and modification.

## Connections to Other Work
This work bridges [[mechanistic-interpretability]] (producing transparent, modular algorithms) and [[agents]] (using LLMs as search engines). It relates to program synthesis and neural architecture search (NAS), which also automate algorithm discovery, but differs by maintaining explicit, human-readable operators and hard constraints (physics-based filtering). It complements deep-learning approaches like those in [[generative-models]] and [[deep-learning]] by offering an alternative route: rather than learning end-to-end, evolve structured operators that remain interpretable. ## Practical Applications
1. **Oil and gas exploration**: Faster, more reliable seismic imaging for subsurface mapping; reduced manual tuning of processing pipelines.
2. **Earthquake monitoring networks**: Real-time seismic data gap-filling from sparse or damaged sensor arrays.
3. **Geothermal prospecting**: High-quality reconstruction of incomplete surveys at lower computational cost than deep learning.
4. **Microseismic monitoring**: Denoising and interpolating induced seismic events in hydraulic fracturing operations.
5. **Portable seismic surveys**: Field-deployable algorithms (no GPU/agent needed) for resource-constrained environments (e.g., remote regions, embedded systems).

## Product & Startup Ideas
1. **SeisEvo-as-a-Service**: Cloud platform where geophysicists upload proprietary reconstruction problems and the system evolves tailored algorithms, then returns them as lightweight, deployable code (no vendor lock-in).
2. **Interpretable seismic processor plug-in**: Desktop software (MATLAB, Python library) that lets oil-and-gas processors use the discovered operators or evolve new ones for specific survey geometries, with visualizations of what each component does.
3. **Hardware-accelerated seismic edge device**: Embed Evo-POCS/Evo-MSSA in low-power FPGAs for real-time seismic array processing on IoT sensor networks; market to microseismic and earthquake-monitoring startups.
4. **Domain-specific algorithm evolution platform**: Generalize SeisEvo to other inverse problems (medical imaging, radar, sonar); sell the framework to instrumentation companies needing fast, interpretable reconstruction.
5. **Geophysics consulting tool**: Offer clients rapid algorithm redesign for new equipment, survey types, or noise profiles—faster and cheaper than manual expert tuning or retraining large neural networks.

## Technical Limitations
1. **Physical constraint specification**: The approach requires explicit, hand-coded constraints (dip consistency, rank structure, etc.). Discovering constraints themselves is not addressed; if a domain's physics is poorly understood or constraints are too loose, search may fail or overfit.
2. **Search space definition**: Results depend heavily on which operator components are "opened for editing." If key modifications lie outside the search space, evolution cannot find them; determining the right search space is manual and problem-specific.
3. **Scalability to complex domains**: Seismic reconstruction is relatively well-defined and low-dimensional (1D time series, 2D gathers). Domains with higher-dimensional, more complex physics (e.g., fluid dynamics, climate) may yield exponentially larger search spaces or weaker constraints.
4. **No theoretical guarantees**: Unlike classical optimization, there is no proof that evolved algorithms converge, remain stable, or generalize beyond the test set used for scoring. Occasional overfitting to test data cannot be ruled out.
5. **Computational cost of search**: The paper does not report wall-clock search time; if evolution requires many iterations and physical simulations, the one-time cost may be prohibitive for practitioners wanting fast turnaround on new problems.
6. **Noise robustness**: Evolved algorithms were tested on synthetic or controlled noise; real seismic data often contains non-Gaussian artifacts, multiple noise types, and unknown interference—generalization is unproven.

## Open Questions
1. **Can the framework discover constraints automatically?** Instead of hand-specifying dip consistency or rank bounds, could an agent or meta-learner infer useful constraints from unlabeled data?
2. **How does search scale to multimodal reconstruction?** SeisEvo handles 2D interpolation and denoising; can it scale to 3D/4D seismic, joint inversion, or multi-physics problems?
3. **What is the sensitivity to initial algorithm choice?** Starting from POCS vs. a different baseline might yield different evolved algorithms. Is there a canonical, minimal starting point?
4. **Can evolved algorithms be composed?** If two separate problems are solved (e.g., interpolation, denoising), can their evolved operators be combined or does the search need to rediscover the combination?
5. **Real seismic validation**: How do Evo-POCS and Evo-MSSA perform on field data from different acquisition geometries, instruments, and geologic settings than training data?
6. **Transfer learning for algorithm evolution**: If an algorithm evolves well for one survey geometry, can it be fine-tuned for a new geometry in fewer iterations than a cold start?

## Key Takeaway
LLM agents can discover interpretable, deployable seismic reconstruction algorithms faster than manual design, without requiring neural networks at inference time.
