# Rule of Thumb: Explaining Artificial Intelligence Systems using Partial Information

**Authors:** Kaivalya Rawal, Daria Onitiu, Brent Mittelstadt, Sandra Wachter, Chris Russell
**Published:** 2026-08-11 | **arXiv:** [2608.10766v1](http://arxiv.org/abs/2608.10766v1)

## Summary
This paper introduces "Rule of Thumb" (RoT), a new method for explaining AI decisions by identifying the most relevant features for a specific prediction. The approach works without needing access to the model's internals, making it practical for auditing black-box systems, explaining LLM outputs, and supporting scientific discovery — while also meeting regulatory requirements for AI transparency.

## Theoretical Background
Explainable AI (XAI) aims to make opaque AI systems interpretable to humans. Most existing approaches either require access to the model's internal weights and architecture (like gradient-based methods) or generate post-hoc explanations through perturbation (e.g., LIME, SHAP). This paper builds on the concept of feature importance — identifying which input variables matter most for a decision — but frames it as identifying partial information: the minimal set of features needed to predict *how the model behaves* on a given instance. The work addresses a practical gap: regulators and auditors often cannot access proprietary models, so model-agnostic methods are essential.

## Core Contributions
- **Novel formulation**: RoT reframes explanation as finding the smallest subset of features that preserve prediction behavior, rather than computing global or local feature weights.
- **Three concrete applications**: Demonstrates effectiveness on (a) zero-shot LLM classification without fine-tuning, (b) auditing opaque systems without model access, and (c) discovering patterns in scientific data.
- **Regulatory alignment**: Explicitly designed to satisfy explainability requirements from AI regulations (likely referring to EU AI Act and similar frameworks).
- **Efficiency**: Substantially faster than existing model-agnostic alternatives (SHAP, LIME) while remaining interpretable to practitioners.
- **Model-agnostic design**: Works across different model types without architectural assumptions.

## Connections to Other Work
RoT relates to [[SHAP]] and [[LIME]] (model-agnostic explanation methods) but differs in its focus on minimal sufficient features rather than feature importance scores. It connects to work on [[adversarial robustness]] and feature masking, where understanding which features a model relies on is critical. The application to LLM explanation aligns with emerging work on [[mechanistic interpretability]] of transformers, though RoT operates at a higher level (input features rather than internal activations). The regulatory framing connects to broader discussions of [[alignment]] and trustworthy AI systems.

## Practical Applications
- **LLM auditing**: Companies deploying large language models can explain classification decisions (e.g., content moderation, credit scoring) without exposing proprietary model weights.
- **Regulatory compliance**: Organizations can generate legally defensible explanations for high-stakes decisions (hiring, lending, healthcare) under GDPR, AI Act, or similar regimes.
- **Scientific discovery**: Researchers can use RoT to identify which experimental variables (gene expressions, sensor readings, etc.) drive model predictions in biology or physics.
- **Third-party model evaluation**: Auditors can certify or criticize AI systems deployed by other organizations without requiring source code or API-level access.
- **Fairness auditing**: Detecting whether protected attributes (race, gender, age) are being used indirectly by comparing explanations across demographic groups.

## Technical Limitations
- **Feature discretization**: RoT assumes features can be meaningfully masked or removed. With high-dimensional continuous data (images, embeddings), defining "partial information" becomes non-obvious.
- **Assumption of feature independence**: The method may struggle when features are highly correlated or when interactions are critical; removing one feature while keeping another may create unrealistic input distributions.
- **Sufficiency vs. necessity**: Identifying features needed to preserve *prediction behavior* doesn't necessarily explain *why* the model uses those features or whether that reasoning is sound.
- **Scalability to very high dimensions**: While faster than SHAP/LIME, performance on datasets with thousands of features is unclear.
- **Evaluation metric**: Relies on measuring "behavioral preservation," but there's no guarantee this matches human intuitions about explanation quality.
- **Model access for evaluation**: Although the method is model-agnostic, it still requires *querying* the model repeatedly to measure prediction changes when features are masked — inaccessible models may have API rate limits.

## Open Questions
- How does RoT compare to [[attention mechanisms]] in transformers when explaining LLM decisions — are the selected features consistent with learned attention patterns?
- Can RoT be extended to explain *sequential or interactive* decisions (multi-turn dialogue, sequential predictions)?
- How robust is RoT to adversarial inputs or deliberately misleading partial-information subsets?
- Does the set of features identified by RoT generalize across similar instances, or is it highly instance-specific?
- Can RoT be combined with mechanistic interpretability methods to provide both "what features matter" (Rule of Thumb) and "how the model computes it" (internal circuit analysis)?
- What is the minimum size of partial information needed before explanations become unhelpful to humans? Is there a user study validating this?

## Key Takeaway
Fast, model-agnostic explanations by finding minimal feature subsets that preserve AI predictions, without needing model internals.
