# Approximate Muon with low-rank adapters

**Authors:** Ben Anson, Conor Houghton, Edward Milsom
**Published:** 2026-08-14 | **arXiv:** [2608.14492v1](http://arxiv.org/abs/2608.14492v1)

## Summary
This paper adapts the Muon optimizer — which works well for pretraining neural networks — to work with LoRA (low-rank adapters), a popular parameter-efficient fine-tuning method. The key insight is that Muon's orthogonalization step doesn't naturally work with low-rank updates, so the authors approximate a relaxed version of Muon's objective using linearization and least-squares, creating sMuon. The result is modest but consistent performance improvements across fine-tuning tasks while keeping computation efficient.

## Theoretical Background
The Muon optimizer (from concurrent work) is a second-order optimization method that orthogonalizes weight updates during pretraining — this improves both training speed and final model quality compared to standard optimizers like Adam. Low-rank adapters (LoRA) reduce fine-tuning cost by only training small, low-rank matrices that approximate weight updates, freezing the base model weights. The tension: Muon requires orthogonalizing the full update, but LoRA's low-rank constraint makes true orthogonalization mathematically infeasible. The paper solves this by relaxing Muon's objective and approximating it via two steps — linearization (simplifying the non-linear problem locally) and least-squares (finding the best low-rank solution to the simplified problem).

## Core Contributions
1. **sMuon algorithm**: A principled approximation of Muon for low-rank settings that relaxes the orthogonalization constraint and solves via linearization + least-squares, avoiding expensive matrix decompositions.
2. **Efficient matmul-only implementation**: Uses only standard matrix multiplication rather than QR factorizations or SVD, making it practical.
3. **Empirical validation**: Demonstrates moderate but consistent improvements across supervised fine-tuning (SFT) and ReLoRA pretraining experiments, with results that vary by model and evaluation set.

## Connections to Other Work
This bridges [[Muon]] (the base optimizer) and [[LoRA]] — two important but previously incompatible techniques in the parameter-efficient fine-tuning ecosystem. Related to broader work on combining second-order methods with PEFT (e.g., [[Shampoo]], [[K-FAC]]), and sits in the family of [[optimization]] research for large language models. The relaxation approach echoes techniques in constrained optimization where infeasible objectives are approximated locally.

## Practical Applications
- **Fine-tuning large language models on limited compute**: Practitioners using LoRA for domain adaptation or instruction-tuning can now apply Muon's training speedups without expensive linear algebra.
- **Multi-task fine-tuning**: Teams managing many task-specific LoRA adapters benefit from more stable, faster training.
- **Mobile/edge deployment**: Reduced PEFT cost means faster on-device model adaptation.
- **Academic research with limited budgets**: Lower-cost fine-tuning enables smaller labs to adapt large models.

## Technical Limitations
- **Modest empirical gains**: The paper notes results are "model- and eval-dependent," suggesting sMuon doesn't uniformly dominate — practitioners must benchmark per use case.
- **Approximation quality**: Linearization is a local approximation; unclear how well it holds in practice across different initialization and learning rates.
- **Low-rank constraint coupling**: The method still inherits LoRA's constraint of updating only a low-rank subspace — won't help if that subspace is poorly chosen.
- **Limited to fine-tuning**: Focused on SFT and ReLoRA; unclear if it works well for other training regimes (e.g., RL fine-tuning, domain adaptation with distribution shift).
- **Comparison scope**: No head-to-head with other second-order + LoRA hybrids or recent optimizers (e.g., [[AdamW]] variants, Lion).

## Open Questions
1. How does sMuon perform on very large models (70B+) or across diverse domains? Does the approximation quality degrade?
2. Can the relaxation be tightened — e.g., via a better local approximation or iterative refinement?
3. Does sMuon help with other PEFT methods (e.g., prefix-tuning, adapters, BitFit) or is LoRA's structure essential?
4. What is the actual wall-clock speedup vs. Adam + LoRA in standard software stacks (HuggingFace Transformers, PyTorch)?
5. Can this extend to RL fine-tuning (e.g., [[RLHF]]) or multi-task settings where LoRA adapters are task-specific?

## Key Takeaway
Muon optimizer now works with LoRA fine-tuning via low-rank approximation, delivering modest speed and quality gains for parameter-efficient tuning.
