# Multimodal Thinking with Renderable Programs

**Authors:** Sunli Chen, Ding Zhong, Ziqiao Ma, Jiaxin Liu, Zeyuan Yang et al.
**Published:** 2026-09-24 | **arXiv:** [2609.30130v1](http://arxiv.org/abs/2609.30130v1)

## Summary
This paper introduces SVGLM, a framework that uses scalable vector graphics (SVG) as an intermediate representation to enable vision-language models to generate and reason about images within a single thinking chain. Instead of treating images as fixed visual inputs or latent encodings, the model outputs SVG code—which is simultaneously both an image description and executable instructions—allowing reasoning tasks to incorporate visual generation naturally and interpretably.

## Theoretical Background
Vision-language models (VLMs) like CLIP and GPT-4V can understand images and text, but their architectures typically keep image understanding and text reasoning separate. Recent work on omnimodal models has attempted to unify text and image generation, but they rely on rasterized (pixel-grid) or latent (compressed numerical) representations that are hard to inspect or edit. SVG is a vector graphics format that describes images using geometric primitives (shapes, paths, colors) written as code—making it both human-readable and editable. This paper exploits that duality: SVG can serve as both a visual artifact and a textual instruction, bridging the gap between discrete symbolic reasoning (what text-based models do) and continuous visual understanding (what vision models do).

## Core Contributions
1. **SVGLM framework**: A method to fine-tune open-source VLMs to generate SVG code as part of their reasoning output, enabling "thinking-with-images" where the model can create and refine visual elements during problem-solving.
2. **SVG-based image editing dataset**: A large curated dataset of image editing tasks grounded in SVG, providing training examples of how to describe visual transformations as code.
3. **Empirical validation on mathematical reasoning**: Demonstration that SVG generation improves performance on math benchmarks by allowing the model to visualize and reason about geometric or graphical problem elements.
4. **Interpretability advantage**: Unlike pixel-based or latent representations, SVG outputs are human-readable and editable, making the model's visual reasoning transparent and debuggable.

## Connections to Other Work
This work sits at the intersection of [[large-language-models]] and [[computer-vision]]. It relates to broader efforts in [[generative-models]] that aim to unify modalities (e.g., Dall-E, Imagen), but takes a different approach by choosing a symbolic, text-like representation rather than neural latents. It also connects to work on chain-of-thought reasoning—where intermediate steps help solve complex problems—but extends the chain to include visual thinking. The emphasis on interpretability aligns with [[mechanistic-interpretability]] goals: by using SVG instead of black-box latent codes, the model's visual reasoning becomes auditable.

## Practical Applications
1. **Educational software**: Math and science tutoring systems that can generate diagrams and visual explanations dynamically, helping students see step-by-step geometric or graphical reasoning.
2. **Data visualization assistants**: Tools that help users explore data by automatically generating SVG charts, diagrams, and infographics based on natural language queries.
3. **Accessibility tools**: Screen readers and accessible interfaces that can convert visual reasoning into both readable SVG code and natural language descriptions, helping blind or low-vision users.
4. **Code generation with visual debugging**: Programming assistants that generate both code and accompanying SVG visualizations of algorithms, data structures, or system architecture.
5. **Architectural and design planning**: Tools that generate floor plans, wireframes, or UI mockups in SVG format, with the model's reasoning visible in the code itself.

## Product & Startup Ideas
1. **MathViz Pro**: An interactive math tutoring app where students ask questions and the AI generates animated SVG diagrams alongside explanations, with full traceability of the reasoning.
2. **DataStory**: A business intelligence platform where users query datasets in natural language and receive interactive SVG dashboards with interpretable generation logic embedded in the code.
3. **AccessibleDiagrams**: A service that converts complex visual documents (textbooks, research papers, infographics) into accessible SVG + text pairs, enabling blind users to "see" reasoning chains.
4. **DiagramGPT for Confluence**: A plugin that lets teams generate and edit flowcharts, ERDs, and architecture diagrams in Confluence using natural language, with SVG as the underlying format.
5. **VisualCodeAssistant**: An IDE extension that generates both code and SVG visualizations of algorithms, with side-by-side explanations for learning and debugging.

## Technical Limitations
1. **SVG expressiveness ceiling**: SVG is excellent for geometric, vector, and schematic visuals, but struggles with photorealistic imagery, textures, or fine-grained pixel-level details—limiting domains where the method can be applied.
2. **Training data scarcity**: The paper introduces a new dataset, but SVG-based image editing is a niche domain. Scaling to broader visual reasoning tasks may require generating or collecting much more data.
3. **Model capability constraints**: Open-source VLMs used in the paper may lack the sophistication of larger closed models; performance on truly complex visual reasoning (e.g., dense scene understanding) is unverified.
4. **Length and complexity trade-offs**: SVG code can become verbose and slow to generate for complex images. The paper doesn't discuss performance on tasks requiring high visual detail or many shapes.
5. **Generalization beyond mathematical reasoning**: Experiments focus on math benchmarks. Real-world multimodal tasks (e.g., visual navigation, scene understanding) may not benefit if they require perception of fine detail or photorealism.

## Open Questions
1. **How does SVG performance scale to photorealistic domains?** Can the approach be extended beyond geometric/schematic images, or does it fundamentally require simple, vector-friendly visuals?
2. **What is the optimal granularity of SVG abstraction?** Should the model generate low-level primitives or higher-level semantic objects? How does this choice affect reasoning accuracy and interpretability?
3. **Can SVG reasoning improve on tasks beyond mathematics?** How does the approach perform on visual QA, scene understanding, or planning tasks where pixel-level perception is crucial?
4. **How interpretable is the SVG reasoning in practice?** Do humans actually find generated SVG code easier to understand and debug than latent representations, or does complexity of code itself become a bottleneck?
5. **Can the approach be extended to multimodal agents?** Would SVG generation help multi-step tasks where an agent must plan, visualize, and act in a digital environment?
6. **How does SVG generation cost compare to pixel-based approaches?** Is the token/computational cost of SVG code competitive with other visual generation methods?

## Key Takeaway
SVG code lets vision-language models think visually within text reasoning, making image generation interpretable and editable.
