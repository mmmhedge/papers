# The Regression Tax: Decomposing Why Skills Help and Hurt LLM Agents

**Authors:** Darshan Tank, Baran Nama
**Published:** 2026-07-24 | **arXiv:** [2607.22520v1](http://arxiv.org/abs/2607.22520v1)

## Summary
This paper reveals a hidden cost of adding skills to LLM agents: while skills improve average performance, they also cause regressions where previously successful tasks fail after skill integration. By analyzing nearly 6,000 runs across benchmarks, the authors identify three mechanisms causing regression and show that top-performing skills succeed mainly by avoiding damage, not by enabling new capabilities. The finding challenges how we evaluate and design skills for autonomous AI agents.

## Theoretical Background
LLM agents — systems that use large language models to reason and act toward goals — typically improve when augmented with procedural skills: reusable actions or routines that guide behavior. Prior work assumes skills improve performance uniformly across tasks. This paper builds on evaluation methodology in agent research and traces its foundation to work on tool use and in-context learning in transformers (neural networks using attention mechanisms to process sequences). The implicit assumption being challenged is that aggregate metrics like "average success rate" capture the full picture of skill value. The paper also engages with interpretability concerns — understanding why agent behavior changes — and grounding problems in NLP (the challenge of correctly connecting language to inputs and outputs).

## Core Contributions
1. **Regression taxonomy**: Formally distinguishes regressions (tasks that worked without skills but fail with them) from residual failures (tasks failing in both cases), providing a decomposition of skill impact beyond aggregate metrics.
2. **Three regression mechanisms identified**:
   - Skill description osmosis: skills degrade behavior simply by existing in context, even if never called
   - Grounding displacement: skill procedures override how the agent interprets its inputs
   - Verification displacement: procedures suppress output checking the agent would otherwise perform
3. **Empirical finding**: Best-performing skills outperform others primarily by causing fewer regressions, not by enabling more successes.
4. **Root cause analysis**: Shows persistent failures stem from underinvestment in grounding and verification relative to procedural guidance, revealing a mismatch between where skills add value and where agents actually fail.
5. **Actionable design principle**: Demonstrates many regressions are recoverable through better grounding and verification design, offering a path forward.

## Connections to Other Work
This work relates to [[Tool Use in LLMs]] and [[In-Context Learning]], which explore how models incorporate external procedures. It complements research on [[Mechanistic Interpretability]] by showing how skill presence alters agent cognition even without explicit invocation — a kind of "unintended prompt effect." The grounding and verification concerns connect to broader [[Alignment]] challenges: ensuring agents behave as intended. The empirical methodology mirrors recent work deconstructing agent failures in [[ReAct]] and similar frameworks, though this paper's regression lens is novel. The finding that skills can hurt also echoes concerns in [[Instruction Tuning]] literature about task interference when models learn multiple objectives.

## Practical Applications
- **Enterprise automation**: Office automation systems (the paper's testbed) can be redesigned to separate grounding setup, procedural execution, and verification stages, reducing skill-induced failures in real workflows.
- **Autonomous task platforms**: Tools like ChatGPT plugins or similar extensions can vet new skills against regression criteria before release, preventing user-facing degradation.
- **Custom skill development**: Organizations building internal LLM agents can use the regression framework to debug why adding a new skill broke existing functionality.
- **Agent deployment pipelines**: Testing protocols can explicitly measure regressions on a held-out task set before rolling out new skills to production.

## Product & Startup Ideas
1. **Skill Regression Tester**: Automated tool that benchmarks new LLM agent skills against regression criteria (osmosis, grounding displacement, verification displacement) before deployment, with before/after task success matrices and recommendations.
2. **Grounding-First Skill Designer**: IDE or framework that forces skill developers to explicitly specify input grounding, output verification, and context isolation, preventing osmosis and displacement at design time.
3. **Agent Skill Marketplace with Quality Score**: Curated marketplace for LLM agent skills (akin to app stores) where skills are ranked not just by average lift but by regression rate and grounding/verification quality, helping teams choose safer skills.
4. **Interpretability Dashboard for Agent Traces**: Visual tool for debugging why an agent failed on a previously successful task, highlighting which newly-added skills altered behavior and how (osmosis vs. displacement patterns).
5. **Decomposed Eval-as-a-Service**: SaaS offering that runs comprehensive regression analysis on custom agent skill sets, producing reports showing net gains, regressions, and recovery recommendations without requiring internal benchmarking infrastructure.

## Technical Limitations
- **Benchmark scope**: The study covers two office automation benchmarks and three model harnesses; generalization to other domains (coding, reasoning, planning) is unvalidated.
- **Causality attribution**: While the paper identifies three regression mechanisms, establishing causality relies on trace analysis and proxies rather than controlled ablations (e.g., isolating osmosis from displacement is inferred, not experimentally separated).
- **Skill diversity**: The sample of skills tested is not characterized; it's unclear if findings hold for radically different skill types (e.g., highly abstract vs. granular procedures).
- **Model dependency**: Results may depend on model scale and training; behavior of newer or smaller models is not explored.
- **Recovery validation**: The claim that regressions are "recoverable through better grounding and verification" is identified in traces but not fully validated through implemented fixes on the benchmark.
- **Context length confound**: Skill descriptions add tokens to context; the paper doesn't fully disentangle osmosis (semantic interference) from possible context saturation effects.

## Open Questions
1. **Mechanism isolation**: Can you design experiments to isolate osmosis from displacement? E.g., adding skill descriptions in a "sealed" context block that the agent cannot access during reasoning.
2. **Skill composition**: How do regressions compound when multiple skills are added? Is the effect additive, or do skills interact in non-obvious ways?
3. **Adaptive skills**: Can agents be trained to selectively activate skills only when beneficial, reducing osmosis? Does this require reinforcement learning or can it be done in-context?
4. **Grounding/verification primitives**: What is the minimal set of grounding and verification scaffolding needed to prevent regression? Can you design a universal wrapper?
5. **Cross-domain generalization**: Do the three regression mechanisms (osmosis, grounding displacement, verification displacement) appear in other domains like code generation or scientific reasoning, or are they specific to office automation?
6. **Model size scaling**: Do larger models experience fewer regressions from skills? Is there a scaling law for regression rate?
7. **Skill design patterns**: Can you derive design guidelines or templates for skills that naturally avoid these three regression modes?

## Key Takeaway
Skills can make LLM agents worse, and top skills succeed by damaging less, not helping more—better grounding and verification fix most of it.
