# Benchmarking Zero-Shot LLM-Generated Parent Selection in Genetic Programming for Symbolic Regression

**Authors:** Hengzhe Zhang, Qi Chen, Bing Xue, Wolfgang Banzhaf, Mengjie Zhang
**Published:** 2026-07-26 | **arXiv:** [2607.23505v1](http://arxiv.org/abs/2607.23505v1)

## Summary
This paper tests whether large language models can write effective parent-selection algorithms for genetic programming (a search technique used to find mathematical formulas that fit data) without any training examples or feedback. The researchers prompt eight different LLMs to generate selection operators, evaluate them on real regression benchmarks, and find that some LLM-generated operators outperform standard baselines—suggesting LLMs can produce useful search heuristics from task descriptions alone.

## Theoretical Background
Genetic programming (GP) is an evolutionary algorithm that evolves programs (here, mathematical expressions) to solve problems like symbolic regression—finding formulas that predict output from input data. Parent selection is a critical component: it decides which candidate solutions get to "reproduce" and influence the next generation, affecting the balance between exploring the search space broadly and exploiting promising regions.

Traditional GP uses fixed selection strategies like tournament selection (pick the best among random samples) or lexicase selection (eliminate candidates that fail specific test cases). The novelty here is asking whether LLMs—large neural network models trained on text—can synthesize new selection operators by understanding the task in natural language, without ever seeing examples of good operators or receiving feedback on their performance.

## Core Contributions
1. **Systematic benchmark**: First large-scale evaluation of zero-shot LLM-generated parent-selection operators across 8 LLM models, 12 regression datasets, and 10 independent generations per model.
2. **Demonstration of viability**: Shows that zero-shot LLM synthesis produces competitive operators (e.g., Kimi K2.5's operator beats automatic lexicase and tournament selection) without meta-evolution or iterative refinement.
3. **Semantic selection insight**: Analysis reveals many generated operators use semantic properties (how solutions behave on test cases) to guide selection—non-trivial heuristics derived purely from task description.
4. **Leaderboard correlation analysis**: Examines whether public LLM benchmarks (Humanity's Last Exam, SWE-bench) predict GP performance; finds strong correlation with training fit but weaker correlation with test generalization.

## Practical Applications
1. **Automated algorithm design for scientific discovery**: Practitioners doing symbolic regression (physics, biology) can use LLM-generated operators tailored to their specific problem domains without hiring algorithm experts.
2. **Genetic programming pipelines in industry**: Manufacturing, finance, and engineering optimization problems rely on GP; LLM-generated operators could speed up customization.
3. **Rapid prototyping of evolutionary algorithms**: Teams can generate candidate selection operators in minutes, test them, and iterate—lowering barriers to applied evolutionary computation.
4. **Hyperparameter-free GP systems**: Eliminate the need to hand-tune selection strategies by letting LLMs synthesize operators from problem description alone.

## Product & Startup Ideas
1. **GPOperator Studio**: A web tool where users upload a regression dataset or describe an optimization problem in plain English, receive LLM-generated parent-selection operators, auto-benchmark them, and download the best one for integration into their GP framework.
2. **Evolutionary Algorithm-as-a-Service**: Cloud platform that generates and evaluates custom genetic programming operators (selection, crossover, mutation) via LLMs for users' specific domains, with real-time performance dashboards.
3. **ML-powered GP library**: Open-source or commercial library (like Pymoo, DEAP) with a built-in LLM interface: users call one function to generate task-specific operators, which are cached and ranked by past performance.
4. **Domain-specific solver marketplace**: Curated library of LLM-generated operators for common regression domains (time series, physics, chemistry), versioned and continuously refined as users provide feedback.
5. **Enterprise AutoML with custom operators**: Extend AutoML platforms (AutoSklearn, Auto-WEKA) to include LLM-generated GP operators for symbolic regression tasks, competing with polynomial/neural-network baselines.

## Technical Limitations
1. **Zero-shot scope**: The paper only tests zero-shot synthesis (no iterative feedback). Real-world improvement might require few-shot examples or active feedback loops, which the paper doesn't explore.
2. **Limited benchmark diversity**: Twelve OpenML regression datasets is relatively small; performance on highly specialized domains (quantum chemistry, astrophysics) is unknown.
3. **Generalization gap**: Strong correlation between LLM leaderboard rankings and training R² but weak correlation with test R²—suggests generated operators may overfit or that LLM quality doesn't guarantee robust search heuristics.
4. **Reproducibility and stochasticity**: Ten independent runs per LLM introduce variance; no confidence intervals or statistical significance tests reported.
5. **Operator complexity and efficiency**: No analysis of computational cost of generated operators (some may be more expensive than baselines); no code audit for bugs or semantic correctness.
6. **Fairness across LLMs**: Different LLM families have different training data and prompting sensitivities; single prompt may not be equally "fair" to all models.

## Open Questions
1. **Few-shot and iterative refinement**: Can LLMs improve operators when given examples of good/bad operators, or feedback from GP runs? Does this close the test R² gap?
2. **Mechanistic understanding**: Why do some LLMs (Claude, Gemini) consistently outperform others? Do they implicitly learn principles of search balance (exploration vs. exploitation)?
3. **Domain transfer**: Do operators generated for one domain (e.g., physics) transfer to others (e.g., chemistry)? Can we pre-train or fine-tune for families of problems?
4. **Operator interpretability**: Can we extract human-readable design principles from successful LLM-generated operators and use them to improve hand-designed operators?
5. **Scaling to harder problems**: Do these operators scale to higher-dimensional, multi-objective, or constrained optimization beyond symbolic regression?
6. **Comparison with learned operators**: How do zero-shot LLM operators compare to neural networks trained via meta-evolution on the same benchmark suite?

## Key Takeaway
LLMs can synthesize effective genetic-programming selection operators from task descriptions alone, without examples or feedback, competitive with hand-tuned baselines.
