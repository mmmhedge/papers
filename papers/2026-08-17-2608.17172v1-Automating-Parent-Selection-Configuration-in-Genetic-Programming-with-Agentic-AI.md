# Automating Parent Selection Configuration in Genetic Programming with Agentic AI

**Authors:** Jose Guadalupe Hernandez, Jui-Hsuan Chang, Anil Kumar Saini, Xi Li, Jason H. Moore
**Published:** 2026-08-17 | **arXiv:** [2608.17172v1](http://arxiv.org/abs/2608.17172v1)

## Summary
This paper explores whether AI agents—systems that can reason and act autonomously—can automatically design and configure genetic programming systems. The researchers built an agentic framework that uses large language models (LLMs) to identify and implement parent selection algorithms (rules for choosing which solutions to breed together) for symbolic regression problems. The work shows that LLM reasoning combined with retrieval-augmented generation (accessing existing knowledge) can generate competitive algorithm implementations, suggesting AI agents may automate the tedious configuration work that evolutionary algorithm designers currently do by hand.

## Theoretical Background
Genetic programming is an evolutionary approach where candidate solutions are represented as programs or expressions, and the system iteratively selects the best ones to breed and mutate toward better solutions. A critical design choice is the parent selection algorithm—which individuals survive to reproduce. Common approaches include tournament selection (randomly pick k candidates, breed the best) and lexicase selection (evaluate candidates on multiple test cases in random order). Large language models are neural networks trained to predict text sequences and can reason about domain-specific problems. Retrieval-augmented generation (RAG) enhances LLMs by letting them query external knowledge bases before generating answers, combining parametric knowledge (learned during training) with retrieval of relevant documents.

## Core Contributions
1. **Agentic framework for algorithm discovery**: The paper introduces a multi-step agent that uses LLM reasoning to select and implement parent selection algorithms without human programming. This is qualitatively different from prior work that treats LLMs as code generators alone.

2. **Ablation study across LLM scales and components**: Systematic evaluation of four LLM sizes, isolating the effects of agentic reasoning vs. retrieval-augmented generation on algorithm category, validity, implementation fidelity, and downstream performance. Shows that agentic reasoning and retrieval strongly influence *which* algorithms are generated, though final performance depends primarily on the LLM's base capability.

3. **Competitive performance on symbolic regression**: The best configuration (5 mini–AR: small LLM + agentic reasoning + retrieval) consistently generated valid ε-lexicase implementations and matched or exceeded tournament selection across six problems, establishing a practical baseline.

## Connections to Other Work
This work sits at the intersection of [[AutoML]] (automating machine learning design) and evolutionary computation. It relates to hyperparameter optimization and neural architecture search, which similarly automate configuration choices. The use of LLMs for code generation builds on recent work in [[program synthesis]], but the agentic reasoning layer (where the model plans multiple reasoning steps) is closer to chain-of-thought prompting and [[agents]] frameworks. The paper implicitly asks whether domain knowledge about evolutionary algorithms can be encoded in LLM embeddings and retrieved effectively—touching on [[mechanistic-interpretability]] questions about what LLMs "know" about algorithm design.

## Practical Applications
1. **Automated evolutionary algorithm configuration for domain experts**: Researchers designing genetic programming systems for new problems (e.g., physics equations, circuit design) could use this agent to propose and implement parent selection strategies without manually coding them, reducing time-to-prototype.

2. **Hyperparameter tuning in machine learning pipelines**: Extend beyond parent selection to other evolutionary algorithm components (mutation operators, crossover strategies), automating the search over algorithmic design spaces.

3. **Real-time algorithm adaptation**: Deploy the agent in a live evolutionary system to recommend switching parent selection strategies mid-run if performance plateaus, treating algorithm configuration as a dynamic optimization problem.

4. **Symbolic regression for scientific discovery**: Speed up automated discovery of mathematical models in physics, biology, or chemistry by reducing the manual tuning required for each new problem class.

## Product & Startup Ideas
1. **AutoEA (Automated Evolutionary Algorithms as a Service)**: SaaS platform where users upload a symbolic regression problem, and the agentic system automatically designs and runs an optimized evolutionary algorithm, returning both the best solution and the algorithm configuration used.

2. **Algorithm Recommendation Engine for ML Engineers**: IDE plugin or web tool that suggests genetic programming parent selection strategies and code snippets for teams building custom optimizers, based on problem context and prior experiments.

3. **Domain-Specific Code Generation for Computational Science**: Tool for computational biologists and physicists to auto-generate optimized evolutionary solvers for inverse problems, model fitting, and equation discovery without writing the algorithm boilerplate.

4. **Benchmarking and Comparative Analysis Service**: Platform that runs the agentic system across a corpus of real-world symbolic regression benchmarks, producing a public leaderboard of algorithm configurations and their performance profiles.

5. **Interactive Evolutionary Algorithm Design Studio**: Jupyter-like interface where users can query the LLM agent ("suggest a parent selection strategy for noisy fitness functions") and iteratively refine its recommendations via feedback, learning problem-specific patterns over time.

## Technical Limitations
1. **Domain-specific benchmarking**: Evaluation is limited to symbolic regression. Whether the approach scales to other evolutionary tasks (combinatorial optimization, circuit design, hyperparameter tuning) is unknown. Parent selection dynamics differ across problem domains.

2. **Code validity and efficiency gaps**: Generated implementations are valid but may not be optimized for speed or memory. No systematic analysis of whether LLM-generated code matches hand-written implementations in wall-clock performance or algorithmic elegance.

3. **Dependence on LLM scale**: The paper shows downstream performance "largely depends on the underlying LLM," suggesting the approach may not work well with smaller, open-source models or in low-resource settings. Brittleness to model architecture is not characterized.

4. **Limited retrieval knowledge base**: The quality of RAG depends on what documents are indexed. If domain knowledge about novel parent selection strategies is absent from the retrieval corpus, the agent cannot rediscover or extrapolate beyond what it has seen.

5. **Lack of novelty analysis**: The paper does not deeply analyze whether the agent generates *new* algorithmic insights or only rediscovers canonical approaches. The observation that it "consistently generated established ε-lexicase implementations" suggests limited algorithmic innovation.

6. **No analysis of failure modes**: What happens when the agent generates an invalid or unstable algorithm? How does the framework handle or learn from failures?

## Open Questions
1. **Generalization across problem classes**: Does a single trained agentic system work across symbolic regression, combinatorial optimization, and other domains, or must it be retrained per problem class?

2. **Can agents discover novel parent selection algorithms?**: Rather than rediscovering existing ones, can the agent generate new hybrid or adaptive selection strategies that outperform the baselines? What insights or constraints would enable this?

3. **Interactive refinement and human-in-the-loop**: Can users provide feedback on generated algorithms to iteratively improve recommendations? Does the agent learn from this interaction?

4. **Theoretical analysis of generated algorithms**: For generated algorithms that work well, can we reverse-engineer or explain *why* they work? Does this provide insight into parent selection design principles?

5. **Scaling to larger, messier problems**: How does the approach perform on real-world symbolic regression with missing data, measurement noise, or imbalanced class distributions? Do agentic reasoning advantages persist?

6. **Computational cost-benefit analysis**: What is the wall-clock overhead of the agentic discovery process relative to just running fixed algorithms? Is it worth it for single-run problems vs. algorithmic portfolio scenarios?

## Key Takeaway
AI agents can automatically generate competitive genetic programming algorithms using language models and retrieved domain knowledge, reducing manual tuning.
