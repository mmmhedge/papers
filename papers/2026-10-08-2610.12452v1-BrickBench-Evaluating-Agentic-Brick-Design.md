# BrickBench: Evaluating Agentic Brick Design

**Authors:** Peter Kulits, Yiqing Xu, R. Kenny Jones, Cordelia Schmid, Jiajun Wu
**Published:** 2026-10-08 | **arXiv:** [2610.12452v1](http://arxiv.org/abs/2610.12452v1)

## Summary
BrickBench is a benchmark that tests whether AI agents can design physically buildable LEGO sets from natural language descriptions. The task requires agents to select parts from a library while satisfying semantic, design, and physical construction constraints — a problem that combines language understanding, spatial reasoning, and constraint satisfaction. This matters because it tests whether agents can move beyond generating plausible outputs to producing solutions that work in the real world.

## Theoretical Background
This work sits at the intersection of language-conditioned generation, constraint satisfaction, and embodied reasoning. Prior work in generative models has focused on producing outputs that match semantic intent (e.g., image generation from text), but less attention has gone to ensuring outputs satisfy hard physical constraints. The paper builds on traditions in combinatorial optimization and assembly planning — fields that reason about discrete part selection and spatial feasibility. LEGO design is a proxy for broader assembly tasks where agents must jointly optimize local part interactions and global structural coherence.

## Core Contributions
1. **BrickBench benchmark**: A structured evaluation suite with three difficulty settings that measures agents on validity (physical buildability), alignment (semantic fidelity to prompt), and design quality (aesthetic/structural merit compared to human designs).
2. **BrickAgent environment**: A coding framework that lets agents construct LEGO designs programmatically, inspect them, and receive validation feedback.
3. **Empirical findings**: Demonstrates that leading LLM-based agents can satisfy hard constraints but produce designs inferior to human-designed sets, suggesting a gap between constraint-satisfaction and aesthetic/functional optimization.
4. **Dataset and baseline results**: Public release of the benchmark, allowing future work to iterate on agent architectures for constrained creative tasks.

## Connections to Other Work
This relates to [[embodied AI]] and [[sim-to-real transfer]] in that it grounds language models in physical reality. It shares DNA with [[RLHF]] (reinforcement learning from human feedback) insofar as human design quality could inform reward signals. The constraint-reasoning aspect connects to classical [[CSP (Constraint Satisfaction Problems)]] and modern neurosymbolic approaches that combine neural networks with symbolic constraint solvers. It also echoes recent work on code generation from language (e.g., Codex-style models), since agents here must generate structured assembly code.

## Practical Applications
1. **Automated toy/model design**: E-commerce platforms (Shopify, Etsy) could use agents to auto-generate custom LEGO instructions from customer descriptions, reducing design labor.
2. **Architectural visualization**: Real estate or interior design tools that let users describe a layout and receive 3D part-based mockups they can physically prototype.
3. **Educational tools**: Platforms teaching STEM that generate age-appropriate building challenges from natural language learning objectives.
4. **Manufacturing/CAD automation**: Furniture or modular building design where agents propose feasible assemblies constrained by material libraries and tooling.
5. **Robotics assembly planning**: Training agents to decompose assembly tasks and select physical actions/parts in constrained environments.

## Product & Startup Ideas
1. **BrickAI Studio**: A web app where users describe a LEGO design in plain English and agents auto-generate build instructions, with human-in-the-loop refinement. Monetize via premium design packs or enterprise licensing to toy manufacturers.
2. **ConstraintGen**: A B2B API for generative design under hard constraints (physical, material, cost). Start with LEGO, expand to furniture, electronics, industrial prototypes.
3. **EduBuild**: An edtech platform pairing LLMs with interactive 3D assembly environments for STEM education; agents generate scaffolded building challenges.
4. **Modular Design Copilot**: SaaS tool for furniture/product designers; agents suggest feasible part combinations and assemblies, freeing designers to focus on novelty.
5. **AssemblyOS**: A platform for training agents on domain-specific part libraries (medical devices, consumer electronics, fashion components); license to manufacturers for design automation.

## Technical Limitations
1. **Discrete combinatorial explosion**: Selecting from large part libraries is NP-hard; the benchmark likely constrains part counts and library size, which may not reflect real-world complexity.
2. **Geometric reasoning**: Agents must compute spatial compatibility (collision detection, stability), but LLMs lack native geometric intuition; rely on symbolic APIs or learned representations that may fail on novel configurations.
3. **Aesthetic/design quality**: The paper notes agents satisfy hard constraints but lag on design. This suggests no clear signal or loss function for design merit — a fundamental open problem in generative design.
4. **Simulation fidelity**: Physical validity is checked in simulation; real-world friction, tolerances, and assembly dynamics may differ.
5. **Scalability**: Benchmark settings are "three scales"; unclear how performance degrades with vastly larger part libraries or longer build sequences.
6. **Prompt ambiguity**: Natural language is inherently ambiguous; no analysis of robustness to paraphrases or underspecified instructions.

## Open Questions
1. **Can agents learn from failure feedback?** If an assembly fails physical checks, can the agent iteratively refine it, or does it require retraining?
2. **How do neurosymbolic approaches compare?** Would hybrid systems (symbolic constraint solver + learned part embeddings) outperform pure LLMs?
3. **What drives the design quality gap?** Is it insufficient training data, lack of aesthetic objectives, or fundamental limitations in agent architecture?
4. **Does scaling help?** Do larger models or fine-tuning on LEGO instructions close the gap to human designs?
5. **Cross-domain transfer**: Can agents trained on LEGO transfer to other part-based assembly tasks (furniture, electronics, mechanical devices)?
6. **Human-AI collaboration**: What interface would let humans and agents co-design efficiently? How does real-time feedback improve agent performance?

## Key Takeaway
Agents can build valid LEGO sets from text but produce designs worse than humans, revealing a gap between constraint satisfaction and creative optimization.
