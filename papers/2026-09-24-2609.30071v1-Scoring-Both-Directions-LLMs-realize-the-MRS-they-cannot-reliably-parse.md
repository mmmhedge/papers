# Scoring Both Directions: LLMs realize the MRS they cannot reliably parse

**Authors:** Soham Dan
**Published:** 2026-09-24 | **arXiv:** [2609.30071v1](http://arxiv.org/abs/2609.30071v1)

## Summary
This paper reveals a striking asymmetry in how large language models handle formal semantic representations: Claude models excel at generating English from structured meaning (MRS—Minimal Recursion Semantics), beating specialized trained systems by 10 BLEU points, but fail dramatically at the reverse task of parsing English into that same formal structure (reaching only 65.5 F₁ vs. 91.0 for a hand-built grammar). The finding challenges the assumption that generation performance implies semantic understanding.

## Theoretical Background
The English Resource Grammar (ERG) is a hand-crafted computational grammar—a detailed rule system that maps between English sentences and their formal meaning representations. Minimal Recursion Semantics (MRS) is a graph-based semantic framework that explicitly represents predicates (what actions/properties are expressed) and their arguments (who/what they apply to). The ERG's processor, ACE, can work bidirectionally: parsing text into MRS or generating text from MRS. Prior work (Hajdik et al. 2019) trained sequence-to-sequence neural models on 72k and 1 million MRS-text pairs to tackle generation, establishing a benchmark. This paper tests whether modern LLMs—trained on no task-specific data—can match or exceed these trained systems in both directions.

## Core Contributions
1. **Asymmetry discovery**: Demonstrates a severe directional gap in LLM semantic competence that standard generation metrics mask. Claude Opus reaches 76.3 BLEU on MRS→text (surpassing trained baselines by 10 points) but only 65.5 F₁ on text→MRS parsing.
2. **Zero-shot competitive generation**: Shows that few-shot LLMs (3 examples, no fine-tuning) match or exceed systems trained on hundreds of thousands of pairs, suggesting emergent few-shot capabilities.
3. **Failure mode characterization**: Provides qualitative analysis of why models struggle with parsing—not mere capability gaps, but systematic errors in extracting predicate-argument structure from natural language.
4. **Decoupling of generation from understanding**: Refutes the implicit claim that high generation scores indicate true semantic representation mastery; one direction alone is insufficient evidence.

## Practical Applications
1. **Semantic parsing tools**: Systems that convert natural language to structured databases or logical forms (e.g., question-answering over knowledge bases) cannot rely on LLMs alone without verification against a formal parser.
2. **Dialogue systems requiring grounding**: Chatbots that must map user utterances to formal world states (e.g., task planning, slot-filling in task-oriented dialogue) need separate parsing pipelines, not just generation-based approaches.
3. **Code generation with formal verification**: LLMs that generate code from specifications may accidentally skip formal semantic validation; pairing with formal checkers (like ACE for code) is necessary.
4. **Machine translation with semantic consistency**: Ensuring translated text preserves predicate-argument structure is harder than it appears; generation alone won't catch semantic drift.
5. **Legal and regulatory document processing**: High-stakes text-to-structure tasks (contract parsing, regulatory compliance) require both directions validated separately.

## Product & Startup Ideas
1. **Hybrid semantic parsing service**: A web API that combines LLM generation for fluency with ACE-style formal parsing for validation; sell to legal tech, financial data extraction, and structured knowledge capture startups.
2. **Interactive semantic annotation tool**: A UI that asks LLMs to generate candidate parses, then allows humans to correct them efficiently, creating a dataset for domain-specific grammar induction (e.g., biomedical literature, regulatory text).
3. **Semantic consistency checker for NLP pipelines**: Enterprise tool that flags when downstream NLP components (entity extraction, relation extraction, etc.) disagree with upstream semantic structure; audits for hidden errors in NLP workflows.
4. **Fine-tuning service for direction-specific LLMs**: Offer quick fine-tuning on text→structure tasks (the weak direction for LLMs) using specialized curriculum learning, target vertical of legal/finance/biomedical data processors.
5. **Formal semantics playground for linguists**: An interactive tool letting linguists test LLMs' bidirectional competence on custom grammars and treebanks, with detailed error analysis; sell subscriptions to computational linguistics groups.

## Technical Limitations
1. **Task-specific asymmetry, not general understanding**: The gap may be partly an artifact of MRS's particular representation—some formal semantics might be easier for LLMs to parse (or harder to generate). Generalization to other meaning representations unknown.
2. **Exact-match criterion too harsh**: Only ~1% exact-match on parsing suggests the F₁ metric (on predicates and arguments) may also be underestimating partial understanding. The paper doesn't report which components (predicates vs. arguments, local vs. long-range) fail most.
3. **Few-shot context dependency**: Success on generation with 3 examples raises questions about whether the model is memorizing patterns rather than learning the task. Ablations on example count and relevance missing.
4. **No analysis of syntactic vs. semantic errors**: When parsing fails, is it because the model misunderstands structure (a true semantic problem) or makes syntactic errors first? The paper doesn't untangle this.
5. **ACE as gold standard**: ACE itself is a hand-built system and may have blindspots or errors; inter-annotator agreement with human raters on MRS correctness is not reported, so the gap might be partly a property of the benchmark.
6. **Scale and coverage**: Testing on 10k sentences from a single treebank (likely 20th-century English) limits claims about generalization to modern, diverse English or other languages.

## Open Questions
1. **What drives the asymmetry?** Is it a property of the MRS representation, the task structure, or LLM training? Testing on other formal semantics (Abstract Meaning Representation, FrameNet, dependency semantics) would clarify.
2. **Can parsing be improved via training or prompting?** Does fine-tuning on even modest amounts of labeled data (e.g., 1-10k pairs) close the gap? What about chain-of-thought prompting or step-by-step decomposition?
3. **How much of the gap is memorization vs. generalization?** Controlled experiments varying example relevance, quantity, and in-distribution vs. out-of-distribution test cases would separate these.
4. **Do other LLM families show the same asymmetry?** Is this specific to Claude, or does GPT-4, Llama, Gemini exhibit similar patterns? Multi-model comparison needed.
5. **Can the two directions be combined?** Could a model that first generates text, then parses its own output (or iterates), reduce error? Does self-consistency improve semantic correctness?
6. **What are the human baselines?** How do linguists or untrained humans perform on these tasks? Context-dependent—would ground the "fair" difficulty.

## Key Takeaway
LLMs ace formal semantic generation but fail at semantic parsing, suggesting high output quality alone doesn't prove semantic understanding.
