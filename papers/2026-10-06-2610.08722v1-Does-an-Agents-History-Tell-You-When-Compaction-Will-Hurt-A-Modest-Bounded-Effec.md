# Does an Agent's History Tell You When Compaction Will Hurt? A Modest, Bounded Effect on the TRACE Paired-Replay Corpus

**Authors:** Egor Pakhomov, Erik Nijkamp
**Published:** 2026-10-06 | **arXiv:** [2610.08722v1](http://arxiv.org/abs/2610.08722v1)

## Summary
This paper investigates whether an AI agent's recent behavior can predict when context compaction (summarizing old information to save tokens) will hurt performance. Using a corpus of 590 real compaction events from an app-interaction agent, the authors find that history predicts harm only weakly—the best interpretable trigger catches 21% of harmful compressions while retaining 84% of compression opportunities, but doesn't clearly beat simple token-budget rules. The work matters because long-horizon agents need to compress context, and predicting when compression hurts could improve agent reliability.

## Theoretical Background
Long-horizon agents—systems that take many sequential actions toward goals—must manage context windows (the amount of information they can attend to at once). As agents act over time, their context grows and must be compressed, either by dropping old information or by summarizing it. Most systems use blind, global rules (e.g., "keep only the last 4000 tokens"). This paper builds on the growing literature examining when and how context management fails. It uses TRACE, a paired-replay corpus where compaction boundaries are replayed twice: once with the original context and once with a summary, allowing direct measurement of performance degradation ("burden"—errors or repeated actions). The work is grounded in mechanistic interpretability: can we understand *why* compaction fails by examining agent history?

## Core Contributions
1. **Systematic measurement**: The paper introduces a reproducible method to measure compaction harm (burden) via paired replay—replaying the same decision point under different context conditions.
2. **Weak predictability finding**: Demonstrates empirically that pre-boundary agent history predicts post-compaction failure only weakly (best AUROC 0.66), contradicting intuitions that "context close to compaction is more critical."
3. **Interpretation of naive signals**: Shows that a simple "has-written" feature (whether the agent recently wrote data) doesn't measure what it seems—it actually captures trajectory phase, not compaction vulnerability.
4. **Practical trigger design**: Proposes a frozen, interpretable trigger that avoids 21% of harmful compressions while keeping 84% of compression opportunities, but with honest assessment that it may not beat token-budget rules on burden mass.
5. **Methodological clarity**: Identifies what future corpora must include (matched retention rates, same-boundary replicates, burden metrics) to properly evaluate compaction strategies.

## Connections to Other Work
This work relates to [[mechanistic-interpretability]] efforts that aim to understand and predict agent failure modes. It's adjacent to research on [[reinforcement-learning]] with memory/context constraints and to work on agent evaluation (e.g., how to measure when agents degrade). The paired-replay evaluation method echoes techniques used in studying [[attention]] mechanisms and feature importance in neural networks. The null result (history doesn't strongly predict harm) suggests compaction failures may be more structural (about what information is *in* the summary) than behavioral (about *when* to compress).

## Practical Applications
1. **App automation platforms** (RPA, browser-based agents): Improve reliability of long-running automation by avoiding harmful context compression at known-bad boundaries.
2. **Code generation agents**: Prevent loss of context during multi-file editing tasks where summary quality is critical.
3. **Autonomous data analysis**: Allow agents that work with long data-exploration sessions to compress history without sudden performance cliffs.
4. **Customer service agents**: Retain relevant conversation history across many turns without storing full transcripts.

## Product & Startup Ideas
1. **Context Compression Advisor**: A service that monitors long-horizon agents and alerts teams before harmful compressions occur, using interpretable triggers to flag risky compaction boundaries.
2. **Smart Memory Management for Agent Platforms**: Infrastructure layer that learns task-specific compaction policies (e.g., "don't compress during API debugging phases") rather than using uniform token budgets.
3. **Compaction Quality Auditing Tool**: SaaS product that replays agent traces to measure and optimize compaction strategies before deployment, similar to A/B testing for context windows.
4. **Interpretable Trigger Library**: Open-source/commercial library of pre-trained, frozen triggers for common agent types (browser agents, data agents, code agents) that predict compaction harm without expensive retraining.
5. **Agent Reliability Dashboard**: Monitor production agents and surface correlations between history patterns and post-compaction failures, helping teams diagnose and fix context management issues.

## Technical Limitations
1. **Weak signal ceiling**: The best trigger reaches AUROC 0.66 vs. 0.72 for the replicate baseline—the predictive signal is genuinely modest. It's unclear whether better features could overcome this or whether the problem is fundamentally hard.
2. **Limited corpus scope**: TRACE focuses on AppWorld (simulated app interaction). Results may not generalize to other agent domains (code generation, reasoning, dialogue).
3. **Incomparable evaluation**: The paper cannot directly compare the learned trigger to token-budget rules at "matched retention"—this requires data the corpus doesn't provide, limiting practical deployment guidance.
4. **Summary quality unknown**: The paper measures harm from compaction but doesn't analyze the quality of summaries themselves. A bad summary strategy may make predictive triggers moot.
5. **Burden metric limitations**: "Burden" (errors + repeated actions) may not capture all forms of degradation (e.g., subtle goal drift, hallucination without errors).
6. **Offline evaluation only**: Results are from replayed boundaries, not live agent rollouts. Online performance may differ due to distribution shift.

## Open Questions
1. **What causes weak predictability?** Is compaction harm driven by which *information* is lost (summary quality) rather than *when* compression happens (history patterns)? A study directly manipulating summary quality could clarify this.
2. **Scaling with trajectory length**: Do results hold for very long horizons (1000+ steps)? Does the relationship between history and compaction harm change?
3. **Task-specific triggers**: Can domain-specific triggers (learned separately for code tasks, data tasks, dialogue) substantially improve over the general trigger?
4. **Summary-aware prediction**: If a trigger could see the proposed summary (not just history), how much would predictability improve? This would isolate whether the problem is predicting harm or summarizing well.
5. **Matched retention comparison**: What empirical protocol would let researchers fairly compare history-based triggers to token-budget baselines? The paper identifies this as a key missing evaluation.
6. **Human interpretability**: Can the frozen trigger's decision be explained in plain language to practitioners? Which features actually matter?

## Key Takeaway
Agent history predicts when context compression fails only weakly; better compaction strategies may require understanding summary quality, not just when to compress.
