# Agent in a Bottle: Can LLM Agents Turn Their Capabilities Into Cheap, Scalable Artifacts?

**Authors:** Ankit Sonthalia, Haritz Puerto, Alexander Rubinstein, Martin Gubri, Seong Joon Oh
**Published:** 2026-10-06 | **arXiv:** [2610.08775v1](http://arxiv.org/abs/2610.08775v1)

## Summary
This paper asks whether LLM agents can autonomously create cheap, task-specific solutions (like small distilled models or programs) when given a large repetitive workload and a fixed budget. The authors introduce BOTTLED, a benchmark where agents must complete millions of similar tasks under compute and cost constraints, and find that while strong zero-shot performance doesn't guarantee good "bottling" ability, successful agents can achieve 600+ times cost reduction with acceptable quality loss.

## Theoretical Background
The work builds on two key ideas: (1) **LLM agents** — systems where language models make autonomous decisions about strategy and resource allocation — and (2) **knowledge distillation** — compressing large models into smaller, cheaper ones that retain most performance. It also relates to the broader problem of amortized inference: instead of querying an expensive model millions of times, can you invest upfront computation to create a reusable, cheaper artifact (a small model, a heuristic program, or a lookup table)? The paper frames "bottling" as a distinct capability from raw task performance: knowing how to solve a task is different from knowing when and how to cheaply batch-solve thousands of instances.

## Core Contributions
1. **BOTTLED benchmark**: The first systematic evaluation framework for testing whether agents can autonomously design cost-effective solutions for large repetitive workloads, with fixed token budgets across ten LLM models and three tasks (query-product relevance, text classification, etc.).

2. **Decoupling discovery**: Strong evidence that zero-shot task performance and "bottling" capability are largely independent—models scoring similarly in zero-shot settings can differ dramatically in how well they allocate limited resources to create reusable solutions.

3. **Empirical baselines**: Concrete cost-quality tradeoffs showing that modern agents underperform simple distillation baselines in ~50% of runs, but can still achieve 600+ times cost reduction when successful (e.g., Opus 5 retains 82% macro-F1 on relevance classification at 1/657th cost).

4. **Competitive efficiency**: Demonstration that LLM agents can match or exceed purpose-built cheap-inference models (like Jev) while operating under the same token budget.

## Connections to Other Work
This paper extends [[Agents]] literature by introducing a new evaluation axis: not just task-solving ability, but resource-allocation and artifact-creation ability. It relates to [[Reinforcement Learning]] concepts of sequential decision-making under constraints, [[Generative Models]] for distillation, and classical [[Optimization]] problems in amortized inference. The work also implicitly connects to [[Alignment]] concerns—autonomous agent decision-making about resource use—and the broader question of whether LLMs can reliably make strategic trade-offs.

## Practical Applications
1. **Large-scale classification at scale**: E-commerce companies classifying millions of product queries or reviews daily; agents create domain-specific classifiers under fixed budgets.

2. **Document triage systems**: Law firms, insurance companies, or healthcare providers processing massive document backlogs; agents decide whether to build a small model, write rules, or sample-then-query the expensive LLM.

3. **Content moderation**: Social platforms with millions of posts; agents autonomously design moderation systems (small models, regex heuristics, hybrid pipelines) that fit compute budgets.

4. **Batch NLP pipelines**: Any organization with recurring, high-volume NLP tasks (summarization, entity extraction, translation) that need amortized cost control.

5. **Multi-tenant inference platforms**: Cloud providers offering LLM APIs can use BOTTLED-like evaluation to help customers understand when to invest in distillation vs. direct querying.

## Product & Startup Ideas
1. **"LLM Agent Optimizer" SaaS**: A platform that takes a workload description and cost budget, runs BOTTLED-style evaluation across multiple LLM providers, and recommends the best bottling strategy (distill vs. program vs. hybrid). Charge per evaluation or per saved API tokens.

2. **"Distillation-as-a-Service"**: Automatically create and host task-specific cheap models based on LLM outputs, targeted at teams with repetitive inference needs. Handle the distillation pipeline so users never touch training code.

3. **"Budget-Aware Agent Orchestrator"**: A platform where teams define cost/quality constraints and agents autonomously choose from a menu of inference strategies (direct LLM, cached lookup, small model, heuristic). Monitor actual vs. budgeted cost in real time.

4. **"Jev Alternative": Purpose-built cheap inference for specific repetitive tasks** (e.g., customer-support ticket classification, product tagging). Train once from LLM-generated data, serve at 1/100th the cost of direct LLM queries, with 90%+ quality recovery.

5. **"Agent Training Framework for Resource Allocation"**: Developer tools and RL curricula to train agents to excel at the bottling task specifically—turning it into a teachable, improvable skill for autonomous systems.

## Technical Limitations
1. **Benchmark scope**: Only three tasks tested; unclear if findings generalize to longer-horizon problems, multi-step reasoning, or tasks requiring real-time adaptation.

2. **Agent strategy diversity**: Agents have limited choices (small model, program, hybrid). Real-world bottling might require more exotic strategies (retrieval augmentation, ensemble methods, active learning) that aren't in the current action space.

3. **Quality-cost tradeoff**: The paper doesn't deeply analyze *when* the quality loss of bottled solutions becomes unacceptable—depends on domain (e.g., medical diagnosis has lower tolerance than product recommendation).

4. **Reproducibility and budget constraints**: Fixed token budgets may not reflect realistic scenarios where agents can negotiate or adapt budgets dynamically. Results are also token-budget-specific; different budgets may yield different winner models.

5. **Distillation baselines**: The "small-model distillation baseline" is strong; unclear whether agent-designed distillation differs meaningfully from tuned baselines or simply rediscovers known techniques.

6. **Scalability assumptions**: Assumes workload is available upfront and static; doesn't handle streaming, non-stationary, or evolving tasks.

## Open Questions
1. Can agents learn bottling strategies from past experience (meta-learning), or are they re-discovering the same approaches for each new task?

2. How do bottling capabilities scale with agent reasoning depth (e.g., does chain-of-thought or tree-search improve resource allocation)?

3. What is the minimal model size or computational budget below which bottling fails? Is there a hard phase transition?

4. Can agents combine multiple strategies (e.g., a hybrid ensemble of a small model + direct queries on uncertain cases) better than current approaches?

5. How sensitive are results to the *type* of task? Does bottling work equally well for classification, generation, reasoning, and structured prediction?

6. Can human-agent collaboration (agents propose strategies, humans validate cheapness assumptions) improve bottling success rates?

## Key Takeaway
LLM agents can autonomously create cheap, reusable solutions for repetitive workloads, but their bottling skill doesn't track their raw task ability and often trails simple distillation baselines.
