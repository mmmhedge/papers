# Auditing Emergent LLM-Agent Collaboration through Cooperation-Obligation Coupling

**Authors:** Zuyuan Zhang, Hanqing Yang, Carlee Joe-Wong, Tian Lan
**Published:** 2026-07-29 | **arXiv:** [2607.27429v1](http://arxiv.org/abs/2607.27429v1)

## Summary
This paper addresses a critical gap in auditing multi-agent LLM systems: how to verify that emergent collaborative work is sound and responsibility is fairly allocated. The authors propose iCORE, a unified representation that tracks observable interactions, evolving work assignments, and evidence linking them together, enabling auditors to catch incomplete reasoning and misaligned accountability that plausible outputs might otherwise conceal.

## Theoretical Background
LLM-agent systems combine large language models — neural networks trained on vast text that can follow instructions and reason over tasks — with multi-agent collaboration frameworks where multiple agents coordinate to solve problems. Prior work captures individual aspects of such systems: message logs, tool invocations, task dependencies, or execution traces. However, no existing framework jointly represents three interdependent concerns: (1) what work remains unfinished, (2) who is responsible for it, and (3) what evidence justifies transitions between work states. This paper builds on classical distributed systems auditing and game-theoretic notions of agent incentive alignment to close that gap.

## Core Contributions
1. **iCORE representation**: A three-component encoding (cooperation graph G, obligation graph Q, audit map Π) that fuses observable agent interactions with evolving responsibility assignments and verifiable justifications.
2. **Two formal properties**: Work soundness (all decision-relevant assertions must have finite justification chains) and agent-assignment stability (no agent can credibly claim they could improve task contributions by more than ε, constraining unfair reward allocation).
3. **Soundness theorems and regret bounds**: Formal guarantees that local verification implies global soundness, plus performance bounds under stated conditions.
4. **Empirical improvements**: 11.5–26.4% trajectory-quality gains and 15.1–31.0% terminal-performance gains over passive full-state observation in controlled and real LLM execution.

## Practical Applications
1. **Financial compliance**: Auditing algorithmic trading teams (human + LLM agents) to ensure decision justification and prevent hidden conflicts of interest.
2. **Healthcare workflows**: Verifying that diagnostic multi-agent systems (e.g., radiologist + AI + second-opinion agent) have sound reasoning chains and clear responsibility for recommendations.
3. **Legal document review**: Ensuring paralegal LLM-agent teams assign work fairly, complete all contract review tasks, and justify every flag or approval.
4. **Autonomous vehicle teams**: Debugging why a fleet coordination system made suboptimal decisions by tracing incomplete handoffs or undocumented agent failures.
5. **Enterprise RPA (Robotic Process Automation)**: Certifying that multi-bot workflows for HR, accounting, or procurement have no gaps in coverage and fair task allocation.

## Product & Startup Ideas
1. **iCORE-Monitor SaaS**: A plug-in auditing layer for enterprises running multi-agent LLM workflows (e.g., customer service, claims processing, content moderation). Dashboards show responsibility gaps and work soundness in real time.
2. **Compliance-as-Code for Agent Teams**: Version-controlled, testable audit rules for regulated workflows (finance, healthcare, legal) that automatically flag soundness and fairness violations in agent collaboration logs.
3. **Agent Insurance**: Underwriting premiums for companies deploying multi-agent systems by quantifying auditability risk; iCORE certification lowers premiums.
4. **Debug Console for Multi-Agent Apps**: Developer tool (VS Code extension, or web IDE) that visualizes iCORE representations as interactive graphs, letting engineers replay and fix agent handoff failures.
5. **Regulatory Reporting Generator**: Automated extraction of audit trails from iCORE logs for regulatory filings (SOC 2, HIPAA, financial audits), reducing manual compliance burden.

## Technical Limitations
1. **Instrumentation overhead**: iCORE requires agents to emit structured cooperation and obligation events; legacy systems need retrofitting, which may slow execution or require invasive code changes.
2. **Definition of "sound" is domain-specific**: Work soundness depends on what counts as a valid justification — the framework is flexible but auditors must specify decision-relevant assertions and evidence rules upfront; misspecification defeats the purpose.
3. **Scalability to large agent teams**: Obligation graphs grow with agent count and task granularity; graph-based verification may become expensive for 100+ concurrent agents or deeply nested task hierarchies.
4. **Agent cooperation must be mostly honest**: The framework assumes agents truthfully report their work state; an agent that silently drops tasks or lies about contributions can evade detection (unless external monitors exist).
5. **ε-bounded assignment stability is approximate**: The regret bound allows allocating credit unfairly by up to ε; choosing ε requires domain knowledge and may not capture subjective fairness notions.
6. **Limited to decision-tree-like workflows**: Assumes clear responsibility transitions; cyclic or ambiguous dependencies (e.g., two agents simultaneously solving the same subproblem) may confuse the obligation graph.

## Open Questions
1. **How sensitive is iCORE to the choice of evidence rules and ε?** A follow-up should run sensitivity analysis and provide heuristics for practitioners to calibrate these parameters.
2. **Can iCORE scale to heterogeneous agent types?** Current evaluation assumes similar agent modalities; what breaks with mix of symbolic solvers, neural agents, and humans?
3. **How does iCORE interact with [[RLHF]] or other alignment techniques?** Could audit-based feedback improve agent training, or does it conflict with end-to-end optimization?
4. **What is the computational complexity of verifying soundness and stability?** Worst-case bounds and practical heuristics for large graphs would strengthen the approach.
5. **How does iCORE handle incomplete or delayed reporting?** Real systems have message loss, clock skew, and latency; can the framework tolerate eventual consistency?
6. **Can humans and LLM agents be audited symmetrically?** If humans are part of the team, how do you represent human "work" and "obligation" in a comparable way?

## Key Takeaway
LLM-agent systems need built-in auditability to verify complete reasoning and fair responsibility allocation; iCORE provides a unified framework to catch hidden work gaps and detect unfair credit assignment.
