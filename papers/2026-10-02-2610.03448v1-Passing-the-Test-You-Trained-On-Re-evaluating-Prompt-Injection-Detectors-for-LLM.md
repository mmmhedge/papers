# Passing the Test You Trained On: Re-evaluating Prompt-Injection Detectors for LLM Agents

**Authors:** Zhuowen Liu
**Published:** 2026-10-02 | **arXiv:** [2610.03448v1](http://arxiv.org/abs/2610.03448v1)

## Summary
This paper reveals that prompt-injection detectors perform very differently when tested on agent-specific outputs compared to public benchmarks, even detectors that rank highly. The authors show that a detector scoring well on one benchmark may fail catastrophically on real agent tool outputs, suggesting current evaluation practices dangerously mislead teams deploying these defenses.

## Theoretical Background
Prompt injection — where attackers embed malicious instructions in tool outputs to trick LLMs into executing unintended actions — is a critical security threat for [[LLM agents]], systems that call external tools and process their results. The field currently relies on public benchmarks (like BIPIA) to evaluate detector quality, assuming benchmark rankings predict real-world effectiveness. This work questions that assumption by studying how detectors trained on different input formats generalize across contexts.

## Core Contributions
1. **Benchmark transfer failure**: Demonstrates dramatic ranking inversions — detectors top-ranked on BIPIA catch only 2% of injections in AgentDojo at 1% false-positive rate, while a 72%-catching AgentDojo detector drops to 15% on tau-bench.
2. **False-positive stability**: Finds that false-positive rates (1% to 90%+ range) are more stable across benchmarks than true detection rates, suggesting detectors learn spurious patterns specific to training input format.
3. **Training data audit**: Traces poor transfer to training data mismatch — detectors trained on short prompts (BIPIA's format) fail on attack strings embedded in realistic tool outputs; only detectors trained on agent-style inputs perform consistently.
4. **Practical evaluation guidelines**: Recommends agent-specific evaluation, low false-positive rate reporting, and transparent training data disclosure for deployment decisions.

## Connections to Other Work
This relates to broader concerns about [[adversarial robustness]] in neural systems and the [[distributional shift]] problem — models trained on one data distribution often fail catastrophically when deployed on different data. The work echoes critiques of benchmark-driven evaluation in other domains (e.g., vision, NLP) where test-set overfitting obscures real-world performance. It also connects to [[prompt engineering]] and [[jailbreaking]] research, which has shown LLMs are vulnerable to subtle input manipulations.

## Practical Applications
- **Agent deployment audits**: Security teams deploying tool-using LLMs can now use real tool outputs (instead of benchmark scores) to evaluate detectors before production.
- **Red-teaming workflows**: Organizations can generate adversarial tool outputs using differential replay (run the agent without LLM injection, then inject payloads) to validate their detectors.
- **Detector selection**: Teams choosing among commercial detectors (e.g., Meta's Prompt Guard 2) can benchmark against their own tool outputs rather than trusting published leaderboards.
- **Safer agent frameworks**: LLM agent platforms (AutoGPT, LangChain, etc.) can embed agent-specific detector evaluation into their testing pipelines.

## Product & Startup Ideas
1. **Agent-specific detector marketplace**: A platform that runs submitted detectors against real tool outputs from popular agent frameworks (ReAct, AutoGPT, etc.), publishing true rankings to replace misleading benchmark leaderboards.
2. **Prompt injection security scanning SaaS**: A service that replays customers' LLM agent logs (with differential injection) to audit their detectors' real-world performance and certify safety before deployment.
3. **Automated detector benchmarking tool**: Internal software (open-source or commercial) that teams integrate into CI/CD to continuously evaluate detectors against their agent's actual tool outputs.
4. **LLM agent security insurance**: Underwrite risk for teams using tool-calling LLMs; base underwriting on real detector performance (via this paper's methodology) rather than benchmark scores.
5. **Custom detector training service**: Train injection detectors on a customer's own agent tool outputs and attack patterns, exploiting the finding that domain-matched training is the strongest predictor of generalization.

## Technical Limitations
- **Limited detector coverage**: Only 15 detectors evaluated; newer or proprietary defenses may behave differently.
- **Benchmark scope**: Tested on two agent benchmarks (AgentDojo, tau-bench); generalization to other agent frameworks (e.g., LLaMA-Agents, AutoGPT variants) is unexplored.
- **Attack model simplicity**: Uses "differential replay" injection (run benign, inject payloads) — does not test adaptive attackers who observe the detector and craft evasive payloads.
- **False-positive definition**: Reports false-positive rates on injected benign outputs; does not measure cost of false positives (e.g., legitimate outputs incorrectly blocked) in end-to-end agent performance.
- **No defense proposals**: The paper diagnoses the problem but does not propose new detectors or training strategies to improve transfer.
- **Static tool outputs**: Assumes tool outputs are fixed; does not model adversarial tool-building or scenarios where the attacker controls tool design.

## Open Questions
1. **Adaptive attacks**: Can attackers use knowledge of detector training data (now more transparent) to craft injection strings that evade agent-trained detectors?
2. **Detector ensemble robustness**: Do ensembles of detectors trained on different distributions perform more robustly than single detectors?
3. **What makes an input distribution "agent-like"?**: Which features of tool outputs (nesting depth, length, format) most strongly predict detector generalization, and can this guide detector training?
4. **Real-world prevalence**: How often do prompt injections actually occur in deployed agent systems, and does the false-positive cost matter in practice?
5. **Meta-learning for detectors**: Can detectors be fine-tuned on a small sample of real tool outputs from a new agent to quickly adapt ranking?
6. **Certified defenses**: Are there detector architectures or training procedures that come with theoretical guarantees of transferability across agent types?

## Key Takeaway
Benchmark leaderboards for prompt-injection detectors are unreliable guides to real-world performance in LLM agents—test on your own tool outputs before deployment.
