# GQ-FSL: Green Quantized Federated Split Learning

**Authors:** Idan Roth, Lutz Lampe
**Published:** 2026-07-31 | **arXiv:** [2607.29659v1](http://arxiv.org/abs/2607.29659v1)

## Summary
This paper tackles the energy problem of running neural networks on mobile devices by proposing GQ-FSL, a method that combines federated split learning (distributing computation between device and server) with quantization (using fewer bits to represent numbers). The key insight is allowing different precision levels on the device versus server side, which cuts energy consumption while maintaining accuracy—enabling practical deployment of large models on battery-constrained phones and IoT devices.

## Theoretical Background
The paper builds on two prior concepts: **federated split learning (FSL)**, which splits a neural network between a local device and an edge server to reduce on-device computation, and **quantization**, a technique that reduces model size and computation by representing weights and activations with fewer bits (e.g., 8-bit instead of 32-bit floats). The authors add stochastic quantization (using randomized rounding during training) and develop convergence theory accounting for data heterogeneity—the real-world problem that different devices have different data distributions. Prior work in federated learning assumes data is identically distributed; this work relaxes that assumption.

## Core Contributions
1. **Asymmetric quantization scheme**: Unlike prior quantized FSL, GQ-FSL allows different bit-widths on client and server sides, decoupling per-device energy constraints from global model convergence.
2. **Parameterized energy models**: Explicit formulas quantifying energy cost of computation and wireless transmission for split architectures, enabling principled trade-off analysis.
3. **Convergence analysis under heterogeneity**: Theoretical bound proving that stochastic quantization doesn't break convergence when data distributions vary across devices.
4. **Joint optimization**: Automated algorithm to pick the split point (where to cut the network) and precision levels for both sides, minimizing total system energy subject to accuracy targets.

## Connections to Other Work
GQ-FSL extends [[federated learning]] by addressing the "last mile" problem: federated learning reduces communication, but FSL further cuts device-side compute. However, FSL still requires transmitting intermediate activations (the "cut-layer data"), which burns energy. This work complements [[quantization]] techniques (e.g., post-training or quantization-aware training) by applying them in a split, heterogeneous setting. It also relates to [[communication-efficient learning]] literature but focuses on energy rather than bandwidth alone.

## Practical Applications
1. **Mobile health monitoring**: Wearables running stress detection or ECG analysis models without constant cloud uploads; training happens locally with minimal battery drain.
2. **Smart home inference**: Cameras, microphones, and sensors in IoT devices performing on-device inference (object detection, audio classification) while occasional model updates sync with a home hub.
3. **Vehicular networks**: Autonomous vehicles or connected cars running object detection and path planning, splitting compute between the car's edge compute unit and a nearby roadside server.
4. **Industrial predictive maintenance**: Factory sensors detecting equipment failure patterns without uploading raw sensor data, using local quantized models and sparse updates to a central server.

## Product & Startup Ideas
1. **Edge AI optimization platform**: SaaS tool where ML teams upload a model, specify device hardware constraints (battery, compute), and get auto-recommended split points + quantization configs with estimated energy savings—sell to IoT/mobile app companies.
2. **"GreenML" consulting service**: Specialize in retrofitting existing federated learning pipelines (e.g., at telecom or healthcare companies) with GQ-FSL, quantifying energy/cost reduction for regulatory compliance.
3. **Embedded model marketplace**: Pre-optimized, quantized model library for common tasks (anomaly detection, classification, NLP) with published energy profiles per device type—freemium model targeting IoT startups.
4. **Real-time energy-accuracy dashboard**: Monitoring tool for federated deployments showing per-device energy consumption, model drift, and automatic precision adjustment recommendations.
5. **Hardware-software co-design tool**: IDE for embedded developers that simulates GQ-FSL training end-to-end, visualizing communication/compute trade-offs and generating optimized model artifacts for target hardware.

## Technical Limitations
1. **Convergence bound looseness**: Theoretical guarantees likely contain loose constants; it's unclear how tight the bounds are in practice or if tighter analysis is possible.
2. **Heterogeneity assumptions**: The analysis assumes statistical heterogeneity (non-IID data) but may not capture adversarial or extreme imbalance (e.g., one device with vastly different label distribution).
3. **Energy model accuracy**: Energy estimates depend on hardware-specific parameters (compute power draw, wireless channel state); portability to new devices requires re-calibration.
4. **Fixed-precision assumption**: The framework assumes each weight/activation uses one fixed precision level; dynamic per-layer or per-batch quantization is not explored.
5. **Scalability to massive federations**: No discussion of performance with thousands of devices or communication topology beyond client-server (e.g., hierarchical or mesh networks).
6. **Training overhead**: Stochastic quantization during training adds noise; unclear how much this slows convergence in wall-clock time or affects final model quality long-term.

## Open Questions
1. Can we adaptively adjust precision levels *during* training based on per-device energy budgets and network conditions, rather than fixing them upfront?
2. How does GQ-FSL perform with highly non-IID data (e.g., label skew > 90:10)? Do the convergence bounds still hold?
3. What happens with dynamic device availability (devices dropping out due to battery depletion)? Does the algorithm degrade gracefully?
4. Can we extend this to multi-tier hierarchies (device → edge server → cloud) with cascading quantization?
5. Does learned quantization (training bit-width selection as part of the model) outperform the analytical optimization approach?

## Key Takeaway
Quantizing both sides of federated split learning with different precisions drastically cuts device energy while preserving model accuracy.
