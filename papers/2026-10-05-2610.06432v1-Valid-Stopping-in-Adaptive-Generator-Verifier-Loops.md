# Valid Stopping in Adaptive Generator-Verifier Loops

**Authors:** Mahmoud Hegazy, Michael I. Jordan, Aymeric Dieuleveut
**Published:** 2026-10-05 | **arXiv:** [2610.06432v1](http://arxiv.org/abs/2610.06432v1)

## Summary
This paper addresses a practical problem in agentic workflows: when should a generator-verifier loop stop searching? The core issue is that a cheap verifier (like a learned proxy) often disagrees with a costly ground-truth check (like actual lab validation), leading to false acceptances. The authors develop statistical methods to control how many bad proposals get accepted while the system is running.

## Theoretical Background
Generator-verifier loops are central to many AI systems—a model generates candidates, a fast filter scores them, and the system stops when something passes the filter. The problem arises because the verifier is a proxy: it's fast but imperfect. This connects to classical statistical testing challenges, particularly controlling false discovery rate (FDR)—the expected proportion of false positives among all positives. The paper leverages two modern tools: **e-values** (a generalization of p-values that remain valid under adaptive, sequential stopping) and **conformal prediction** (a distribution-free framework that makes few assumptions about data). The authors extend conformal methods to handle non-monotone losses—situations where the cost function doesn't increase smoothly, which is common in practice.

## Core Contributions
1. **Valid stopping rules**: A principled method to decide when to halt a generator-verifier loop while guaranteeing FDR control—meaning you know, with statistical certainty, how many false acceptances to expect.
2. **E-value construction via index betting**: A novel approach to building e-values through sequential betting strategies, providing valid inference even when the generator adapts against the verifier.
3. **Conformal risk control for non-monotone losses**: Extends classical conformal prediction (which typically requires monotone, smooth cost functions) to handle realistic, irregular loss landscapes.
4. **Empirical validation**: Demonstrations on synthetic problems and a real protein-design task, showing the method catches invalid proposals the verifier would accept.

## Practical Applications
1. **Protein design and drug discovery**: A fast neural model proposes mutations; expensive wet-lab validation checks them. Stop when you're confident enough bad proposals won't slip through.
2. **LLM-assisted search**: An LLM generates solutions; a cheap ranker filters them; a human expert checks the top candidate. Decide when to stop generating without wasting expert review on false positives.
3. **Automated code generation**: A model proposes code; static analysis (fast) screens it; runtime tests (slow) verify correctness. Stop when the pass rate is trustworthy.
4. **Materials science**: Computational screening proposes compounds; DFT simulation validates them. Control false positives in the accept-reject boundary.
5. **Autonomous systems testing**: A simulator generates test cases; a cheap heuristic judges them; real-world validation (costly) confirms safety. Stop generating when you have confidence the test suite is valid.

## Technical Limitations
1. **Computational cost of e-value computation**: While the method is distribution-free, computing e-values and conformal sets can be expensive for high-dimensional or large-scale generators—the paper doesn't deeply explore computational scalability.
2. **Assumption of independent verifications**: The FDR control assumes verifications are independent; in practice, a biased verifier or correlated errors between proxy and ground-truth could violate guarantees.
3. **Non-monotone loss handling is new but untested at scale**: The novel conformal procedure for non-monotone losses is theoretically sound but validated only on relatively small benchmarks; behavior on complex, real-world losses remains unclear.
4. **Generator adaptivity**: While e-values handle adaptivity, the paper assumes the generator's adaptation is not adversarial. A generator deliberately exploiting the verifier's weaknesses might still achieve high false acceptance rates.
5. **Sample efficiency**: The method requires enough samples to reliably estimate conformal quantiles; with very limited ground-truth data, guarantees can be weak.
6. **Verifier quality**: If the cheap verifier is extremely poor (high Type II error—rejecting good proposals), the loop may never terminate or waste enormous computation.

## Open Questions
1. **Computational efficiency**: How can e-value computation scale to large batches of proposals? Can you approximate e-values with warm-start or caching?
2. **Adaptive adversaries**: What happens if the generator learns to specifically fool the verifier while passing the proxy? Can the method detect or prevent this?
3. **Verifier calibration**: How sensitive are the FDR guarantees to miscalibration in the proxy verifier? Can you detect when the verifier is systematically biased?
4. **Multi-verifier systems**: Real workflows often have cascading verifiers (cheap → medium → expensive). How does the theory extend?
5. **Dynamic thresholds**: Can you adapt the "good enough" threshold on the fly while maintaining valid FDR control, rather than fixing it upfront?
6. **Comparative efficiency**: How much does FDR-controlled stopping cost (in computational resources) vs. heuristic stopping rules? When is the statistical guarantee worth the overhead?

## Key Takeaway
Stop agentic loops with statistical certainty about false acceptances, using distribution-free testing and adaptive verifier control.
