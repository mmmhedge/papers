# Reliability-Contagion Feasibility in LLM Multi-Agent Networks

**Authors:** Ruiwu Niu, Xincheng Shu, Ying Zhao
**Published:** 2026-07-24 | **arXiv:** [2607.21912v1](http://arxiv.org/abs/2607.21912v1)

## Summary
This paper studies how errors spread through networks of communicating LLM agents—like a disease contagion—and derives mathematical conditions for when reliability can coexist with information sharing. The authors show that adding more connections to an agent network creates a fundamental trade-off: more communication helps agents correct errors collectively, but also speeds up error propagation. They identify network topologies that balance these opposing forces.

## Theoretical Background
The work builds on [[SEIR models]] (epidemiological frameworks tracking Susceptible, Exposed, Infectious, and Recovered populations), adapting them to model error spread in agent networks. It couples this to majority-vote aggregation—a classical consensus mechanism where agents pool evidence and decide by vote. The paper frames the problem using network theory: how graph structure (connectivity, degree distribution, topology) affects both information pooling benefits and contagion risk. The "invasion factor" measures how efficiently errors propagate in early stages, drawing from dynamical systems analysis of threshold dynamics on networks.

## Core Contributions
1. **Correction-aware contagion model**: Extends classical epidemic models to explicitly track when agents correct erroneous claims, not just when they adopt them.
2. **Quantified reliability–propagation trade-off**: Proves that under fixed communication cost per edge, reliability and error control impose *opposing* graph constraints—more connectivity can hurt robustness even as it improves collective decision-making.
3. **Invasion condition for heterogeneous networks**: Derives early-invasion thresholds for networks with varying agent degrees and link types.
4. **Optimal regular graphs**: Identifies which regular (homogeneous-degree) topologies minimize contagion risk *within* the space of reliable graphs.
5. **Budget-dependent propagation**: Shows that under a fixed sender budget (total communication capacity), first-order thresholds become independent of network density—a counterintuitive scaling result.

## Practical Applications
1. **Designing safe agent swarms for knowledge work**: Construction of internal communication graphs for teams of code-generation or research agents to maximize fact-checking while minimizing error contagion.
2. **Federated LLM inference**: Distributed inference systems where agents verify each other's outputs—topology selection to balance latency (connectivity) and accuracy.
3. **Crisis response chatbot networks**: Coordinated systems answering public health or emergency questions where false information spreads fast; network design to control misinformation.
4. **Scientific collaboration platforms**: Multi-agent literature review and hypothesis generation, where incorrect citations or interpretations can propagate; topology prevents consensus around false claims.
5. **Autonomous content moderation**: Networks of classifier agents that consult peers; topology selection to prevent coordinated error adoption.

## Product & Startup Ideas
1. **Network topology optimization service**: A tool that takes reliability targets and communication budgets, outputs recommended agent-network architectures (e.g., ring, small-world, hierarchical) for enterprises deploying multi-agent LLM systems. Pricing per deployment configuration.
2. **Multi-agent LLM framework with built-in contagion guards**: An open-source or commercial orchestration layer (like LangGraph extended) that simulates error propagation under proposed topologies before deployment and warns on unsafe configurations.
3. **Supply-chain coordination AI**: Multi-agent system for procurement/logistics where agents share market intel; uses the paper's graph constraints to prevent cascading bad decisions (e.g., panic buying).
4. **Distributed financial research platform**: Hedge funds deploy agent networks for cross-asset research; the framework ensures high-confidence consensus while topology controls error-cascade risk.
5. **Robustness audit service for multi-agent deployments**: Consultancy that evaluates existing agent networks (chatbot teams, content systems) for susceptibility to contagion using the paper's invasion factor; recommends rewiring.

## Technical Limitations
1. **Majority-vote assumption**: Real agent networks may not use simple majority voting; hierarchies, trust-weighting, and algorithmic voting rules are more complex and may violate the analysis.
2. **Homogeneity in experiments**: The grok-4.3 experiments use only 6-node networks and 36 closed-world tasks—scaling to large, real-world agent populations and open-ended tasks is untested.
3. **Correction model**: The paper assumes agents *can* correct errors if exposed to the truth; in practice, agents may double down on false beliefs or fail to recognize corrections.
4. **Edge-cost assumptions**: Results depend heavily on whether cost is "per edge" vs. "per communication event"—different budget models flip the conclusions.
5. **Static networks**: The analysis assumes fixed topology; real deployments adapt connections dynamically, potentially breaking early-invasion predictions.
6. **No adversarial agents**: The model assumes all errors are stochastic; it doesn't account for agents deliberately spreading misinformation.

## Open Questions
1. **Dynamic topology selection**: Can agents or operators rewire their network *during* information flow to minimize contagion while preserving reliability? What is the optimal online algorithm?
2. **Heterogeneous agent reliabilities**: How do results change if agents have different intrinsic error rates? Can high-reliability agents be isolated to prevent contagion from low-reliability ones?
3. **Multi-topic propagation**: Real domains involve multiple interrelated claims; how does the framework extend when errors on topic A affect credibility on topic B?
4. **Feedback loops and reputation**: After an agent makes an error, should its future recommendations be downweighted? How does reputation decay interact with contagion?
5. **Scaling to 1000+ agents**: Do the analytical predictions hold? Do small-world or scale-free networks (common in practice) behave differently?
6. **Empirical contagion measurement**: Can the paper's invasion factor be directly measured from real multi-agent LLM deployments, or are unmeasured confounds large?

## Key Takeaway
Connected agent networks spread errors faster than they correct them—topology must be carefully designed to balance information sharing with contagion control.
