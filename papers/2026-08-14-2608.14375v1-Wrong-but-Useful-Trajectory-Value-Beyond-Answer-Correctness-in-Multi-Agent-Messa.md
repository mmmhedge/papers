# Wrong but Useful: Trajectory Value Beyond Answer Correctness in Multi-Agent Messages

**Authors:** Chih-Hsuan Yang, Anjir Ahmed Chowdhury, Cheng-Hau Yang, Weijian Zheng, Fernando Llorente et al.
**Published:** 2026-08-14 | **arXiv:** [2608.14375v1](http://arxiv.org/abs/2608.14375v1)

## Summary
This paper shows that in multi-agent reasoning systems, wrong answers can still be useful for reaching correct final conclusions. The authors introduce Diverse Hypothesis Deliberation (DHD), a measurement method that tests whether individual messages help or harm downstream reasoning by replaying the same solver with each message hidden or visible. They find that across multiple benchmarks and models, incorrect messages frequently improve final correctness because they contain valuable reasoning steps, constraints, or principles—suggesting that agreement or correctness alone shouldn't determine which messages to keep.

## Theoretical Background
Multi-agent reasoning systems combine outputs from multiple independent reasoners (agents) to improve overall performance. Traditional approaches use agreement, confidence scores, or automated correctness metrics to filter which agent outputs to keep. The implicit assumption is that correctness predicts usefulness. This paper builds on work in [[ensemble learning]], [[chain-of-thought prompting]], and [[agent collaboration]], but challenges the assumption that message value equals answer correctness. The measurement protocol (DHD) uses causal intervention—hiding or revealing messages to a downstream integrator (solver)—to isolate each message's causal effect on final reasoning quality.

## Core Contributions
1. **Trajectory Value Concept**: Introduces "trajectory value" — a distinction between whether a message is correct and whether it helps downstream reasoning reach a correct answer.
2. **DHD Protocol**: Proposes a controlled, reusable measurement method that replays an integrator with each message available/hidden, isolating causal effects (not just correlation).
3. **Empirical Measurement**: Demonstrates across five benchmarks and two model families that 40%+ of wrong messages that change final correctness are helpful; these effects are statistically robust (p=0.0002).
4. **Intervention Analysis**: Shows that complete wrong-helpful messages work better than their answers or reasoning alone; the mechanism remains unexplained.
5. **Practical Labels**: Produces trajectory-value labels for training better filtering policies.

## Connections to Other Work
This relates to [[ensemble methods]], [[debate-in-AI]], and multi-agent reasoning frameworks. It challenges assumptions in [[RLHF]] (reward models trained on correctness) and [[self-consistency]] decoding. The work also connects to [[mechanistic interpretability]] by examining what makes a message's contribution valuable beyond surface correctness. Similar to [[chain-of-thought interpretability]] research, it uncovers that intermediate reasoning artifacts carry signal independent of final answer truth.

## Practical Applications
- **Collaborative AI Systems**: Improve message filtering in multi-LLM teams working on science or math problems (e.g., research automation, tutoring systems).
- **Scientific Reasoning Pipelines**: Better selection of hypotheses or proof attempts when multiple agents propose solutions with different decompositions.
- **Debugging & Education**: Identify explanations or reasoning traces that are "wrong but illuminating" for pedagogical purposes.
- **Collaborative Problem-Solving**: Design systems where human teams and AI agents deliberate; trajectory value helps decide whose input to amplify.

## Product & Startup Ideas
1. **"Deliberation Dashboard"**: A platform for research teams where multiple AI agents solve problems in parallel, and trajectory-value scoring automatically highlights non-obvious useful contributions (vs. just voting by correctness).
2. **"Science Co-Pilot for Universities"**: Tutoring/research assistant that learns which wrong approaches or intermediate insights help students (or postdocs) reach correct answers, using DHD-like scoring.
3. **"Hypothesis Ranker API"**: For scientific workflows, rank candidate hypotheses or solution sketches not by predicted correctness but by trajectory value—helping labs prioritize experiments.
4. **"Collaborative LLM Router"**: A service that routes queries to different specialized models and uses trajectory-value labels to learn which model outputs to route to the final integrator (vs. traditional ensemble voting).
5. **"Multi-Agent Reasoning Debugger"**: Tool for enterprises using multi-agent AI (customer support, data analysis) to audit why certain agent suggestions were helpful or harmful, improving training of integration policies.

## Technical Limitations
- **Mechanism Opaque**: The paper identifies that wrong-helpful messages work but does not explain *why* their reasoning helps more than their answer; scaling this finding requires deeper mechanistic understanding.
- **Controlled Setting**: DHD requires replaying the same integrator multiple times (expensive). Generalizing to online or resource-constrained settings is unclear.
- **Limited Scope**: Tested only on mathematics and science benchmarks; generalization to open-ended tasks, code generation, or creative domains is unknown.
- **Model Dependency**: Results are specific to gpt-oss-120b and gemma-4-31B-it; behavior may differ for smaller, larger, or differently-trained models.
- **Label Quality**: DHD labels are still noisy (downstream solver variation exists); reliability of labels for training downstream policies not fully characterized.
- **Causal Assumption**: Assumes hidden/visible message toggles isolate causal effects; interaction effects between messages not addressed.

## Open Questions
- Why do wrong messages with good reasoning steps help? Can we isolate which *components* of a wrong solution are reusable (e.g., a constraint, a decomposition, an intermediate state)?
- How do wrong-helpful messages interact? If two wrong messages are shown together, do they interfere or reinforce?
- Can we predict trajectory value without expensive replay? Is there a lightweight proxy (e.g., diversity, reasoning length, confidence diversity)?
- How does trajectory value scale with model size, training method, or task domain? Is it a general phenomenon?
- Can we train integrators *on* trajectory-value labels to learn better filtering policies? What is the sample efficiency?
- Does trajectory value depend on the order or timing of message presentation?

## Key Takeaway
Wrong answers can meaningfully improve multi-agent reasoning when they contain useful reasoning steps; correctness alone shouldn't filter which messages to keep.
