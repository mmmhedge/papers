# DART-SD: Diamond-topology Aware Retrieval and Tuning for Self-Distillation of Multi-Turn Tool-Calling Agents

**Authors:** Hangrui Xu, Jiarui Wang, Yang Yang, Chuanbo Zhu, Fangda Chen et al.
**Published:** 2026-08-19 | **arXiv:** [2608.18524v1](http://arxiv.org/abs/2608.18524v1)

## Summary
This paper addresses a fundamental problem in training autonomous agents: when tasks have multiple valid solution paths (order-independent sub-goals), standard trajectory imitation learning forces all solutions into a single path, penalizing valid alternatives. DART-SD instead models the solution space as a "diamond topology" — a lattice of converging paths — and uses targeted self-distillation to correct only the parts of reasoning that failed, preserving correct reasoning steps that precede failure points.

## Theoretical Background
The work builds on several foundations: (1) **tool-calling agents** — LLMs augmented with API access to perform multi-step tasks; (2) **imitation learning** — training agents by copying trajectories from successful executions; (3) **graph-based representations** — specifically, directed acyclic graphs (DAGs) that capture multiple execution paths converging to the same goal state; (4) **self-distillation** — a training technique where a model learns from its own generated outputs, refined through targeted supervision.

The key insight is recognizing that many multi-turn tasks don't have a single optimal ordering—tools can be called in different sequences if dependencies are satisfied. Traditional trajectory imitation treats each unique sequence as a separate training signal, causing "topological collapse" where the model learns spurious preferences for one ordering over equally valid alternatives.

## Core Contributions
1. **Interaction-State Transition Graph (ISTG)**: A structured representation capturing the diamond topology of both successful and failed execution paths, rather than treating trajectories as flat sequences.

2. **Critical Topological Breakpoint (CTB) detection**: An algorithm to identify where an exploratory rollout first diverged from any valid execution path—the precise point where correction is needed.

3. **Localized self-distillation**: A training paradigm that applies loss only to the recovery steps (from CTB onward), with explicit gradient masking to prevent destructive updates to the correct reasoning prefix.

4. **Empirical validation**: Experiments on multi-turn tool-calling benchmarks showing significant improvements in both success rate and policy diversity versus full-trajectory baselines.

## Connections to Other Work
This work sits at the intersection of:
- **[[Reinforcement Learning from Human Feedback (RLHF)]]** and **self-distillation** — using model-generated rollouts for training refinement, but with finer-grained supervision.
- **Agent frameworks** like [[ReAct]] and [[Toolformer]]—extending these with better learning algorithms for complex tool use.
- **Multi-path learning** — related to work on curriculum learning and goal-conditioned RL that acknowledge non-unique solution paths.
- **Graph-based reasoning** — conceptually related to [[Graph Neural Networks]] for representing structured solution spaces, though applied here to sequential agent decisions.

The core innovation is recognizing that agent training shouldn't enforce a single trajectory when the task structure admits multiple valid ones.

## Practical Applications
1. **Autonomous software agents**: Training agents to complete multi-step coding tasks (database queries, API orchestration, file manipulation) where the order of operations can vary.

2. **Research automation**: Agents that gather and synthesize information from multiple sources in flexible orders—literature search, data collection, hypothesis testing.

3. **Task planning systems**: Industrial automation and robotics where subtask ordering is flexible (e.g., assembly tasks with independent work streams).

4. **Business process automation**: RPA-style agents handling order processing, customer service routing, or data entry with multiple valid workflows.

5. **Scientific discovery**: Agents designing experiments or simulations where preliminary steps can be reordered without changing validity.

## Product & Startup Ideas
1. **"Agent Training as a Service"** — Cloud platform that automatically detects task topologies from human demonstrations and optimizes agent training without requiring manual trajectory annotation. Pricing: per-agent-rollout or per-deployed-agent.

2. **"WorkflowDive"** — Enterprise software that audits RPA/automation workflows, identifies all valid execution paths (the diamond topology), and trains agents robust to any ordering. Sells to enterprises with fragile automation stacks.

3. **"Multi-Path Agent Studio"** — No-code/low-code tool for building and training tool-calling agents with built-in topology detection. Targets business analysts and citizen developers building custom agents.

4. **"Agent Certification System"** — A testing framework that evaluates whether trained agents handle all valid orderings of subtasks, not just the one shown in training. Sells to regulated industries (finance, healthcare).

5. **"Flex Reasoning API"** — Managed LLM service that wraps standard LLMs with DART-SD-style training, allowing customers to deploy more robust multi-step agents without retraining models themselves.

## Technical Limitations
1. **Topology discovery assumption**: The framework assumes the task's valid ordering structure is already known or easily discoverable from successful trajectories. For tasks with deeply hidden constraints, ISTG construction may be incomplete or incorrect.

2. **Scalability to very long horizons**: Detecting CTB and maintaining state graphs grows expensive for 20+ step tasks; the paper doesn't report wall-clock scaling analysis.

3. **Limited to order-independent sub-goals**: Tasks where ordering genuinely matters (sequential dependencies, state-dependent branching) don't benefit from the diamond topology framing.

4. **Self-distillation circularity**: The approach relies on the agent generating rollouts to recover from; if the agent is already severely broken, recovery references may not exist, limiting learning from harder failure modes.

5. **Evaluation scope**: Experiments focus on "complex multi-turn tool-calling benchmarks" (likely API/search tasks); generalization to diverse domains (robotics, real dialogue, creative tasks) unclear.

## Open Questions
1. How does DART-SD perform on tasks where the true solution topology is **not** a diamond—e.g., tasks with hard sequential dependencies or nested decision structures?

2. Can CTB detection work when the agent's failure is due to **incorrect state representation** rather than wrong action choices? Does the approach degrade gracefully?

3. What is the computational overhead (graph construction, CTB detection, masked gradient computation) as task horizon grows? At what point does it become infeasible?

4. How sensitive is the method to **noise in trajectory data**—e.g., demonstrations that appear valid but have subtle errors?

5. Does the approach generalize across **different tool distributions**—e.g., training on one API set and testing on different tools in the same topological structure?

6. Can you **infer** the task topology without ground-truth successful trajectories, using only failed rollouts and weak supervision?

## Key Takeaway
Smart agent training preserves valid reasoning paths instead of forcing all solutions into one trajectory, improving both performance and adaptability.
