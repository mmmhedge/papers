# Dynamic Expert Pruning for Multi-Agent Systems

**Authors:** Jabin Koo, Soheil Abbasloo, Sungjae Lee, Jungseul Ok
**Published:** 2026-10-02 | **arXiv:** [2610.02951v1](http://arxiv.org/abs/2610.02951v1)

## Summary

This paper proposes Dynamic Expert Pruning (DEP), a method that reduces memory footprint in Mixture-of-Experts language models by dynamically selecting which model components ("experts") to activate based on the specific task and agent at hand. Rather than using a single fixed pruning mask for all requests, DEP learns to predict task-specific masks from system prompts, enabling more efficient deployment in multi-agent environments where different agents have different needs.

## Theoretical Background

Mixture-of-Experts (MoE) architectures scale transformer models by routing each token to only a small subset of experts—specialized sub-networks—rather than activating the entire model. While this reduces computation per token, all experts must remain stored in GPU memory, creating a deployment bottleneck. Expert pruning attempts to permanently remove unimportant experts to shrink memory footprint. Prior work on pruning has been *static*: a single pruning mask is calibrated offline and applied to every inference request. The key insight here is that in multi-agent systems—where a single backbone model serves multiple agents with different roles and tasks—a one-size-fits-all mask is suboptimal because different tasks recruit different experts.

## Core Contributions

1. **Empirical finding**: System and task prompts alone sufficiently encode which experts an agent needs; pruning patterns differ across tasks and roles, invalidating the static pruning assumption.

2. **Dynamic Expert Pruning method**: A lightweight predictor network (trained once on workflow transcripts) maps agent/task prompts → per-request expert masks in a single forward pass, requiring no per-configuration calibration.

3. **Generalization without retraining**: DEP generalizes to unseen workflows without retraining, and the performance gap vs. static baselines widens when retaining fewer experts, demonstrating that role specialization enables sparser serving.

## Connections to Other Work

This work sits at the intersection of [[Mixture-of-Experts]] scaling and dynamic inference optimization. It extends static pruning (e.g., magnitude pruning, structured sparsity) into the temporal/task-adaptive domain. Related to [[multi-agent systems]] literature on task-specific model adaptation and [[transformers]] efficiency work (e.g., token pruning, layer skipping). The prompt-based expert prediction parallels recent work on using natural language descriptions to guide model behavior, though applied here to structural efficiency rather than task performance.

## Practical Applications

1. **Cost-effective multi-tenant LLM serving**: Cloud providers can serve many concurrent agents/tenants on shared GPU hardware with reduced memory footprint, increasing utilization and lowering per-request cost.

2. **Mobile/edge deployment of specialist agents**: Resource-constrained devices (robots, IoT, mobile) can run role-specific LLM agents by keeping only necessary experts in memory.

3. **Conversational agent platforms**: A single backbone with DEP can efficiently switch between customer-support, technical-support, and sales agents, each using a different expert subset.

4. **Multi-role game AI**: In open-world games or simulations, NPCs with different roles (merchant, guard, quest-giver) can share a backbone but activate task-specific experts.

## Product & Startup Ideas

1. **Multi-tenant LLM inference platform**: SaaS offering that dynamically allocates experts per customer/workload, achieving 2–3× memory efficiency vs. static pruning and passing savings to customers via lower API costs.

2. **Specialized agent-as-a-service marketplace**: Spin up role-specific LLM agents (legal advisor, financial analyst, technical support) that share a backbone, reducing infrastructure spend by 40–60% compared to separate fine-tuned models.

3. **On-device multi-role assistant framework**: Middleware/SDK for deploying multiple AI personas on edge devices (phones, robots, cars) with dynamic expert routing, enabling richer offline experiences.

4. **Enterprise workflow automation**: Software that learns an organization's task-specific expert patterns and auto-configures agent inference, reducing latency and hardware costs for internal GenAI workflows.

5. **Open-source MoE optimization toolkit**: Developer tools and libraries for easy integration of DEP into existing MoE training pipelines, with telemetry to help teams identify expert utilization patterns.

## Technical Limitations

1. **Prompt dependency**: The method assumes system/task prompts are available and sufficiently descriptive. Adversarial or malformed prompts may trigger suboptimal expert masks.

2. **Predictor training**: Requires transcripts of representative workflows; performance on highly novel task distributions may degrade without online adaptation or retraining.

3. **Sparsity trade-offs**: While DEP excels at high sparsity (few experts), the gains may plateau at moderate sparsity where static baselines are already reasonable.

4. **Overhead not fully characterized**: The paper does not deeply analyze latency/memory overhead of the lightweight predictor itself, or how it scales with model size and number of experts.

5. **No analysis of failure modes**: Limited discussion of when agents genuinely need overlapping or unexpected experts, or how robust DEP is to distribution shift in real-world workloads.

## Open Questions

1. Can DEP adapt online as it encounters new task patterns, or does it require expensive retraining?

2. How does performance scale with number of agents and tasks? Is there a saturation point where the predictor becomes a bottleneck?

3. Can the same predictor be shared across models of different sizes, or must it be retrained per architecture?

4. What is the relationship between prompt quality/length and pruning effectiveness? Can shorter prompts work as well?

5. How does DEP interact with other efficiency techniques (quantization, distillation, token pruning)? Can they be combined?

6. In practice, how often do agents' needs change within a session? Is static-per-session masking sufficient, or is per-request adaptation critical?

## Key Takeaway

Dynamic pruning of expert models for multi-agent systems improves efficiency by predicting task-specific expert subsets from prompts rather than using a fixed mask.
