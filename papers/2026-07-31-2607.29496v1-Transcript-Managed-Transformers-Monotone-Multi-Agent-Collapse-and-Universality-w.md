# Transcript-Managed Transformers: Monotone Multi-Agent Collapse and Universality with Two Pop-Enabled Transcripts

**Authors:** Sergey Salishev
**Published:** 2026-07-31 | **arXiv:** [2607.29496v1](http://arxiv.org/abs/2607.29496v1)

## Summary
This paper studies how Transformers with finite precision and fixed weights can be formally analyzed as computational machines with stack-like memory channels (transcripts). The authors prove that with two pop-enabled transcripts (stack operations), a system of agents can compute anything a Turing machine can—establishing a fundamental connection between transformer architectures and classical computability theory.

## Theoretical Background
The paper builds on formal language theory and automata theory, specifically the Chomsky hierarchy and stack-based computation models. Key prior foundations include:

- **Finite-state transducers**: machines that read symbols and produce outputs while maintaining finite internal state. The Restricted Transcript-Managed Transducer (RTMT) without pop operations realizes exactly deterministic finite-state transductions.
- **Context-free languages (DCFL)**: languages recognizable by deterministic pushdown automata (finite controller + one stack). The paper shows one pop-enabled transcript achieves this level.
- **Recursively enumerable (RE) languages**: the most powerful language class recognizable by Turing machines. The authors prove two pop-enabled transcripts suffice.
- **Hopcroft–Ullman formalism**: a classical presentation of pushdown automata that the paper leverages to map transcript operations to the language hierarchy.

The work treats Transformers as constrained computational devices: fixed weights, finite precision, and operations (append, pop, stay) on bounded blocks visible through fixed windows.

## Core Contributions
1. **Formal model of transcript-managed computation**: introduces the Transcript-Managed Transducer (TMT) framework, which abstracts transformer layers as finite controllers acting on partitioned memory channels.
2. **Characterization of pop-free layers**: proves that append-only transcripts (no pop) compute exactly deterministic finite-state transductions—even with multiple agents under monotone protocols.
3. **Universality result with two stacks**: demonstrates that two pop-enabled transcripts (one agent or two agents, doesn't matter) suffice for Turing-complete computation.
4. **Precise complexity bounds**: establishes simulation costs and proves invariance to fixed block size and visibility radius, while identifying what extensions (unbounded Spawn, writable stores, hidden-block access) push beyond current bounds.

## Connections to Other Work
This paper sits at the intersection of:

- **[[Mechanistic interpretability]]** of transformers: by formalizing transformer computation as transducers with explicit memory operations, it makes the internal structure transparent and analyzable.
- **Multi-agent protocols**: relates to work on how finite populations of agents with local information can solve problems through coordinated transcripts and visibility rules.
- **Formal language theory & computability**: connects modern neural architectures to classical automata hierarchies, showing transformers can bridge finite-state to Turing-complete computation with minimal structure.
- **Stack-based attention mechanisms**: complements work on structured memory in sequence models by proving theoretical necessity of pop operations for universality.

The monotone protocol constraint (append, route, copy only—no arbitrary reads) is a novel restriction not standard in classical automata theory.

## Practical Applications
1. **Verification of transformer behavior**: formally verify that a transformer layer with known structure and weight patterns can or cannot solve specific language/computation problems.
2. **Efficient transformer design**: identify minimal memory operations needed for target tasks (e.g., if a task requires only FST-level power, pop operations are wasteful).
3. **Debugging multi-agent systems**: analyze agent-to-agent communication protocols by mapping them to transcript operations and checking Chomsky hierarchy membership.
4. **Language understanding in dialogue systems**: prove bounds on what dialogue agents with fixed stack channels can learn or generate.

## Product & Startup Ideas
1. **Transformer capability analyzer**: SaaS tool that takes a transformer architecture specification and automatically determines what language classes it can compute, predicting task learnability before training.
2. **Provably bounded LLM layer design**: consulting service helping orgs build transformers with formal guarantees on memory usage and computational limits (useful for regulated industries).
3. **Multi-agent protocol verifier**: software that takes a multi-agent communication spec and certifies whether it can solve a given computational problem using the TMT hierarchy.
4. **Efficient architecture search engine**: automated tool that generates minimal transformer variants with pop operations only where theoretically necessary, reducing flops.
5. **Formal model extraction for interpretability**: tool that reverse-engineers a trained transformer's behavior and compiles it to a minimal equivalent TMT specification for auditing and explanation.

## Technical Limitations
1. **Finite precision assumption**: real transformers use floating-point arithmetic with rounding; the paper's formalization assumes exact finite alphabets, which may not capture numerical instability or gradient descent behavior.
2. **Fixed weights and protocol**: the model doesn't account for learning or adaptation—weights and routing rules are static. Training dynamics are out of scope.
3. **Visible suffix only**: agents can only see fixed-length recent context, not arbitrary historical blocks. Many practical attention patterns (e.g., attending to distant past) aren't modeled.
4. **Overhead not quantified**: while simulation costs are stated, practical constants and scalability with block count $k$ and context depth remain implicit.
5. **No noise or partial observability**: assumes deterministic, perfect observation within the visible window; real noisy channels aren't addressed.
6. **Causal constraint**: the "causal" assumption (no future context) is restrictive for bidirectional models (e.g., BERT).

## Open Questions
1. **Can subuniversal levels be efficiently learned?** If a task lies at the DCFL level, can gradient descent discover a one-channel pop architecture faster than a two-channel one?
2. **What is the minimum visible window size?** How does reducing the visible suffix radius affect expressiveness?
3. **Can pop operations be learned implicitly?** Do transformers trained on context-free language tasks naturally develop stack-like behavior in their attention patterns?
4. **How do continuous embeddings interact with finite-alphabet abstraction?** Can the model be extended to handle infinite alphabets or learned embeddings?
5. **Multi-agent learning dynamics**: if agents learn the transcript protocol jointly via RL, what hierarchy level do they converge to? Is two-transcript universality *necessary* in practice?
6. **Interaction with [[Attention Is All You Need]] mechanisms**: can classical multi-head attention be compiled into the TMT model, or does attention power exceed the stack hierarchy?

## Key Takeaway
Two pop-enabled memory channels let transformer agents compute anything Turing machines can—formalizing the computational ceiling of modern neural architectures.
