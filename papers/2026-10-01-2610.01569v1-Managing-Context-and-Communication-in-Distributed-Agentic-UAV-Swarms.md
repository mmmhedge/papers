# Managing Context and Communication in Distributed Agentic UAV Swarms

**Authors:** Andrea Iannoli, Ivan Zyrianoff, Angelo Trotta, Lorenzo Gigli, Marco Di Felice
**Published:** 2026-10-01 | **arXiv:** [2610.01569v1](http://arxiv.org/abs/2610.01569v1)

## Summary
This paper tackles a core challenge in distributed UAV swarms: how to keep each drone's onboard language model reasoning sharp while avoiding communication overload. The researchers propose an architecture where UAVs selectively share information based on what matters to each neighbor, rather than broadcasting everything. In a simulated search-and-rescue scenario with ten drones, their approach completes missions where naive message flooding fails, while cutting inference costs roughly in half.

## Theoretical Background
Distributed multi-agent systems (multiple independent actors coordinating without central authority) have long faced a fundamental tradeoff: unrestricted communication ensures shared awareness but wastes bandwidth and computation; silent operation keeps costs low but leaves agents making decisions on stale information. Recent work has deployed large language models (LLMs — neural networks trained on vast text corpora to generate coherent responses) as reasoning engines in agent architectures, enabling adaptive, natural-language-driven decision-making. The paper builds on earlier research in gossip protocols (distributed algorithms where nodes selectively share state with neighbors) and attention mechanisms in transformers, applying these to the specific constraints of UAV networks where communication bandwidth and inference power are scarce.

## Core Contributions
1. **Structured memory organization**: Runtime knowledge stored as atomic notes (facts) rather than raw conversation history, organized into three tiers — core (global mission data), local (drone-specific observations), and peer-specific (what each neighbor needs to know).
2. **Interest-aware gossip**: A deterministic algorithm that decides which notes to send to which neighbors based on semantic novelty and recency, not just flooding everything.
3. **Event-driven reason-act-observe lifecycle**: A clean execution loop that keeps the SLM's reasoning window small and focused, avoiding context degradation.
4. **Empirical validation**: Demonstrates that structured selective dissemination outperforms both unrestricted flooding (30–70% mission failure) and delegating forwarding to the SLM itself (100% failure).

## Connections to Other Work
This work sits at the intersection of [[multi-agent-systems]] (distributed coordination), [[large-language-models]] as agent cognition, and classical gossip/epidemic protocols. It echoes recent progress on [[context management in transformers]] (keeping model inputs concise) and [[RLHF]] style fine-tuning for agent behavior, but applies these ideas to the underexplored domain of resource-constrained embodied AI. The memory-tiering concept parallels retrieval-augmented generation (RAG) systems, which separate knowledge storage from reasoning. Unlike centralized multi-agent RL systems, this work leans toward symbolic, language-driven reasoning in a fully decentralized setting.

## Practical Applications
- **Search and rescue**: Rapid drone teams responding to disasters, where cellular networks may be unavailable and each UAV must reason locally about survivor locations and hazards.
- **Environmental monitoring**: Swarms of drones surveying forests or agricultural land, sharing alerts about fire hotspots, pest infestations, or weather anomalies without overwhelming a base station.
- **Infrastructure inspection**: Autonomous drone teams inspecting power grids, pipelines, or bridges, where each UAV learns what's anomalous and shares findings selectively.
- **Autonomous warehouse logistics**: Indoor drone fleets coordinating package movement with minimal central infrastructure.
- **Collaborative mapping**: Multiple drones exploring unknown terrain, building a shared map by exchanging only high-value observations.

## Product & Startup Ideas

2. **EdgeReason**: A SaaS platform for enterprises to deploy mission-critical swarms (power-line inspection, mining) with plug-and-play semantic memory and adaptive communication policies.
3. **RescueNet**: A specialized software suite for disaster-response organizations, pre-tuned for search-and-rescue with integrated weather/terrain APIs and survivor-detection SLMs.

## Technical Limitations
- **Scalability untested**: Evaluation on only ten UAVs; unclear how memory and gossip latency scale to 100+ drones or densely packed urban scenarios.
- **SLM capacity assumptions**: Assumes each UAV can host an SLM with acceptable latency; real-world hardware constraints (power budget, thermal limits) not addressed.
- **Semantic novelty is heuristic**: The "interest-aware" dissemination relies on hand-tuned similarity metrics; no formal guarantees that critical information won't be dropped if it doesn't match the heuristic.
- **Limited communication model**: Assumes reliable local wireless (e.g., WiFi Direct); performance under lossy, intermittent, or high-latency links unclear.
- **Mission specificity**: Architecture tuned for search-and-rescue; generalization to other mission types (e.g., adversarial swarms, real-time combat) untested.
- **No formal verification**: No proofs of mission-completion guarantees or convergence properties.

## Open Questions
- How does performance degrade as the number of drones scales? Is there a critical density beyond which gossip overhead becomes prohibitive?
- Can the memory schema and dissemination policy be learned (e.g., via reinforcement learning) rather than hand-designed, so the system adapts to new mission types?
- What is the relationship between SLM quality (model size, training) and the effectiveness of the gossip protocol? Can a weaker SLM be compensated by better information sharing?
- How robust is the approach to Byzantine failures (drones sending false information or behaving adversarially)?
- Can this architecture be extended to heterogeneous swarms where some UAVs are compute-rich and others are compute-constrained?
- What happens when communication is intermittent or the swarm is temporarily partitioned? How quickly can consensus be rebuilt?

## Key Takeaway
Selective information sharing cuts drone swarm coordination costs by half while keeping missions on track—a practical step toward truly autonomous distributed teams.
