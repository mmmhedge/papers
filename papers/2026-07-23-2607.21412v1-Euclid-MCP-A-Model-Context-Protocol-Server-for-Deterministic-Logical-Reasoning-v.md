# Euclid-MCP: A Model Context Protocol Server for Deterministic Logical Reasoning via Prolog

**Authors:** Bartolomeo Bogliolo
**Published:** 2026-07-23 | **arXiv:** [2607.21412v1](http://arxiv.org/abs/2607.21412v1)

## Summary
This paper introduces Euclid-MCP, a software tool that connects large language models to a logical reasoning engine (Prolog) so they can reliably solve multi-step logical problems instead of guessing. The work matters because LLMs are good at language but terrible at guaranteed logical correctness—critical in compliance, security, and safety applications—and this system bridges that gap by letting the LLM ask a symbolic engine for definitive answers.

## Theoretical Background
The paper builds on neuro-symbolic AI, which combines neural networks (like LLMs) with symbolic reasoning engines that follow strict logical rules. The symbolic side uses Horn-clause logic, a subset of first-order logic commonly implemented in Prolog (a logic programming language where you write rules and facts, then query them deterministically). The neural side relies on LLMs' ability to generate text. The gap being addressed is that LLMs often "hallucinate"—produce plausible-sounding but false answers—when asked to reason through chains of logical steps, especially on complex or unfamiliar problems. The paper also critiques semantic RAG (Retrieval-Augmented Generation), which retrieves relevant documents but doesn't guarantee logical correctness when rules must be enforced exactly.

## Core Contributions
1. **Euclid-IR**: A new intermediate representation for Horn-clause logic that is both human-readable and easily generated by LLMs, designed to be compiler-agnostic (can target Prolog, SQL, or other backends).
2. **Euclid-MCP server**: An implementation of the Model Context Protocol (MCP) standard that exposes Prolog inference as a tool interface, allowing LLMs to call logical reasoning on-demand via a translate-run-inspect-repair loop.
3. **Empirical demonstration**: Evidence that on realistic IT security/compliance tasks, LLMs + Euclid-MCP outperform LLMs alone in correctness and latency, and that this approach is fundamentally more suitable for rule enforcement than semantic RAG.
4. **Architectural insight**: A proposal that Euclid-MCP can serve as a shared reasoning substrate for both RAG-based assistants and agentic systems.

## Connections to Other Work
This work sits at the intersection of neuro-symbolic AI and tool-augmented agents. It relates conceptually to [[RLHF]] and agent frameworks (like ReAct or chain-of-thought prompting) by giving agents a more trustworthy external tool. It differs from pure retrieval systems by enforcing logical determinism rather than statistical relevance. The MCP (Model Context Protocol) framing aligns Euclid-MCP with emerging standards for LLM tool integration—positioning it as interoperable infrastructure rather than a bespoke coupling. The critique of semantic RAG echoes ongoing debates about when retrieval is sufficient versus when symbolic reasoning is necessary.

## Practical Applications
1. **IT security policy enforcement**: Verifying whether a user/system combination violates compliance rules (e.g., RBAC, data access policies).
2. **Regulatory compliance auditing**: Certifying that transactions, configurations, or workflows meet deterministic legal or operational rules.
3. **Incident triage & diagnosis**: Chaining logical rules to determine root causes or required remediation steps in complex systems.
4. **Knowledge-base query assistants**: Answering questions against a fixed rule set (e.g., insurance eligibility, tax implications) without hallucination.
5. **Enterprise chatbots for governance**: Allowing non-technical users to ask rule-based questions (e.g., "Can I access this resource?") with guaranteed correct answers.

## Product & Startup Ideas
1. **Compliance-as-a-Service (CaaS)**: A hosted Euclid-MCP service where enterprises upload their compliance rules as Prolog and expose a chat interface for auditors, employees, or regulators to query policy compliance without manual interpretation.
2. **Risk & Decision Engine for Financial Services**: Banks use Euclid-MCP to answer "Can we approve this loan?" or "Does this transaction breach our limits?" by compiling regulatory and risk rules into Prolog, backed by an LLM interface.
3. **Legal Document Review Automation**: Law firms use the system to deterministically extract and verify contractual obligations and liability rules from a rule engine, surfaced via conversational UI.
4. **Security Policy Simulator & Auditor**: Cybersecurity firms integrate Euclid-MCP to verify access-control policies, firewall rules, and role hierarchies—answering "Who can access X?" with logical certainty.
5. **Multi-Agent Reasoning Backbone**: A B2B API/SaaS for companies building agentic systems, offering Euclid-MCP as the deterministic reasoning layer for coalition of autonomous agents that must agree on facts and enforce shared rules.

## Technical Limitations
1. **Prolog scalability**: Logical inference can be computationally expensive or non-terminating on large rule sets or recursive predicates; the paper does not thoroughly benchmark against worst-case complexity.
2. **Knowledge representation bottleneck**: Converting complex, ambiguous real-world rules into Horn-clause logic is hard; the paper does not address how to author or maintain these rule sets at scale.
3. **LLM generation accuracy**: The system still relies on the LLM correctly translating a user query or domain problem into valid Euclid-IR; misgeneration upstream breaks the pipeline.
4. **Limited expressiveness**: Horn-clause logic cannot express disjunctive rules, negation-as-failure edge cases, or probabilistic reasoning; some domains may require richer logic.
5. **Debugging opacity**: While the paper mentions "proof traces," there is limited discussion of how to debug or explain why a logical query failed or why a rule did not match to an end user.

## Open Questions
1. How does Euclid-MCP perform on rule bases with thousands of clauses or deeply nested derivations? Where does performance degrade?
2. Can the system handle uncertainty or probabilistic rules (e.g., "Usually X implies Y")? Is there a principled way to integrate confidence scores from LLMs into logical inference?
3. How would one scale Euclid-IR authoring and maintenance in an enterprise setting? Is there a domain-specific language or UI that makes rule creation less error-prone?
4. Does the LLM's ability to generate valid Euclid-IR improve with prompting, few-shot examples, or fine-tuning? Is there an upper limit?
5. How does Euclid-MCP compare to other neuro-symbolic backends (e.g., neural-guided theorem provers, differentiable logic)?

## Key Takeaway
Coupling LLMs to a deterministic logical engine via standardized protocol eliminates hallucination in rule-based reasoning tasks.
