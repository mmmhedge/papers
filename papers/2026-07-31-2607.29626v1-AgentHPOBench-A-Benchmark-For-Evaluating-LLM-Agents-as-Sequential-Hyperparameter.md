# AgentHPOBench: A Benchmark For Evaluating LLM Agents as Sequential Hyperparameter Optimizers

**Authors:** Tianyu Huai, Tingshuo Fan, Xinchi Chen, Yining Zheng, Yuxin Wang et al.
**Published:** 2026-07-31 | **arXiv:** [2607.29626v1](http://arxiv.org/abs/2607.29626v1)

## Summary
This paper introduces AgentHPOBench, a benchmark that evaluates whether large language model (LLM) agents can act as autonomous scientists by iteratively optimizing machine learning hyperparameters based on experimental feedback. The benchmark tests 12 LLM agents on 30 real ML tasks, revealing that current agents can perform basic optimization but struggle with sustained iterative improvement and interpreting complex experimental logs.

## Theoretical Background
The work sits at the intersection of two evolving areas. First, LLMs — neural networks trained on vast text corpora that can follow instructions and generate code — are increasingly being deployed as autonomous agents (systems that act independently in environments, observe outcomes, and adapt behavior). Second, hyperparameter optimization (HPO) is the classical machine learning problem of automatically tuning configuration parameters (like learning rates or batch sizes) to improve model performance. Traditionally, HPO uses either random search, grid search, or Bayesian optimization — mathematical frameworks that propose new configurations without reasoning about why previous runs succeeded or failed. This paper asks whether LLMs can do better by interpreting experimental evidence (metrics, logs, error messages) to make informed decisions, similar to how a human researcher would.

## Core Contributions
1. **AgentHPOBench dataset**: 30 executable ML tasks spanning seven research domains (NLP, computer vision, graph learning, etc.), each with validated baselines and multi-step optimization trajectories. Tasks are real, reproducible, and executable — not synthetic or simulated.

2. **Sequential evaluation protocol**: Unlike static benchmarks that ask "can you generate this code?", this evaluates agents over multiple timesteps where each decision depends on observing prior results. This tests *iterative reasoning under uncertainty*.

3. **Comprehensive empirical comparison**: Systematic evaluation of 12 different LLM agents (including GPT-4, Claude, open-source models) plus classical HPO baselines under identical conditions, revealing specific failure modes.

4. **Diagnostic findings**: Quantifies three concrete limitations — agents struggle with sustained multi-step improvement (don't consistently beat baselines), fail to extract actionable insights from complex logs, and don't reliably converge toward reference performance reported in papers.

## Connections to Other Work
This extends the emerging field of [[LLM agents for scientific reasoning]] (e.g., systems like Galactica or domain-specific agents). It differs from prior benchmarks like [[HumanEval]] (static code generation) and paper reproduction benchmarks (final answer correctness) by focusing on *experimental reasoning in a loop*. The work implicitly critiques the gap between LLM capabilities at one-shot tasks versus sustained interactive problem-solving. It also relates to [[reinforcement-learning]] agent evaluation, but applies the sequential-decision framework to a deterministic (non-stochastic) domain where feedback is experimental metrics rather than rewards. The comparison to classical HPO methods (Bayesian optimization, multi-armed bandits) establishes a baseline for how much reasoning ability LLMs actually add.

## Practical Applications
1. **Automated ML pipeline tuning**: Data scientists could deploy an LLM agent to automatically tune deep learning experiments overnight, avoiding manual trial-and-error.

2. **Scientific research acceleration**: Chemistry, materials science, or biology labs could use agents to design experiments iteratively — e.g., proposing next reaction conditions based on prior results and scientific literature.

3. **Cloud ML service optimization**: Platforms like Google Cloud AI or AWS SageMaker could embed LLM agents to auto-tune model hyperparameters for users without ML expertise.

4. **Reproducibility auditing**: Automatically debug why a published paper's results don't reproduce locally by iteratively adjusting configurations based on logged discrepancies.

5. **Federated HPO**: Decentralized systems where multiple edge devices report metrics and an LLM agent running on a central server proposes next configurations based on aggregated feedback.

## Product & Startup Ideas
1. **HyperAgent**: A web app where users upload a dataset and ML training script, then an LLM agent auto-tunes hyperparameters and explains decisions in plain English — freemium model with premium support for complex logs and multi-objective optimization.

2. **ExperimentOS**: A platform combining experiment tracking (like Weights & Biases), automated HPO via LLM agents, and natural language querying of results ("which hyperparameters improved generalization?").

3. **Scientific Agent-as-a-Service**: API offering LLM agents trained specifically on domain corpora (chemistry, biology, materials science) to propose next experiments in wet-lab settings — agents access literature + prior runs via API.

4. **Benchmark-as-a-Service**: Host AgentHPOBench in the cloud, allow users to evaluate their custom LLM agents in a sandbox, and provide detailed reports on where agents fail — monetize via subscriptions.

5. **Thesis Writing Agent**: An LLM agent that iteratively tunes experiment parameters while drafting a thesis chapter, updating methodology sections in real-time as new results arrive — targets PhD students and researchers.

## Technical Limitations
1. **Simulation vs. reality gap**: Tasks are reproducible but relatively controlled. Real-world HPO often involves non-deterministic hardware, distributed systems, and long-tail failure modes (OOM, network timeouts) that agents may not experience.

2. **Log complexity ceiling**: The paper shows agents fail on "complex logs" but doesn't precisely define what complexity defeats them. In production, log volumes can be orders of magnitude larger.

3. **Compute cost not addressed**: Iterative HPO with LLM agents requires many forward passes (one per step). The paper doesn't compare wall-clock time or API costs vs. classical methods, which may be prohibitive for large experiments.

4. **No multi-objective or constrained optimization**: Benchmarks test single-metric optimization (e.g., validation accuracy). Real problems often involve trade-offs (latency vs. accuracy, power vs. performance) that the framework doesn't expose.

5. **Homogeneous task distribution**: Seven research categories cover different domains, but each category likely has similar structural properties (dataset sizes, training curves). Agents may overfit to these patterns and fail on truly novel task types.

6. **Limited agent diversity**: Tests 12 agents, but most are closed-source LLMs with similar training data and architectures. Behavior on truly novel or niche agent designs is unknown.

## Open Questions
1. **Why exactly do agents fail at sustained improvement?** Is it lack of exploration diversity, poor attribution (attributing results to wrong hyperparameters), or something else? Ablation studies on agent prompting strategies would help.

2. **Can agents learn from *other* projects' logs?** If an agent sees HPO trajectories from hundreds of prior ML projects in its training data or context, does it generalize better? Transfer learning for agents remains unclear.

3. **What is the minimum log complexity agents can handle?** Construct a progression of synthetic logs with increasing complexity (spurious correlations, noise, misleading metrics) and measure where each agent breaks.

4. **How do agents perform on truly novel domains not in pretraining?** E.g., hyperparameter optimization for exotic hardware (TPUs, neuromorphic chips) or niche scientific domains.

5. **Can multi-agent collaboration improve HPO?** What if two agents debate next hyperparameter choices or one agent reviews another's logs? This connects to [[multi-agent-systems]] and could unlock emergent reasoning.

6. **How does in-context learning scale?** As the number of prior run results grows, do agents degrade due to context length limits, or can they learn to compress/summarize efficiently?

## Key Takeaway
LLM agents can optimize ML hyperparameters iteratively but lack sustained reasoning and struggle with complex experimental logs compared to their promise as autonomous scientists.
