# AIMS: An Agentic AI Framework for Sim-to-Real Multi-Modal ISAC

**Authors:** Yijie Bian, Kai Zhang, Wei Guo, Zixin Wang, Shenghui Song et al.
**Published:** 2026-09-30 | **arXiv:** [2609.39964v1](http://arxiv.org/abs/2609.39964v1)

## Summary

This paper introduces AIMS, a framework that uses multiple AI agents to automatically configure and adapt machine learning models for integrated sensing and communication (ISAC) systems across sim-to-real deployment scenarios. The key problem: training ISAC models requires real-world data, which is expensive and scarce, so researchers use simulations—but existing simulations don't transfer well to real deployments because of mismatches between simulated scenes, sensor readings, and wireless characteristics. AIMS solves this by having agents automatically generate deployment-specific synthetic data and configure learning systems through natural-language requests.

## Theoretical Background

**Integrated Sensing and Communication (ISAC)** combines radar/sensing systems with wireless communication in a single unified framework—a trend in modern 5G/6G networks. The challenge addressed here is the **sim-to-real gap**: simulated environments rarely capture all the real-world complexity, so models trained purely on synthetic data perform poorly on actual sensors and networks.

Prior work relies on either manual annotation of real data (expensive) or crude domain adaptation techniques (unreliable). AIMS builds on two foundational ideas:

1. **Multi-agent coordination**: agents (autonomous decision-making systems) can divide labor—one agent handles scene generation, another handles learning configuration.
2. **Structured knowledge and planning**: using domain rules (e.g., "sensing modality X requires wireless configuration Y") to guide agent decisions and detect conflicts.

The paper also leverages **mixture-of-experts (MoE)** learning—a technique where multiple specialized neural networks handle different data modalities and can be selectively activated.

## Core Contributions

1. **Two-agent orchestration system**: A scene construction agent generates geographically grounded, synchronized synthetic sensing + wireless data from shared physical states; a scene understanding agent configures task-relevant modalities and learning mixtures.

2. **Dependency-aware planning**: Structured domain knowledge encodes relationships between scene properties, sensing configurations, and wireless parameters, enabling agents to avoid invalid configurations.

3. **Feedback-driven revision**: Validation evidence from synthetic data quality checks feeds back to agents, triggering replanning when mismatches are detected.

4. **Natural-language interface**: Users specify deployment tasks, conditions, and real-data budgets in plain language; the framework translates this into executable sim-to-real pipelines.

5. **Empirical validation**: Demonstrated on real DeepSense 6G dataset for vehicle detection and beam prediction, outperforming baseline simulation and fusion approaches.

## Connections to Other Work

This work sits at the intersection of:

- **[[Multi-agent systems]]**: Using agent-based planning and coordination (similar to cooperative multi-agent reinforcement learning but in a supervised learning context).
- **Domain adaptation and transfer learning**: Addresses the classical sim-to-real problem, but uses agentic orchestration rather than adversarial or constraint-based methods.
- **Neuro-symbolic AI**: Combines learned models (neural networks) with structured symbolic domain knowledge (dependency rules).
- **Large-language models for planning**: While not explicitly stated, the natural-language interface likely leverages LLMs for task interpretation (related to [[agents]] that use language as an interface).

Relates to broader challenges in **few-shot learning** and **zero-shot generalization** across modalities.

## Practical Applications

1. **5G/6G network deployment**: Telecom operators can quickly configure ISAC models for new geographic regions or frequency bands without collecting months of labeled data.

2. **Autonomous vehicle perception**: Deploying vehicle detection and localization in new cities or weather conditions using minimal real-world calibration.

3. **Radar-communication system optimization**: Defense or automotive radar systems that need to adapt to new hardware or environmental conditions.

4. **Smart city sensing infrastructure**: Cities can spin up new sensor networks (cameras + communication links) and auto-tune models for traffic, emergency response, or environmental monitoring.

5. **Satellite or aerial sensing**: Remote sensing systems deployed to new regions can rapidly adapt models using synthetic scenes generated from geographic data.

## Product & Startup Ideas

1. **ISAC Deployment-as-a-Service platform**: A SaaS offering where telecom operators or enterprises describe their sensing + communication needs in plain language, and the system automatically generates validated sim-to-real models and deploys them to edge devices.

2. **Synthetic data generation toolkit for wireless networks**: A tool that automatically creates realistic 5G/6G simulation environments (scenes, sensor traces, channel models) from natural-language specifications, sold to chip makers and network equipment vendors.

3. **Multi-modal sensor fusion optimizer**: A consulting/software product that helps enterprises (autonomous vehicles, robotics) rapidly adapt multi-sensor systems to new deployment sites by orchestrating synthetic data generation and few-shot model adaptation.

4. **Agentic network optimization agent**: A continuously running system for telecom operators that monitors deployed ISAC models, detects performance drift, and autonomously revises sim-to-real configurations based on validation feedback without human intervention.

5. **AI for regulatory compliance in wireless systems**: A product that helps manufacturers ensure ISAC systems meet regional spectrum regulations and safety standards by automatically generating test scenarios and validating models against domain rules before real-world deployment.

## Technical Limitations

1. **Validation bottleneck**: The framework still requires *some* real-world data or validation evidence to close the sim-to-real gap; it cannot eliminate the need for validation entirely, only reduce it.

2. **Domain knowledge brittleness**: The structured knowledge (dependency rules) must be hand-engineered for each new domain or wireless standard; generalization across very different ISAC scenarios is unclear.

3. **Computational cost of agent orchestration**: Running agent planning and replanning for each deployment request adds latency; scalability to rapid, dynamic deployments is not discussed.

4. **Limited to configured modalities**: The framework assumes sensing and wireless modalities are predefined; extending to entirely novel sensor types or communication protocols requires manual domain knowledge updates.

5. **Evaluation scope**: Experiments focus on vehicle detection and beam prediction; it's unclear how well AIMS generalizes to other ISAC tasks (e.g., localization, target tracking, or multi-user scenarios).

6. **Scene realism**: Synthetic scenes are grounded in real geography but may not capture edge-case phenomena (weather extremes, hardware anomalies) that cause real-world failures.

## Open Questions

1. **How much real-world validation data is actually necessary?** What is the diminishing return curve for few-shot adaptation? Can the framework predict when it has enough synthetic data without ground truth?

2. **Can agents learn and refine domain knowledge over time** rather than relying on hand-crafted rules? Could the framework improve as it processes more deployments?

3. **How does performance degrade with out-of-distribution deployments?** E.g., if a model trained for urban environments is deployed in rural or maritime settings with no domain knowledge updates.

4. **Can the agent framework handle adversarial or dynamic environments**, where deployment conditions change over time? How would feedback-driven revision handle non-stationary mismatches?

5. **What is the interpretability and explainability of agent decisions?** When a deployment fails, can users understand why the agent made a particular sim-to-real configuration choice?

6. **How do agentic configurations compare to end-to-end learned or meta-learning approaches** (e.g., learning to learn across domains)? Is explicit agent planning necessary, or can implicit adaptation suffice?

## Key Takeaway

Agents automatically configure synthetic data generation and model training for wireless sensing systems, reducing real-world data needs and adapting to new deployments via natural language.
