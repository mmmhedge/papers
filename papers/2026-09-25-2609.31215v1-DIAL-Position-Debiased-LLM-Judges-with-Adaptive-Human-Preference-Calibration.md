# DIAL: Position-Debiased LLM Judges with Adaptive Human Preference Calibration

**Authors:** Zesheng Cai, Yingqi Fan, Sichang Chen, Jin-Hong Du
**Published:** 2026-09-25 | **arXiv:** [2609.31215v1](http://arxiv.org/abs/2609.31215v1)

## Summary
This paper tackles a critical problem in using LLMs as judges: they are biased by response order (position bias) and often disagree with human preferences even when position effects are removed. DIAL is a framework that combines many LLM comparisons with fewer human comparisons to detect and remove position bias, learn underlying LLM preferences, and then calibrate those preferences toward human judgments. The work matters because LLM-based evaluation is becoming standard practice, but if judges are unreliable or misaligned with human values, downstream applications built on their judgments will fail.

## Theoretical Background
LLM evaluation typically works by asking a model to compare two responses and rank them. Prior work noted that these rankings can depend on which response appears first or second (position bias), undermining reliability. The paper builds on classical causal inference and measurement theory: the authors model each LLM judge as having a true latent preference plus position-specific noise, similar to how experimental designs account for confounding factors. They also draw on recent work in preference learning and human alignment — the idea that model behavior should match human values, not just optimize for some proxy metric. The key insight is that with enough LLM comparisons (which are cheap) and strategic use of human annotations (which are expensive), you can statistically disentangle the three components: true judge preference, position effect, and gap to human preference.

## Core Contributions
1. **Theoretical identification results**: The paper proves that under reasonable assumptions, you can uniquely recover the latent LLM preferences, position effects, and human calibration targets from mixed LLM and human comparison data — i.e., the problem is well-posed mathematically.
2. **Adaptive calibration algorithm**: DIAL proposes a practical algorithm that learns from LLM judgments while adaptively incorporating human feedback, trading off between trusting LLM anchors and correcting toward human evidence.
3. **Uncertainty quantification**: The framework provides fixed-weight confidence intervals for calibrated preferences, enabling principled downstream use.
4. **Large-scale empirical study**: The authors collect 410K+ judgments from 21 different LLM judges in both display orders, creating a dataset and benchmarking position bias and human alignment across models.

## Connections to Other Work
This work relates to [[RLHF]] (Reinforcement Learning from Human Feedback) and broader [[alignment]] literature, which aim to steer LLMs toward human preferences. It also connects to the "evaluation crisis" — the recognition that standard benchmarks may not capture true model quality or safety. The position bias issue parallels classical experimental design concerns (e.g., order effects in surveys). From a methodological angle, DIAL uses ideas from causal inference and semi-supervised learning: leverage abundant unlabeled (or cheaply-labeled) data to improve limited labeled data. The multi-judge heterogeneity aspect relates to ensemble and mixture-of-experts approaches.

## Practical Applications
1. **Scalable evaluation pipelines**: Use LLM judges to rank model outputs (e.g., comparing chatbot responses) while automatically correcting for known position biases and human misalignment.
2. **Preference dataset quality control**: When building datasets of human-preferred responses, use DIAL to detect and flag responses where judge disagreement or position bias is high.
3. **Model fine-tuning targets**: Instead of training directly on raw LLM rankings, use DIAL's calibrated human-aligned preferences as supervision, improving downstream model quality.
4. **Audit and monitoring**: Periodically run DIAL on production LLM judges to detect drift in their behavior or emerging biases.
5. **Cost reduction in annotation**: Reduce human annotation budgets by using DIAL to learn from a small number of human comparisons plus abundant LLM comparisons.

## Product & Startup Ideas
1. **LLM Judge-as-a-Service platform**: Offer a managed evaluation service that automatically debriases LLM judges and aligns them with client-specific human preferences, charging per evaluation.
2. **Evaluation analytics dashboard**: Build a tool that helps AI teams monitor position bias and human alignment in their evaluation pipelines, flagging anomalies and suggesting recalibration.
3. **Preference learning consultancy**: Provide services to help companies build high-quality preference datasets using DIAL, reducing annotation costs while improving label quality.
4. **Automated ranking & reranking**: Develop a library/plugin that integrates DIAL into RAG (retrieval-augmented generation) or ranking pipelines, ensuring retrieved results match human preferences.
5. **AI safety audit service**: Create a compliance tool for enterprises to audit whether their internal LLM judges exhibit systematic bias or misalignment, with remediation recommendations.

## Technical Limitations
1. **Assumption of shared structure**: DIAL assumes that LLM judges, despite their differences, share some underlying preference structure that can be learned and calibrated. This may break for very heterogeneous judges or domain-specific tasks.
2. **Limited human data**: While the method is designed for sparse human feedback, performance will degrade if human labels are too few or unrepresentative.
3. **Linear/low-rank approximation**: The theoretical framework likely assumes some form of additive or linear structure in the bias and calibration; complex, context-dependent position effects may not be captured.
4. **Generalization across tasks**: It is unclear whether position biases and human alignment patterns learned on one task generalize to new tasks or domains.
5. **Computational cost of estimation**: The algorithm requires fitting models to large LLM comparison datasets; scalability to billions of judgments is not discussed.
6. **No ground truth in practice**: The paper cannot observe "true" human preferences — only finite samples. The calibration target itself is noisy.

## Open Questions
1. **Does position bias vary by response domain?** For instance, is the position effect different when comparing code outputs vs. creative writing? How should DIAL adapt?
2. **How does human annotator bias interact with LLM judge bias?** If human annotators also have systematic preferences, does DIAL still converge to a meaningful target?
3. **Can position debiasing transfer across LLM architectures?** If you learn position effects on GPT-4, do they apply to Claude or Llama? Is there shared bias structure?
4. **What is the minimal human sample size for reliable calibration?** Can you give guidance (e.g., "50 comparisons per task") or is it task-dependent?
5. **How does DIAL perform on adversarial or out-of-distribution responses?** Can judges be reliably calibrated for rare or novel outputs?
6. **Real-time vs. batch calibration**: Should DIAL recalibrate continuously as new human feedback arrives, and if so, how often?

## Key Takeaway
LLM judges are biased by response order and misaligned with humans; DIAL removes position bias and recalibrates toward human preferences using few human labels plus many LLM comparisons.
