# Mem++: Non-Destructive Memory for Long-Term Organizational LLM Agents

**Authors:** Ahmad Yehia, Aly O. Abdelkareem, Islam Ahmed, Hesham Omran, Khaled Alashmouny et al.
**Published:** 2026-10-01 | **arXiv:** [2610.02002v1](http://arxiv.org/abs/2610.02002v1)

## Summary
This paper introduces Mem++, a memory system for LLM-based organizational agents that preserves full document history rather than compressing information at write time. The key insight is that organizational decisions evolve over time—newer documents revise older ones—so the system must track which version was "current" when a question is asked. Mem++ outperforms existing memory baselines by 8-13 percentage points on organizational benchmarks because it keeps all versions and lets the answering model choose the right historical context.

## Theoretical Background
LLM agents need external memory to handle tasks requiring knowledge of past events, decisions, or documents—they can't store unlimited context in their input window. Existing memory systems typically use write-time distillation: when a new document arrives, they extract facts, create graph edges, or summarize it immediately, discarding the raw text. This approach works well when facts are stable, but organizational records often contradict each other (e.g., "we decided X" is later revised by "we actually decided Y"). The paper builds on retrieval-augmented generation (RAG) — a pattern where an LLM answers by first retrieving relevant documents—but adds temporal awareness. It also draws on temporal knowledge graph literature and the observation that human reasoning over versioned documents requires knowing *when* a statement was true, not just what statements exist.

## Core Contributions
1. **Non-destructive memory design**: Stores complete documents with metadata (date, author) instead of extracting and summarizing. No generative model is called at write time, reducing cost and latency.
2. **Temporal filtering at read time**: Retrieves only documents dated up to the time of the question, ensuring historically accurate context.
3. **Hybrid ranking strategy**: Combines lexical (keyword) and semantic (embedding-based) ranking to retrieve both literally relevant and conceptually related documents.
4. **Empirical validation**: Demonstrates 8.0–13.1 point improvements over strong baselines on OrgMemBench, and competitive performance on LoCoMo and LongMemEval-S benchmarks.

## Connections to Other Work
Mem++ contrasts with [[Retrieval-Augmented Generation (RAG)]] systems that don't account for temporal validity. It relates to work on [[temporal knowledge graphs]] and versioning in enterprise knowledge systems, but applies these ideas to the LLM-agent setting. The paper also engages with broader agent memory research (e.g., memory hierarchies for long-context agents) and temporal reasoning in NLP. Unlike [[graph-based memory systems]] that commit to a structure early, Mem++ defers interpretation to the answering stage, aligning with lazy-evaluation paradigms in software systems.

## Practical Applications
1. **Enterprise decision tracking**: Organizations like law firms, consulting companies, or government agencies regularly revise policies and decisions. Mem++ can track which version was active on a given date, answering queries like "What was our approved vendor list in Q2 2024?"
2. **Legal/compliance audits**: Regulators often need to know what a company's position was at a specific time. Preserving full document history with timestamps provides an immutable audit trail.
3. **Product requirement evolution**: Engineering teams maintain living documents of feature specs. Mem++ can answer "What was the original requirement before we pivoted?" without losing historical context.
4. **Medical records and patient history**: Healthcare providers need to distinguish between current and past diagnoses/treatments. Temporal awareness prevents conflating superseded information with active treatment plans.
5. **News/research archival**: Media organizations and research teams can query versioned articles and reports with awareness of publication dates and revisions.

## Product & Startup Ideas
1. **Enterprise Memory OS**: A SaaS layer on top of organizational document systems (Confluence, SharePoint, Notion) that adds temporal LLM-aware querying—"what was our decision on X as of date Y?"
2. **Compliance & Audit Assistant**: A tool for regulated industries that ingests versioned policy documents and generates time-stamped audit reports, flagging when decisions changed and why.
3. **Legal Discovery Platform**: Automate e-discovery for litigation by preserving document versions and enabling lawyers to ask historical questions ("who knew what, and when?") with precise temporal grounding.
4. **AI-Powered Knowledge Archaeology**: A search engine for internal wikis/documentation that understands that older docs may be superseded, helping teams avoid implementing deprecated decisions.
5. **Temporal Chatbot for Product Teams**: A Slack/Teams bot that answers engineering and product questions with awareness of when specifications changed, reducing "but we already decided that" debates.

## Technical Limitations
1. **Scalability concerns**: Storing complete documents verbatim rather than summaries increases storage and retrieval latency. The paper doesn't detail performance with millions of documents or terabytes of text.
2. **Read-time cost trade-off**: Deferring work from write time to read time means every query must retrieve and rank many documents. This is slower than pre-computed summaries, especially under high query volume.
3. **Ranking algorithm dependency**: The hybrid lexical-semantic ranking is heuristic-driven. It may fail to retrieve relevant historical context if keyword overlap is low and semantic embeddings are misaligned (e.g., domain-specific jargon).
4. **Author/date reliability**: The system assumes accurate metadata. In real organizations, document timestamps and authorship are often unreliable or missing.
5. **Limited to English/text**: Evaluation focuses on textual documents. Performance on images, tables, or other media is unstudied.
6. **Evaluation scope**: OrgMemBench may not capture all real organizational complexity (e.g., implicit decisions, oral communications, decisions spread across many documents).

## Open Questions
1. How does Mem++ scale to millions of documents across years of organizational history? What are the latency/throughput trade-offs?
2. Can the system handle structured document revisions (e.g., "version 2.3 of policy X") without explicit date metadata?
3. How does performance degrade if documents lack reliable timestamps or authorship information?
4. Does the system work across multiple languages or domain-specific technical documents (e.g., code, medical records)?
5. Can we learn optimal ranking weights (lexical vs. semantic) from task performance rather than using fixed heuristics?
6. What happens if an organization has contradictory or circular decisions (A revised B, but later B was reinstated)? Does the LLM correctly reason through these?
7. How do results change if we use different embedding models or retrieval strategies (e.g., learned sparse retrieval)?

## Key Takeaway
Keeping full document history instead of summarizing at write time lets LLM agents accurately answer questions about what was true when.
