# AutoCompact: Learning When to Compact Context in Long-Horizon Coding Agents

**Authors:** Xuan Zhang, Longtao Zheng, Cunxiao Du, Bo An, Xin Dong
**Published:** 2026-10-01 | **arXiv:** [2610.02163v1](http://arxiv.org/abs/2610.02163v1)

## Summary
This paper presents AutoCompact, a system that teaches coding agents to automatically decide when and how to compress their working context during long software engineering tasks. The agent learns this compaction policy alongside its main coding policy through a combination of supervised learning from corrected trajectories and reinforcement learning, achieving 9.2% absolute improvement on real repository-level coding benchmarks.

## Theoretical Background
The work builds on two foundational ideas: (1) **long-horizon task agents** — systems that must maintain and reason over extended sequences of actions to solve complex problems, and (2) **context management in large language models (LLMs)** — the challenge that LLMs have fixed context windows, so managing what information to keep becomes critical as tasks progress. Prior work on coding agents (like SWE-agent) solves software tasks by inspecting repositories, searching for relevant code, making edits, and running tests. The paper recognizes that naive context retention creates two problems: overflow (exceeding token limits) and staleness (old exploration steps that are no longer relevant). AutoCompact extends this by treating compaction decisions as a learnable policy component, similar to how reinforcement learning agents learn action policies.

## Core Contributions
1. **Compaction as a learned policy**: Rather than using fixed heuristics for when/what to compact, AutoCompact trains the agent to make these decisions as part of its overall behavior policy.
2. **Trajectory correction pipeline**: A novel data collection method where a judge validates compaction decisions and summaries; flawed compactions are corrected before execution, ensuring each trajectory learns from valid context continuations.
3. **Joint optimization**: Combines supervised fine-tuning (on corrected trajectories) with RL optimization (using task-success rewards) to simultaneously improve coding performance and compaction quality.
4. **Empirical validation across context budgets**: Demonstrates robustness across different context window sizes (16K, 256K) with graceful fallback behavior.

## Connections to Other Work
This relates to [[RLHF]] and [[Reinforcement Learning from Human Feedback]] in using human-like corrections during training, though here the "judge" is automated. It extends [[SWE-agent]] (the base agent for repository-level coding) by adding learned context management. The work also connects to broader themes in [[long-horizon reasoning]] with LLMs and [[prompt compression]] / [[context distillation]] techniques, but differs by making compaction an integral learned skill rather than a post-hoc optimization. The joint supervised+RL training approach mirrors curriculum-learning and multi-objective optimization patterns in agent training.

## Practical Applications
1. **Enterprise software maintenance**: Automatically triaging large codebases for bug fixes or refactoring — agents can now work on multi-file, multi-hour tasks without context exhaustion.
2. **Continuous integration pipelines**: Embedding coding agents into CI/CD to handle automated code reviews, test debugging, or incremental feature implementation.
3. **Documentation and onboarding**: New developers exploring unfamiliar repos; the agent learns to summarize explored sections so human developers don't re-read stale notes.
4. **GitHub/GitLab automation**: Autonomous pull request resolution — agents handle long chains of edits, tests, and revisions without manual intervention.

## Product & Startup Ideas
1. **CodeAssistant Pro**: A VS Code/IDE extension that runs AutoCompact-style agents in the background for automated refactoring, bug fixing, and test generation on large monorepos; users set task descriptions and let the agent work.
2. **Repository Analyzer & Fixer SaaS**: A cloud service that ingests a GitHub repo URL and autonomously fixes classes of bugs (e.g., deprecated API usage, security issues, test failures) by dispatching coding agents that learn repository-specific compaction strategies.
3. **Context-Aware Code Copilot**: A smarter code completion tool that actively manages context as users explore files, compacting old explorations to free space for current work — learn per-repository context preferences.
4. **Autonomous DevOps Agent**: Integrates with Jira/linear; agents automatically pick up tickets, explore code, write fixes, run tests, and open PRs — learns when to summarize exploration history to stay within token budgets.
5. **Internal Tool for Large Orgs**: White-label agent platform for tech teams to run custom coding agents on internal monorepos, with dashboard showing when/why agents compact context and what they decide to preserve.

## Technical Limitations
1. **Judge dependency**: The quality of compaction improvements is upper-bounded by the judge's accuracy; systematic judge errors propagate through training data.
2. **Context window assumptions**: The approach assumes a fixed, known context window; it does not handle dynamic or adversarially-sized contexts.
3. **Stalenesss detection**: No explicit mechanism to *detect* which information is stale — the agent must learn this implicitly from trial-and-error, which could be sample-inefficient.
4. **Compaction summarization quality**: Relies on the base LLM to produce faithful, concise summaries; hallucinations or lossy compression during compaction could degrade downstream actions.
5. **Generalization across tasks**: Trained on SWE-bench; unclear how well learned compaction strategies transfer to tasks outside software engineering.
6. **Offline judge scalability**: Running a judge on all trajectories during data collection is computationally expensive and doesn't scale to extremely large task distributions.

## Open Questions
1. **How much information is actually lost during compaction?** A comparison of task success with/without compaction steps would isolate the cost of summarization.
2. **Can agents learn to *predict* when compaction is needed?** Current work learns to compact; does the agent develop an internal "context pressure" signal, or does it reactively respond to overflow?
3. **Does learned compaction strategy transfer across repositories or task types?** Fine-grained ablations on domain shift would clarify generalization.
4. **What if compaction decisions are collaborative (agent + human)?** A human-in-the-loop variant where developers can override or suggest compactions might improve long-term task success.
5. **Can we use contrastive learning on compaction summaries?** Rather than supervised correction, could we train the agent to distinguish *good* vs. *bad* summaries without explicit judgment?
6. **How does compaction interact with retrieval-augmented generation?** If agents use external search/indexing instead of in-context memory, does compaction become unnecessary?

## Key Takeaway
Coding agents learn to automatically compress their working memory during long tasks, improving task success by 9% while staying within token limits.
