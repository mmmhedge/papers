# Training Parallel Speculative Draft Models by Directly Minimizing Expected Decoding Rounds

**Authors:** Yunxiao Zhao, Changxiao Cai
**Published:** 2026-10-07 | **arXiv:** [2610.10411v1](http://arxiv.org/abs/2610.10411v1)

## Summary
This paper develops a new training method for "draft models" that speed up large language model inference through speculative decoding. The key innovation is an objective called Expected Decoding Rounds (EDR) that directly optimizes for how many forward passes the system needs, rather than using approximate proxies. The method improves inference speed across math, code, and chat tasks.

## Theoretical Background
Speculative decoding works by having a fast, small model (the drafter) propose multiple tokens in parallel, which a large, accurate model then verifies together. Prior work trained drafters using block-local objectives — measuring rejection only within a single proposed block — but these ignore how acceptance in one block affects where the next block starts. This paper frames the problem as a Markov reward process, a mathematical model where future states depend only on the current state and chosen action. This enables principled optimization of the global decoding pipeline rather than local components in isolation.

## Core Contributions
1. **EDR objective formulation**: A training loss that weights rejection costs by state occupancies (the probability of being in each state during decoding) and directly equals expected decoding rounds — not an approximation.
2. **Temporal-difference gradient**: An exact, unbiased gradient for optimizing EDR via rollouts from the target model, enabling practical finetuning.
3. **Offline evaluator**: A method to compare draft models on the same target rollouts without re-running full speculative decoding, reducing evaluation cost.
4. **Empirical validation**: Improvements to two state-of-the-art drafters (DSpark, DFly) across nine benchmarks, showing consistent gains in accepted token length.

## Connections to Other Work
This work relates to [[reinforcement-learning]] through its Markov reward process formulation and temporal-difference methods. It builds on speculative decoding (Leviathan et al.) and semi-autoregressive generation, extending them with theoretically grounded training. The approach contrasts with prior surrogate losses (e.g., block-level rejection prediction) that decouple the optimization from actual decoding efficiency. It connects to broader LLM inference acceleration research and [[optimization]] of neural network inference pipelines.

## Practical Applications
- **Real-time LLM inference**: Speed up API servers and on-device inference for latency-critical applications (chatbots, search, coding assistants).
- **Cost reduction**: Lower GPU utilization per inference request, reducing operational expenses for inference-heavy services.
- **Mobile/edge deployment**: Faster inference on resource-constrained devices with smaller target models and efficient drafters.
- **Batch processing**: Reduced time-to-first-token and total throughput time for document processing, content moderation, and log analysis.

## Product & Startup Ideas
1. **LLM inference optimization SaaS**: Package EDR-trained drafters as a drop-in inference engine for existing LLM APIs (OpenAI, Anthropic alternatives).
2. **Model distillation marketplace**: Platform to automatically train and sell optimized draft models for popular base LLMs; customers license drafters for their inference workload.
3. **On-device LLM acceleration**: SDK for mobile/edge apps that bundles a lightweight target model + EDR-optimized drafter, marketed to phone manufacturers and embedded AI startups.
4. **Developer tool for inference benchmarking**: Web dashboard that evaluates draft models using the offline EDR evaluator without running full decoding — helps engineers pick the right drafter for their latency budget.
5. **Speculative decoding infrastructure for enterprises**: Managed service that deploys custom LLMs with auto-trained drafters; charges per inference round saved.

## Technical Limitations
- **Drafter architecture constraints**: EDR assumes drafters can produce variable-length blocks and work with the same vocabulary/embedding space as the target model; architecture mismatches aren't addressed.
- **Target model dependence**: Training is specific to a target model; changing target models requires retraining. Cross-target generalization is unexplored.
- **Computational cost**: EDR training requires rollouts from the target model, which is expensive; the paper doesn't analyze how many rollouts are needed for convergence.
- **Distribution shift**: Drafters trained on one data distribution may not generalize to new input domains without retraining.
- **Semi-autoregressive assumption**: Method assumes drafters propose blocks; fully autoregressive or non-parallel drafting strategies are out of scope.

## Open Questions
- How does EDR performance scale to even larger target models (e.g., 405B parameters)?
- Can drafters trained via EDR on one target model transfer to similar models without full retraining (e.g., across model families)?
- What is the sample complexity of EDR training — how many target rollouts are needed for convergence, and how does it compare to surrogate losses?
- Does EDR extend to multi-token verification (accepting variable numbers of tokens per round) or adaptive block sizing?
- How does EDR handle very long sequences where state-occupancy calculations become computationally expensive?

## Key Takeaway
EDR objective directly optimizes draft model training for actual inference speed, eliminating hyperparameters and improving speed across code, math, and chat tasks.
