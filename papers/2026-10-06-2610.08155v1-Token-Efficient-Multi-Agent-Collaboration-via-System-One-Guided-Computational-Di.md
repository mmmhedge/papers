# Token-Efficient Multi-Agent Collaboration via System One-Guided Computational Division of Labor

**Authors:** Zihan Zhou, Xinzhe Hu, Hanxu Yang, Liangjian Wen, Zhao Kang
**Published:** 2026-10-06 | **arXiv:** [2610.08155v1](http://arxiv.org/abs/2610.08155v1)

## Summary
This paper proposes S1-MAS, a framework that makes multi-agent LLM systems cheaper and faster by splitting work: lightweight "System One" models handle coordination decisions (task selection, routing, termination), while expensive LLMs focus on reasoning. The approach cuts token costs by 45–97% and latency by 38–93% compared to existing systems, without sacrificing accuracy—making LLM-based agent collaboration more practical for real applications.

## Theoretical Background
The work builds on two conceptual pillars:

1. **Multi-agent systems (MAS)** — systems where multiple specialized agents collaborate to solve complex problems. Recent LLM-based MAS frameworks (like AgentVerse, DyLAN, SelfOrg) assign reasoning and coordination jointly to the same powerful model, which is expensive.

2. **System One vs. System Two cognition** — a cognitive psychology distinction (Kahneman). System One handles fast, bounded decisions; System Two handles slow, deliberate reasoning. The paper applies this metaphor: lightweight, fast models (System One) for coordination; powerful LLMs (System Two) for open-ended reasoning.

The key insight is that coordination decisions—which tasks to run next, which agent plays which role, when to stop—are fundamentally bounded problems with clear constraints. Reasoning about complex questions is not. Decoupling them saves tokens without quality loss.

## Core Contributions
- **Decoupled architecture**: separates lightweight coordination logic (System One controller + compact reader) from expensive reasoning (LLM workers), rather than entrusting both to one model.
- **Decision-evidence loop**: a compact reader retrieves condition-relevant evidence from sources to guide the lightweight controller's coordination decisions, enabling adaptive collaboration without task-specific training.
- **Empirical validation**: demonstrates superior or comparable accuracy across seven diverse benchmarks while achieving 45–97% token reduction and 38–93% latency reduction versus three strong baselines (AgentVerse, DyLAN, SelfOrg).
- **Practical scalability**: proves that structured, bounded coordination can be delegated to smaller models without degrading multi-agent reasoning performance.

## Connections to Other Work
This paper critiques and extends **existing LLM-based MAS frameworks** ([[AgentVerse]], [[DyLAN]], [[SelfOrg]]) by identifying their coupling of reasoning and coordination as a scalability bottleneck. It relates conceptually to:

- **Cognitive architectures** that separate fast and slow processing (inspired by dual-process theory).
- **Retrieval-augmented generation (RAG)** — the compact reader is akin to a lightweight retrieval component.
- **Hierarchical [[reinforcement-learning]]** — the controller-worker structure echoes hierarchical RL, but applied to LLM coordination rather than learned policies.
- **Token efficiency** and **[[optimization]]** in LLM inference — part of a broader push to make large models cheaper and faster.

## Practical Applications
- **Enterprise knowledge systems**: Large organizations need to route queries to specialized agents (legal, finance, HR); S1-MAS reduces cost per query while maintaining quality.
- **Real-time customer support**: Automated systems that triage customer issues, select specialist agents, and retrieve relevant docs can operate at lower cost and latency.
- **Scientific research assistants**: Multi-agent systems that gather literature, synthesize findings, and propose hypotheses; S1-MAS makes continuous iteration affordable.
- **Autonomous web services**: Agents that search, extract, aggregate, and reason about web data; token efficiency is critical for high-volume deployments.
- **Chatbots with external tools**: Systems that decide which tools to call, fetch data, and synthesize answers; lightweight coordination reduces per-user cost.

## Product & Startup Ideas
1. **S1-MAS-as-a-Service**: A managed API endpoint where users define agent roles and evidence sources; the platform handles lightweight coordination + LLM workers, billing per reasoning token only. Target: enterprises wanting multi-agent capabilities without cost overruns.

2. **Smart Document Router**: A B2B SaaS that routes enterprise documents (contracts, support tickets, expenses) to specialized AI agents for processing, using lightweight coordination and RAG. Sell to law firms, insurance, and finance.

3. **Lightweight Agent Orchestration Middleware**: Open-source or commercial toolkit that lets developers plug their own LLM workers into an S1-MAS-style controller. Addressable market: AI/ML startups building agent platforms.

4. **Cost-Aware Multi-Agent Analytics Dashboard**: A monitoring platform that shows token spend, latency, and accuracy per agent and per task type, with recommendations to push more decisions to System One. Sold to enterprises running large agent deployments.

5. **Specialized Query Engine for Knowledge Bases**: A product that uses S1-MAS to route company-internal knowledge queries (Slack, docs, databases) to the right agent without always invoking GPT-4o. Target: remote-first and distributed teams.

## Technical Limitations
- **Assumption of bounded coordination**: The framework assumes coordination decisions can be cleanly separated and learned by lightweight models. If task dependencies or role assignments are genuinely complex and interdependent, this separation may fail.
- **Evidence source availability**: The compact reader must access pre-defined, authorized sources. In domains with unstructured or sparse evidence, retrieval quality may degrade.
- **Lack of adaptive re-weighting**: The paper doesn't discuss how to dynamically tune the balance between lightweight and expensive reasoning if problem domains shift.
- **Evaluation on benchmarks only**: All results are on academic benchmarks; real-world multi-agent systems may have longer task chains, messier evidence, and emergent failure modes not captured by these tasks.
- **Training overhead not detailed**: The paper mentions no task-specific training, but doesn't discuss how the System One models and reader are initially trained—there may be hidden upfront costs.
- **Scalability to many agents**: It's unclear how the controller and reader scale as the number of specialized agents or evidence sources grows into hundreds or thousands.

## Open Questions
- **How sensitive is performance to System One model quality?** What is the minimum capability needed in the lightweight controller?
- **Can System One models learn to defer gracefully?** When should the lightweight controller escalate a decision to an LLM rather than make a bounded guess?
- **How does this scale with agent heterogeneity?** What happens if agent roles have overlapping competencies or require negotiation rather than assignment?
- **Is evidence retrieval the bottleneck?** Under what task and source conditions does RAG fail, and can that be mitigated?
- **Transfer across domains**: Do System One models trained on one set of tasks generalize to new domains, or is retraining necessary?
- **Failure mode analysis**: What kinds of coordination errors does the system make when the controller is wrong? Can these be detected and corrected?

## Key Takeaway
Splitting cheap lightweight models for routing from expensive LLMs for reasoning cuts multi-agent system costs 45–97% without losing accuracy.
