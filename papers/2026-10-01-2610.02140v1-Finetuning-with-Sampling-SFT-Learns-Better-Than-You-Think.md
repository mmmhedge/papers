# Finetuning with Sampling: SFT Learns Better Than You Think

**Authors:** Aayush Karan, Sitan Chen, Yilun Du
**Published:** 2026-10-01 | **arXiv:** [2610.02140v1](http://arxiv.org/abs/2610.02140v1)

## Summary
This paper challenges the conventional wisdom that supervised finetuning (SFT) — a simpler training method — necessarily produces worse generalization than reinforcement learning (RL) on new tasks. The authors propose an MCMC-based sampling algorithm that transforms offline training data to be more "on-policy" (matching what the model would naturally produce), enabling SFT to match or exceed RL's performance while avoiding catastrophic forgetting. The key insight: the problem isn't the learning algorithm itself, but the data distribution it sees.

## Theoretical Background
The paper builds on a fundamental tension in posttraining large language models. **Supervised finetuning (SFT)** directly optimizes a model to imitate expert demonstrations, making efficient use of offline data but often failing to generalize beyond the training distribution. **Reinforcement learning (RL)** learns from a model's own sampling trajectory, allowing on-policy learning that theoretically generalizes better but requires expensive exploration and struggles with off-policy data. Prior work (e.g., [[RLHF]], [[DPO]]) has tried to bridge this gap by modifying the loss function. This paper instead proposes a **data transformation approach**: use Markov chain Monte Carlo (MCMC) — a sampling technique for drawing from complex distributions — to iteratively make offline trajectories look like samples the reference model would produce, thereby converting an off-policy problem into an on-policy one before training begins.

## Core Contributions
1. **MCMC sampling algorithm for data transformation**: A concrete procedure that progressively reweights and modifies offline traces to match the on-policy distribution of a reference model, enabling SFT to benefit from on-policy learning without explicit RL objectives.
2. **Empirical demonstration that SFT is underestimated**: Shows SFT with transformed data rivals or beats strong on-policy baselines (RL methods) across scientific skill acquisition, mathematical reasoning, and open-ended expertise tasks.
3. **Reduced catastrophic forgetting**: The finetuned models generalize to new tasks while preserving base model capabilities better than RL baselines.
4. **Sampling as a general primitive**: Frames data transformation via sampling as a reusable operator in the posttraining pipeline, separate from the learning objective itself.

## Connections to Other Work
This work directly challenges assumptions underlying [[RLHF]] and other RL-heavy posttraining approaches. It relates to recent critiques of RL's necessity and complements papers studying [[DPO]] (Direct Preference Optimization) and simpler alternatives to RL. The data transformation angle connects to importance sampling and dataset curation literature. It also aligns with broader trends questioning whether "harder" optimization is always better — similar to findings that simple scaling laws often dominate architecture innovations.

## Practical Applications
1. **Faster posttraining pipelines**: Replacing computationally expensive RL (which requires repeated model sampling and reward model queries) with SFT on curated data, reducing posttraining cost by orders of magnitude.
2. **Safer capability injection**: For specialized domains (medicine, law, code), using MCMC to ensure finetuning data stays in a safe, controllable distribution reduces risk of unexpected capability drift.
3. **Multi-task finetuning**: Learning new skills (mathematical reasoning, coding, domain expertise) without forgetting base knowledge, critical for general-purpose assistants.
4. **Offline dataset improvement**: Retroactively upgrading existing offline expert datasets (from human feedback, prior models) to be higher-quality for SFT, extending the utility of existing data.

## Product & Startup Ideas
1. **"SFT-as-a-Service" platform**: A cloud service that takes raw expert demonstrations and applies the MCMC sampling algorithm, returning a curated, high-quality training dataset ready for any SFT pipeline — selling data transformation as a service layer.
2. **Cost-optimized model finetuning**: A startup offering dramatically cheaper posttraining than incumbents (no RL infrastructure needed), targeting enterprises wanting to finetune proprietary models on domain data.
3. **Data quality audit tool**: Software that assesses whether offline datasets are "on-policy enough" for direct SFT, recommending MCMC transformation to increase finetuning efficiency.
4. **Generalist assistant builder**: An end-to-end platform for building multi-skill assistants (customer support + coding + domain knowledge) that learns without catastrophic forgetting, using this approach to scale cheaply.
5. **Synthetic data generation from real traces**: A tool that uses MCMC sampling to expand offline expert data synthetically — taking a small human-annotated dataset and generating on-policy variants for efficient training.

## Technical Limitations
1. **MCMC computational cost unclear**: The paper must show wall-clock time comparisons; if the MCMC sampling is itself expensive, the overall speedup vs. RL may be modest.
2. **Reference model choice**: The algorithm depends on a "reference model" to define on-policy-ness. How sensitive is the method to the choice and quality of this model? Poor reference models could degrade performance.
3. **Limited task scope**: Results focus on scientific skills, math, and "open-ended expertise." Unclear how well this transfers to generation tasks with longer horizons, embodied control, or highly constrained outputs (e.g., structured prediction).
4. **Scalability to frontier scales**: Testing is on models of unspecified size. Does the benefit persist at GPT-4 / Llama-405B scale where the forgetting vs. generalization tradeoff may shift?
5. **Assumption of offline expert data**: The method requires high-quality offline demonstrations. For tasks where human annotation is expensive or sparse, gains may evaporate.
6. **MCMC convergence**: No formal analysis of convergence speed or guarantees that the transformed data actually matches the target on-policy distribution in practice.

## Open Questions
1. **What is the actual computational cost of MCMC sampling relative to end-to-end RL?** A wall-clock time and FLOPs comparison would ground the practical advantage.
2. **Can this method work with weaker reference models, or does it require a near-optimal base model?** How gracefully does performance degrade?
3. **Does this scale to multi-turn dialogue and very long-horizon tasks where on-policy exploration is hardest?**
4. **Can the MCMC transformation be combined with RL (e.g., using transformed data as initialization)?** Is there a regime where hybrid approaches outperform both pure SFT and pure RL?
5. **How does data imbalance and noise in the offline dataset affect the MCMC transformation?** What happens with mixed-quality expert data?
6. **Can you theoretically characterize when on-policy data transformation beats task-specific loss modifications (like DPO)?**

## Key Takeaway
Smarter data sampling can make simple finetuning match complex reinforcement learning without forgetting.
