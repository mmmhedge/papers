# Screen Before You Serve: Simulation for Production Customer Experience AI Agents at 140M Scale

**Authors:** Edesio Alcoba, Kevin Rossell, Aman Gupta, Shao Tang, Jiwoo Hong et al.
**Published:** 2026-09-24 | **arXiv:** [2609.30137v1](http://arxiv.org/abs/2609.30137v1)

## Summary
This paper presents a simulation framework for testing customer service AI agents before deployment to real users. The authors built Snowglobe, a simulator that generates synthetic customer interactions and mocked tool responses, letting teams evaluate agent performance on thousands of conversations without exposing customers to failures. At Nubank (a major Brazilian fintech), this approach increased customer satisfaction by 36.69 points and self-service rates by 8.82 percentage points in live A/B tests, while enabling safe exploration of 16,000+ model configurations.

## Theoretical Background
This work sits at the intersection of [[agents]] (AI systems that perceive, plan, and take actions), [[large-language-models]] (neural networks trained on massive text corpora to generate human-like responses), and testing methodologies for production systems. The core challenge is that customer experience (CX) agents must handle multi-turn conversations, invoke external tools (databases, APIs), follow compliance rules, and maintain user trust — making them risky to iterate on live. Prior work in dialogue systems and reinforcement learning has explored agent evaluation, but typically offline (no real feedback) or online (risky). The paper extends this by coupling synthetic user simulation (generating realistic customer requests and reactions) with mocked tool outputs, creating a fast feedback loop that approximates production without customer risk.

## Core Contributions
1. **Snowglobe simulator design**: A practical system for end-to-end agentic workflow testing using synthetic customers and tool mocks, validated at 140M scale (Nubank's production volume).
2. **Correlation validation**: Empirical proof that simulated evaluator scores correlate strongly with production metrics (tNPS and self-service rate), establishing simulation as a proxy for live performance.
3. **Broad model exploration**: Demonstration that simulation enables safe screening of 16,000+ configurations (models, reasoning settings, prompts) — infeasible via live A/B tests alone.
4. **Production impact quantified**: Two live A/B tests showing tangible improvements (tNPS +36.69, SSR +8.82pp) driven by simulation-guided iteration, on Nubank's highest-volume support agent.

## Connections to Other Work
This extends prior work in [[dialogue systems]] evaluation and [[reinforcement-learning]] agent testing by moving beyond offline metrics toward production-grounded simulation. It relates to broader efforts in [[alignment]] (ensuring agents behave as intended), [[multi-agent-systems]] (coordinating agent + user + backend tool behaviors), and testing frameworks like automated dialogue evaluation. The hypothesis-driven approach mirrors A/B testing methodology from tech products, but shifts the screening phase offline. Related concepts: user simulation in dialogue (Schatzmann et al.), sim-to-real transfer in robotics, and synthetic data generation for NLP.

## Practical Applications
1. **Fintech & regulated industries**: Testing compliance-critical agents (loan applications, dispute resolution, KYC) before production without risking regulatory violations or customer churn.
2. **Omnichannel support platforms**: Screening agent configurations for email, chat, phone across languages and regions before rollout.
3. **E-commerce returns/refunds**: Simulating high-stakes agent conversations (refund eligibility, upselling during dispute resolution) to maximize customer satisfaction.
4. **Healthcare triage agents**: Validating symptom-checking agents on synthetic patient interactions before live deployment, reducing false negatives.
5. **Insurance claim handlers**: Testing multi-step workflows (claim intake → investigation → payout) with realistic edge cases without exposing customers to agent errors.

## Product & Startup Ideas
1. **Simulation-as-a-Service (SaaS) for CX agents**: Multi-tenant platform letting companies upload custom agents, synthetic user personas, and tool mocks; generate 10k+ test conversations in hours; export pass/fail metrics and replay logs. Target: mid-market SaaS companies (Zendesk, Intercom competitors).
2. **Synthetic customer library marketplace**: Pre-built synthetic personas (angry customers, new users, edge cases, non-English speakers) that teams can license and customize for their domain. Monetize via persona licensing + API calls.
3. **Agent A/B testing accelerator**: Platform that runs simulation-guided experiments in parallel, auto-selects winning configuration, and routes live traffic to validated models. Reduces time-to-decision from weeks to days.
4. **Compliance screening tool for regulated agents**: Specialized simulator focusing on regulatory-risk detection (e.g., flagging conversations where agent violates GDPR, FCRA, or industry-specific rules). Market: banking, insurance, healthcare.
5. **Real-time agent monitor with sim-based anomaly detection**: Continuously stream production conversations to a simulator to detect when agent behavior drifts from expected patterns, with auto-rollback triggers.

## Technical Limitations
1. **Synthetic customer realism**: Simulator relies on plausible synthetic requests and reactions; adversarial or highly unusual customer behaviors may not be captured, leading to agent failures in production.
2. **Tool mock fidelity**: Mocked tool outputs (e.g., database responses) may not reflect latency, partial failures, or inconsistent state in production. Cascading tool errors could behave differently in simulation.
3. **Correlation, not causation**: High correlation between simulated and production metrics validates the proxy but doesn't prove causation; confounders (e.g., seasonal trends, backend changes) could affect live results.
4. **Scalability of multi-agent coordination**: Paper focuses on single-agent systems; unclear how simulation scales to multi-turn handoffs (agent → human agent → escalation) or concurrent agent interactions.
5. **Domain generalization**: Results from Nubank's card/payment domain; generalization to other regulated industries (healthcare, legal) or unstructured domains (creative customer service) untested.
6. **Cost of simulation infrastructure**: No discussion of compute cost to run 16,000+ simulated conversations; may be prohibitive for smaller teams.

## Open Questions
1. **Can synthetic customer distribution drift?** As the agent improves, do customer request distributions shift in production? Does the simulator need retraining to stay predictive?
2. **How to detect when simulation no longer correlates with production?** What safeguards ensure the proxy doesn't degrade silently?
3. **Does simulation generalize across customer segments?** Did Nubank validate separately for new vs. repeat customers, or by geography?
4. **How much tool-mock realism is required?** Ablation: how much does latency, partial failures, or eventual consistency in mocked tools degrade predictiveness?
5. **Can this integrate with [[reinforcement-learning]] for direct agent optimization?** Rather than hypothesis-driven screening, can simulation reward signals directly train agents?
6. **What is the trade-off between exploration breadth and depth?** The paper screened 16k configs shallowly; how many conversations are needed to rank configs reliably, and when is live A/B testing more efficient?

## Key Takeaway
Simulated customer conversations let teams safely test production agents on thousands of scenarios before deployment, reducing risk and accelerating iteration.
