# TACO: Ternary Absolute-max Column-wise One-sparse Optimizer for LLM Fine-Tuning

**Authors:** Jichao Jiang, Cristian McGee, El Houcine Bergou, Hanqin Cai, Aritra Dutta
**Published:** 2026-10-01 | **arXiv:** [2610.02199v1](http://arxiv.org/abs/2610.02199v1)

## Summary
This paper introduces TACO, a memory-efficient optimizer for fine-tuning large language models that reduces optimizer state by 174× compared to AdamW while maintaining accuracy. By using a sparse, low-precision update rule based on column-wise signs, TACO enables full-parameter fine-tuning of 30–32B parameter models on a single 80 GB GPU—a practical breakthrough for resource-constrained settings.

## Theoretical Background
Modern LLM fine-tuning relies on first-order optimizers like AdamW, which maintain dense optimizer state (momentum and variance estimates for every parameter). This state roughly triples memory overhead: for a 13B-parameter model, AdamW8bit requires ~28 GB just for optimizer memory. Recent work (Muon) proposed matrix-valued updates using operator-norm steepest descent, which reduces state but deviates from AdamW's geometry and can hurt accuracy on AdamW-pretrained models. TACO builds on Muon's theoretical framework (operator-norm steepest descent) but takes a more aggressive sparse route: it computes exact steepest descent under a dimension-normalized $\ell_1 \to \ell_1$ operator norm by selecting only the sign of the largest-magnitude entry per column. This retains first-order gradient information while making persistent state negligible.

## Core Contributions
1. **Sparse sign-based update rule**: TACO selects per-column signs from the absolute-maximum gradient entries, computing exact steepest descent under $\ell_1 \to \ell_1$ norm geometry—not an approximation.
2. **Extreme state compression**: Reduces persistent optimizer memory to only low-precision gradient components per column, achieving 174× reduction vs. AdamW8bit (27.7 GB → 0.16 GB) on OPT-13B.
3. **Peak memory reduction**: Cuts peak training memory by 2.9× (80.6 GB → 27.5 GB), enabling 30–32B model fine-tuning on single H100.
4. **Maintained accuracy and speed**: Demonstrates comparable accuracy and runtime to AdamW across multiple model families and tasks—no performance cliff.

## Connections to Other Work
TACO directly addresses limitations of [[Muon]] (geometry mismatch with AdamW-pretrained models) while adopting its operator-norm steepest-descent philosophy. It relates to broader efforts in optimizer compression and memory-efficient fine-tuning (e.g., LoRA, QLoRA), but differs by modifying the optimizer itself rather than weight rank or precision. The one-sparse column selection is conceptually related to [[sparsity]] in neural networks and [[quantization]], though applied to optimizer updates rather than weights. It also connects to second-order optimizer design, where memory is classically a bottleneck.

## Practical Applications
1. **On-device fine-tuning**: Researchers and practitioners can now fine-tune 30B+ models on consumer/enterprise GPUs (80 GB), enabling domain adaptation without cloud infrastructure.
2. **Multi-task adaptation**: Teams can maintain multiple fine-tuned versions of large models on a single server, switching between them for different applications (medical, legal, customer support).
3. **Continued learning**: Organizations can periodically fine-tune models on new data without expensive retraining infrastructure, lowering operational cost.
4. **Hardware efficiency**: Reduces power consumption and datacenter load for fine-tuning jobs, cutting carbon footprint and compute costs.
5. **Education**: Makes large-model experimentation accessible to universities and small labs without GPU clusters.

## Product & Startup Ideas
1. **Fine-tuning-as-a-service platform**: Offer fast, cheap fine-tuning API for LLMs on shared hardware; TACO's memory efficiency allows higher utilization and lower per-job cost than competitors.
2. **Enterprise model customization SaaS**: White-label service for companies to fine-tune LLMs on proprietary data without sending it to OpenAI/Anthropic; single H100 can serve many customers.
3. **Edge LLM toolkit**: Developer library packaging TACO for on-device fine-tuning; target mobile/IoT teams building personalized AI features.
4. **Model zoo with checkpoints**: Pre-fine-tuned model marketplace; sell 30B variants fine-tuned for specific domains (healthcare, legal, finance) that run on affordable GPUs.
5. **GPU cluster orchestration software**: Scheduler that maximizes utilization of shared H100s using TACO to pack more fine-tuning jobs, targeting research institutions and enterprises.

## Technical Limitations
1. **Per-column sparsity structure**: The one-sparse column design assumes weight matrices benefit from this geometry; may not generalize equally to 1D (bias) or higher-order tensors.
2. **Sign-only updates**: Discarding magnitude information per update could limit convergence speed on highly anisotropic loss landscapes; no convergence rate analysis provided.
3. **Pretrained model dependency**: Requires models already trained with AdamW-like geometry; unclear how well TACO fine-tunes models trained with other optimizers (e.g., SGD, LAMB).
4. **Limited hyperparameter tuning**: No ablation on learning rate schedules, column selection heuristics, or precision of stored gradients; optimal settings may be problem-specific.
5. **Scalability to XL models**: Tested up to 32B; no evidence on 70B+ models or multi-GPU fine-tuning, which may require communication-efficient variants.
6. **Task diversity**: Evaluation limited to language modeling and instruction-tuning; unclear performance on vision-language, code, or other specialized tasks.

## Open Questions
1. **Convergence theory**: What is the convergence rate of TACO under standard smoothness/convexity assumptions? Does it match AdamW asymptotically?
2. **Magnitude retention**: Can maintaining a small high-precision magnitude component (e.g., top-k) per column improve accuracy without breaking memory gains?
3. **Multi-GPU scaling**: How does TACO's sparse structure interact with distributed fine-tuning (gradient accumulation, data parallelism)? Is all-reduce communication efficient?
4. **Generalization beyond transformers**: Does TACO work for CNNs, RNNs, or other architectures, or is it tuned to transformer weight structure?
5. **Warm-start and transfer**: Can a model fine-tuned with TACO be further fine-tuned with AdamW without accuracy loss, or does it create a "geometry lock-in"?
6. **Hyperparameter sensitivity**: How sensitive is TACO to learning rate, batch size, and column precision vs. AdamW? Is tuning required per task?

## Key Takeaway
TACO cuts LLM fine-tuning memory by 174× via sparse column-wise sign updates, enabling 30B+ models on single GPUs without sacrificing accuracy.
