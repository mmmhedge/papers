# LLM-Driven Multi-Agent Control for Skill-Based Smart Manufacturing

**Authors:** Kay Köhle, Darko Anicic, Thomas A. Runkler, René Graf
**Published:** 2026-10-01 | **arXiv:** [2610.01364v1](http://arxiv.org/abs/2610.01364v1)

## Summary
This paper demonstrates how large language models (LLMs) can control manufacturing systems by pairing each factory module with an LLM-based agent that both plans production sequences offline and handles real-time faults online. The key innovation is showing that LLMs can coordinate across distributed factory modules using standardized communication protocols (MQTT, OPC UA) and emerge fault-diagnosis behaviors without explicit programming, making smart factories more flexible for custom, small-batch production.

## Theoretical Background
The work builds on three foundational areas: (1) **LLM-based agents** — using language models as autonomous decision-makers that can plan and act in structured environments; (2) **multi-agent systems** — frameworks where multiple autonomous agents coordinate to solve problems, typically studied through communication protocols and distributed control architectures; and (3) **smart manufacturing** — factory automation that uses real-time feedback and adaptive control, traditionally built on fixed programs and PLC (programmable logic controller) logic. The paper treats factory modules as observable state that agents can query via standardized APIs (OPC UA — a manufacturing communication standard), grounding agent reasoning in live sensor data rather than purely abstract planning.

## Core Contributions
1. **Three distinct agent architectures** (orchestrator, peer-to-peer, monolithic) implemented and evaluated in a realistic factory simulation — establishing that peer-to-peer and monolithic approaches match or exceed centralized orchestration.
2. **Emergent fault-diagnosis without explicit programming** — all three architectures autonomously detect and respond to silent hardware faults (e.g., blocked conveyor belts) without hard-coded failure handlers, showing LLMs can reason about degraded system state.
3. **Standardized integration blueprint** — demonstrating that MCP (Model Context Protocol) tool servers paired with MQTT inter-agent messaging and real-time state injection form a reproducible, modular foundation for LLM-controlled manufacturing.
4. **Autonomous rerouting capability** — the orchestrator uniquely solved a conveyor fault by dynamically rerouting production flow, proving LLMs can generate novel workarounds for hardware constraints.

## Connections to Other Work
This paper sits at the intersection of [[agents]], [[multi-agent-systems]], and applied LLM reasoning. It relates to:
- **LLM-based planning and control** (e.g., [[ReAct]], prompt-based reasoning) — but grounds agents in real factory state rather than simulated text environments.
- **Distributed multi-agent coordination** — extends classic architectures (centralized vs. peer-to-peer) with LLM reasoning, showing emergent behavior from language model communication.
- **Manufacturing automation** — moves away from rigid PLC programs toward adaptive, language-driven control, addressing the "last-mile" problem of custom production scheduling.
- **Tool-use and grounding** — leverages [[prompt engineering]] and structured APIs (OPC UA, MQTT) to keep agents honest to factory constraints, preventing hallucination.

## Practical Applications
1. **Just-in-time custom manufacturing** — small shops making bespoke products (medical devices, industrial components) can reprogram factory modules via natural language queries rather than hiring engineers to rewrite control logic.
2. **Fault-tolerant production lines** — factories experiencing hardware degradation (sensor noise, conveyor wear) can have agents autonomously reroute orders or halt dangerous operations instead of waiting for technicians.
3. **Factory commissioning and handover** — integrating new modules into existing lines — agents can learn module capabilities via API introspection and coordinate without manual reprogramming.
4. **Predictive maintenance dashboards** — agents continuously reasoning about module state can flag anomalies (e.g., "belt friction increasing, reroute heavy loads") before catastrophic failure.
5. **Multi-site production orchestration** — distributed LLM agents at different factories can coordinate production quotas and material flows via MQTT, adapting to regional demand shifts.

## Product & Startup Ideas
1. **LLM Manufacturing Agent Platform** — SaaS suite offering pre-built LLM agents for common factory modules (conveyors, pick-and-place arms, labelers) with plug-and-play OPC UA integration. Target: mid-size job shops automating custom orders.
2. **Adaptive Factory Scheduler** — an agent that learns production recipes from job specifications (material, shape, finish) and autonomously schedules them across modules, rebooking around faults. Position as "ChatGPT for factory planning."
3. **Fault-Aware Production Monitor** — dashboard pairing LLM reasoning with real-time sensor streams; alerts operators to emerging faults before stoppages and suggests autonomous workarounds (rerouting, parallelization). Sell as "predictive + prescriptive."
4. **Plug-and-Produce Middleware** — open-source/commercial tool translating any OPC UA-compliant machine into an LLM-compatible agent; enables small manufacturers to retrofit legacy equipment without rewriting control software.
5. **Multi-Factory Coordination Network** — federated platform where independent job shops offer spare capacity as "services"; central LLM broker matches jobs across sites, negotiating schedules and freight. Network effect as more shops join.

## Technical Limitations
1. **No cost or latency analysis** — paper does not quantify inference delays (how long does each LLM decision take?) or token costs, critical for real-time fault response where sub-second decisions matter.
2. **Simulation-only evaluation** — all nine challenges run in a simulated six-module hexagonal factory; transfer to real hardware, sensor noise, and actual legacy equipment reliability is unproven.
3. **Scalability unstudied** — paper tests three architectures on 6 modules; unclear how coordination complexity and LLM reasoning scales to 50+ modules or globally distributed sites.
4. **No baseline comparison** — no head-to-head against traditional PLC programs, rule-based controllers, or classical multi-agent algorithms (e.g., contract nets, auction mechanisms), making impact unclear.
5. **Hallucination and safety** — LLMs can generate plausible-sounding but unsafe commands (e.g., overspeed a motor, ignore temperature limits); paper does not address guardrails, safety verification, or liability if agent errors cause equipment damage.
6. **Fault types limited** — only tests silent hardware faults; does not address cascading faults, adversarial inputs, or attacks on MQTT/OPC UA channels.
7. **Token budget and model size** — no discussion of which LLM was used or whether edge-deployable small models work; assumes internet-connected inference or expensive on-premise servers.

## Open Questions
1. **What is the latency breakdown?** How much time do agents spend waiting for LLM inference vs. sensor reads vs. inter-agent communication? Can this scale to sub-second response times?
2. **How does performance degrade with real sensor noise and partial observability?** Simulation assumes perfect state observation; what if cameras are occluded or sensors drift?
3. **Can agents formally verify safety before executing?** Given a candidate action (e.g., "reverse conveyor"), can the system prove it won't violate temperature, speed, or collision constraints before issuing it?
4. **How do agents adapt to new modules without retraining?** If a factory adds a new conveyor type, does the agent learn its capabilities on-the-fly, or does each new module require manual calibration?
5. **What emerges at 100+ modules?** Does peer-to-peer coordination collapse into coordination overhead, or does hierarchical (e.g., zone-based) grouping emerge naturally?
6. **Can adversarial robustness be achieved?** If someone prompt-injects via a malicious job order, can agents detect and reject unsafe commands?
7. **How do costs compare to traditional control?** Total cost of ownership: LLM inference costs + hardware (MCP server, MQTT broker) vs. engineering time to write and maintain PLC logic?

## Key Takeaway
LLM-based agents autonomously control and repair factory production by coordinating via standardized APIs, achieving flexible custom manufacturing without reprogramming.
