# Persistent Recursive Worlds Enable Autonomous Software Evolution

**Authors:** Beichen Huang, Zhenyu Liang, Bowen Zheng, Ran Cheng
**Published:** 2026-08-11 | **arXiv:** [2608.10450v2](http://arxiv.org/abs/2608.10450v2)

## Summary
This paper presents Genesis, a system that enables autonomous software development by agents over long timescales (120+ hours) without requiring individual agents to persist. Instead of keeping agents alive, Genesis keeps the software project itself persistent—agents propose changes to a shared repository, changes get reviewed and accepted, and only validated work advances the project history. The system successfully built a Rust C compiler from scratch and rewrote legacy Fortran code, demonstrating that long-term software evolution can be organized around a stable project rather than stable agents.

## Theoretical Background
The work builds on two foundational ideas: (1) multi-agent systems coordination, where multiple autonomous agents must collaborate on shared tasks, and (2) version control and repository management from software engineering. Genesis extends traditional version control by adding a "recursive world" abstraction—each world represents a namespace (a directory path) with an accepted state, allowing agents to delegate work across nested contexts. This connects to prior work on persistent memory for AI agents, but inverts the persistence requirement: instead of agents maintaining state across episodes, the project maintains state while agents are ephemeral. The recursive delegation mechanism resembles hierarchical task decomposition in multi-agent reinforcement learning.

## Core Contributions
1. **Persistent recursive world architecture**: A novel organizational model where software projects persist across agent lifetimes; agents operate on finite episodes, proposing changes that only advance the version history if accepted.
2. **Long-horizon compilation**: Demonstrated a complete C compiler implementation spanning 120+ hours and 1,000+ agent episodes using commodity LLMs (DeepSeek V4 Flash), passing industry-standard test suites (c-testsuite, LLVM, Csmith).
3. **Agent replacement without degradation**: Showed that development can continue seamlessly after agent replacement (tested with agent substitution), maintaining test performance across generational transitions.
4. **Legacy code modernization at scale**: Reimplemented 13 MESA modules (100k+ Fortran lines) as Rust with 1.55–6.87x median speedups, demonstrating the system's applicability beyond greenfield development.
5. **Cost-efficient long-horizon reasoning**: Achieved substantial software engineering tasks for $44 in model inference costs, making autonomous development economically viable.

## Connections to Other Work
Genesis relates to several research directions:
- **[[Agents]] and [[multi-agent-systems]]**: Extends prior work on agent-based software engineering (e.g., Devin, SWE-agent) by decoupling agent persistence from task persistence.
- **[[Large-language-models]] for code**: Builds on code generation breakthroughs (Copilot, Claude, DeepSeek) but focuses on *composition* and *verification* of agent outputs over long horizons.
- **Version control and CI/CD**: Formalizes how automated testing and acceptance criteria (via the version history) create feedback loops for agent correction.
- **Hierarchical task decomposition**: The recursive delegation mechanism echoes work in hierarchical reinforcement learning and goal-decomposition in multi-agent systems.
- **Memory and context management**: Contrasts with approaches that give agents persistent memory (e.g., retrieval-augmented generation for agents); Genesis achieves continuity through persistent *artifacts* instead.

## Practical Applications
1. **Legacy code modernization**: Automatically refactor large codebases (COBOL, Fortran, C) into modern languages (Rust, Python) with performance validation.
2. **Compiler and language tool development**: Bootstrap new compilers or DSL toolchains from specifications without human engineering effort.
3. **Continuous software evolution**: Enable codebases to evolve autonomously—e.g., auto-upgrade dependencies, refactor for performance, apply security patches—while maintaining test suites.
4. **Multi-team collaboration**: Organize large engineering efforts where agents represent different teams or specializations; the project state is the "source of truth" rather than synchronizing agent memories.
5. **Scientific software development**: Rapidly prototype and optimize numerical libraries (e.g., replace BLAS/LAPACK implementations) with automated benchmarking.

## Product & Startup Ideas
1. **"EvoX for Enterprise"**: A SaaS platform that runs Genesis on customer codebases to continuously refactor, optimize, and migrate legacy systems (COBOL→Python, Fortran→Rust). Charge per lines-of-code processed or per speedup achieved.
2. **"Autonomous DevOps Assistant"**: A CI/CD plugin that continuously improves build times, test coverage, and performance by proposing and validating incremental changes; agents die after each commit, but the repository evolves.
3. **"Language Modernization as a Service"**: Target specific industries (finance, biotech, manufacturing) with pre-trained agent teams specialized in their tech stacks; offer 5–10x speedup guarantees on numeric workloads.
4. **"AI-Driven Security Patching"**: Deploy agents to continuously scan and propose security patches across a portfolio of services; project state is the patched codebase, agents are transient executors.
5. **"Compiler Synthesis Platform"**: Offer custom compiler generation for domain-specific languages; customers define grammar/semantics, Genesis agents build, test, and optimize the compiler automatically.

## Technical Limitations
1. **Test suite quality dependency**: Genesis's success relies entirely on comprehensive test suites; weak or incomplete tests will allow regressions to be accepted into the version history.
2. **Scalability unclear for distributed teams**: Tested on single-project scenarios; unclear how well recursive delegation scales across geographically distributed or async teams.
3. **Agent hallucination and semantic drift**: Over 120+ hours, agents may accumulate subtle semantic errors that pass tests but violate domain invariants (e.g., numerical stability in scientific code).
4. **Cost of per-episode model inference**: While $44 is cheap, each agent episode incurs inference cost; for very large codebases or tight iteration loops, costs could explode.
5. **Limited to deterministic domains**: Software with non-deterministic behavior (concurrency, randomness, I/O) is harder to validate; test-driven acceptance may miss race conditions or subtle timing bugs.
6. **No formal verification**: Relies on empirical testing; safety-critical systems (aviation, medical) would need theorem proving or formal methods, not just test coverage.
7. **Repository state explosion**: Over 1,000+ episodes, the repository accumulates history; garbage collection, pruning, or archival strategies are not discussed.

## Open Questions
1. **Can Genesis handle multi-objective optimization?** The current setup optimizes for "test pass" and manual acceptance; how would you encode competing goals (performance vs. readability, latency vs. memory)?
2. **What happens with partial failures?** If an agent breaks a test mid-way, how does rollback / branching work? Is there a branching strategy for exploratory development?
3. **How does agent diversity affect convergence?** Would a team of different LLM models (GPT-4, Claude, DeepSeek) outperform a homogeneous team? Is there a diversity-performance tradeoff?
4. **Can this scale to distributed, asynchronous teams?** What if agents work on overlapping parts of the codebase with eventual consistency?
5. **How do you prevent adversarial or trolling edits?** If agents can propose changes freely, is there a risk of intentional sabotage? What's the governance model?
6. **Does the recursive world structure generalize to non-code artifacts?** Could this apply to hardware design, ML model training, or scientific experiments?

## Key Takeaway
Autonomous software projects can evolve indefinitely using transient agents if the project itself persists and validates changes.
