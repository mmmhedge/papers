# Rethinking Personalized Generation: Test-Time Alignment via Factorized Ranking Models

**Authors:** Qiyao Ma, Junshan Zhang, Zhe Zhao
**Published:** 2026-09-28 | **arXiv:** [2609.35695v1](http://arxiv.org/abs/2609.35695v1)

## Summary
This paper addresses a fundamental problem: large language models trained with standard alignment methods optimize for an "average" user and ignore the diversity of real preferences. The authors show that personalized generation—tailoring outputs to individual users—can be tackled efficiently at test time using lightweight ranking models rather than expensive reward models. They propose a million-parameter MLP-based ranker that scores candidate outputs 10,000× faster than billion-parameter reward models while delivering better personalization across nine datasets.

## Theoretical Background
[[LLM alignment]] has traditionally focused on making models follow a single set of human-preferred behaviors, typically through [[RLHF]] (reinforcement learning from human feedback) or similar methods. The standard paradigm trains a reward model—a neural network that learns to score generated text—then uses it to optimize the base generator. However, this approach assumes all users want the same thing, which is unrealistic.

The paper builds on [[test-time scaling]] methods like Best-of-N (BoN), which generate multiple candidate outputs and select the best one at inference time. This is distinct from scaling training compute—it trades generation cost for output quality. The key insight is that personalization can be reframed as a *ranking problem* (matching candidates to user preferences) rather than a *generation problem* (training a better model), which changes how we should approach it.

## Core Contributions
1. **Empirical discovery of personalization headroom**: Demonstrates through experiments that substantial performance gains are available by aligning outputs to individual user preferences at test time, even with fixed base models.

2. **Ranking-vs.-generation framing**: Argues that personalized generation is fundamentally a candidate matching problem, not a generator capability problem, making it ideally suited to test-time methods.

3. **Efficient personalized ranking architecture**: Proposes a parameter-efficient ranking model (millions vs. billions of parameters) that reuses the base generator's internal embeddings, reducing overhead to <0.4% of standard reward model size.

4. **Latency and cost improvements**: Achieves 10,000× lower scoring latency than billion-parameter reward models while outperforming them on all nine evaluated datasets.

5. **Scalable preference data strategy**: Shows that scaling fine-grained personalized preference data during training enables the lightweight ranking model to accurately capture diverse user preferences.

## Connections to Other Work
This work sits at the intersection of [[alignment]] and [[test-time scaling]]. It directly challenges the standard [[RLHF]] paradigm by showing that monolithic reward models are misaligned (literally) with the goal of personalization. Related to [[prompt engineering]] and [[in-context learning]], which also adapt LLM behavior at test time, but via different mechanisms. Also connects to [[ranking and information retrieval]], where ranking-based scoring has long been efficient. The efficiency gains echo recent trends in [[model distillation]] and parameter-efficient fine-tuning (e.g., LoRA), but applied to the reward/ranking layer.

## Practical Applications
1. **E-commerce recommendation**: Personalize product descriptions and review summaries to each user's stated preferences (e.g., price-sensitive vs. quality-focused shoppers).
2. **Conversational AI**: Adapt chatbot tone, verbosity, and content depth per user (technical jargon for engineers, plain language for general users).
3. **Content generation platforms**: Tailor news summaries, social media captions, or creative writing outputs to individual creator styles and audience personas.
4. **Customer support**: Generate support responses tuned to customer satisfaction history and support tier (premium vs. standard).
5. **Personalized tutoring**: Adapt explanation style, difficulty level, and pacing to individual student learning profiles.

## Product & Startup Ideas
1. **Personalization-as-a-service API**: Offer a lightweight ranking service that plugs into any base LLM, allowing companies to personalize outputs without retraining. Monetize per scoring request.

2. **Creator studio for influencers**: SaaS tool that learns each creator's voice (via preference data) and auto-generates captions, thumbnails, or email copy tuned to their audience. Lower cost than custom fine-tuning.

3. **Enterprise chatbot personalization layer**: Middleware that enriches corporate chatbots with user-specific preferences (role, seniority, communication style) without modifying the underlying model.

4. **Preference learning for B2B SaaS**: Help product companies collect and deploy fine-grained user preference data, then use lightweight ranking to personalize UX text, error messages, and recommendations.

5. **Marketplace for preference models**: Tiered ranking models trained on different demographic, cultural, or professional preference data—available as plug-and-play components for other companies' LLMs.

## Technical Limitations
1. **Candidate pool requirement**: Depends on generating multiple candidates (N in Best-of-N), which increases generation cost upfront. Only efficient if N is moderate and the base generator is fast.

2. **Preference data cold-start**: Requires fine-grained personalized preference data at train time. New users with no preference history may not benefit. Bootstrapping preference data for new domains is non-trivial.

3. **Embedding reuse assumption**: Directly reusing base model embeddings assumes they capture user-relevant signal. May fail if the base model is trained on different objectives or has poor representations for certain preference dimensions.

4. **Scalability of preference data annotation**: Collecting diverse, granular preference labels across nine datasets is labor-intensive. Real-world deployment at scale may hit annotation bottlenecks.

5. **Generalization beyond tested settings**: Experiments cover nine datasets across three settings. Unknown how well the approach generalizes to new domains, languages, or user populations with different preference structures.

6. **No online learning**: The ranking model is static after training. Cannot adapt to individual users' evolving preferences without retraining.

## Open Questions
1. **Dynamic preference adaptation**: Can the ranking model be updated online (per user or per session) without full retraining? What is the sample complexity?

2. **Preference conflict and group alignment**: What happens when preferences conflict across groups or shift over time? Can the method gracefully handle preference shift?

3. **Mechanistic understanding**: Why do lightweight ranking models outperform billion-parameter reward models? Is it regularization, better calibration, or something else? (Connects to [[mechanistic-interpretability]].)

4. **Multimodal preferences**: Does the approach extend to vision + language, audio, or other modalities? Do embeddings from multimodal models work as well?

5. **Human-in-the-loop iteration**: Can the system solicit feedback on ranked candidates to continuously improve the ranking model? How many feedback rounds are needed?

6. **Trade-off between generation and ranking cost**: When is it cheaper to generate N candidates and rank them vs. training a better base generator? What is the optimal N?

## Key Takeaway
Lightweight ranking models can personalize LLM outputs at test time faster and cheaper than giant reward models, unlocking untapped performance for diverse user preferences.
