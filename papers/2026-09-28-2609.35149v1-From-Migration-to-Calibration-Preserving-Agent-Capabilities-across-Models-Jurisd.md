# From Migration to Calibration: Preserving Agent Capabilities across Models, Jurisdictions, and Scale

**Authors:** Yaxiao Liu, Pengbo Liu, Yiwen Liu, Yihua Guan, Jiaxing Song
**Published:** 2026-09-28 | **arXiv:** [2609.35149v1](http://arxiv.org/abs/2609.35149v1)

## Summary
This paper addresses how AI agents maintain their capabilities when deployed under different conditions—switching underlying models, operating across different countries or regions, or scaling to new markets. The authors propose a three-layer framework (information, harness, and user calibration) to adapt agents while preserving their core abilities and meeting new requirements. The work is methodological, laying out evaluation strategies rather than providing fully implemented solutions.

## Theoretical Background
The paper builds on agent design principles where capability preservation is critical during deployment transitions. It assumes agents operate across distinct layers: (1) the information/knowledge they rely on, (2) the "harness"—the infrastructure and tools they use to act, and (3) user-facing contracts—the specific formats and preferences outputs must satisfy. Prior work on model transfer, interface adaptation, and behavioral validation in multi-agent systems (systems where multiple agents interact) motivates the need for systematic calibration. The authors reference harness-transfer studies and judge-validity research, suggesting that naive interface compatibility is insufficient; agents need semantic-level verification that they still solve the intended problem.

## Core Contributions
- **Three-layer calibration framework**: Information preservation (keeping source knowledge applicable to target), harness adaptation (aligning tools and infrastructure), and user calibration (meeting output contracts like templates and schemas).
- **Capability non-degradation objective**: Rather than assuming agents automatically work in new contexts, the paper proposes measuring pre-specified capability benchmarks and enforcing that performance does not drop below thresholds.
- **Methodological evaluation design**: Proposes held-out evaluations using factorial testing (varying source evidence and checkpoint repair independently), target-native execution records, and group-level reporting to catch localized failures masked by aggregate metrics.
- **Distinction between optimization types**: Separates trainable policies from frozen-backbone configuration and discusses evidence verification versus relative judgment (DPO/GRPO optimization).

## Connections to Other Work
This work relates to [[RLHF]] (reinforcement learning from human feedback) and [[alignment]] in the sense that it concerns ensuring agents behave as intended. It touches on [[multi-agent-systems]] because deployment across jurisdictions and heterogeneous markets involves coordination. The emphasis on "contracts" and "template enforcement" connects to specification and verification challenges in [[agents]]. It differs from pure [[mechanistic-interpretability]] work—rather than probing internal model structure, it focuses on behavioral adaptation at system level.

## Practical Applications
- **Autonomous vehicle deployment**: Migrating a trained driving agent from one region to another (different traffic laws, road marking conventions) while verifying safety benchmarks remain met.
- **Multilingual customer service agents**: Deploying a conversational agent across markets with different output format requirements (templating, regulatory disclaimers, regional tone preferences).
- **E-commerce marketplace optimization**: Adapting pricing or recommendation agents when integrating a new vendor or expanding to a new geography, ensuring revenue targets hold.
- **Foundation model fine-tuning pipelines**: Transitioning a base language model to a task-specific variant without losing general-purpose capabilities.
- **Cross-border compliance in finance**: Adapting trading or lending agents to new regulatory jurisdictions while preserving risk controls.

## Product & Startup Ideas
1. **Agent Calibration-as-a-Service platform**: Automated testing and adaptation layer for organizations deploying agents across regions or models. Ingests deployment specs, runs factorial evaluations, and suggests configuration changes or retraining budgets.
2. **Behavioral equivalence certification tool**: SaaS that certifies whether a migrated agent retains capability parity with the original, using the proposed evaluation framework—useful for regulated industries (finance, healthcare, autonomous systems).
3. **Cross-border agent adapter**: Plug-and-play middleware that handles jurisdiction-specific output contracts, schemas, and local validation rules, with a visual configuration UI and audit trail.
4. **Model transition orchestrator**: Enterprise tool for safely upgrading agent models (e.g., swapping a 2-year-old language model for a newer one), running continuous capability monitoring and rollback triggers.
5. **Agent audit and compliance suite**: Generates group-level performance reports and flags localized capability failures by demographic or cohort, targeting regulated deployments (lending, hiring, content moderation agents).

## Technical Limitations
- **Methodological rather than empirical**: The paper does not implement or validate the framework on real systems; robustness and practical applicability remain unproven.
- **Definition of "capability"**: The paper assumes pre-specified capability measures exist, but defining these measures is itself hard, especially for subjective tasks (e.g., "quality" of a recommendation).
- **Scalability of evaluation**: Factorial testing and held-out evaluations can be expensive at scale; the paper does not discuss computational or time budgets for validation pipelines.
- **User calibration ambiguity**: Specifying output contracts is treated as straightforward, but in practice, "user preferences" are often implicit or contradictory across cohorts.
- **Assumption of stable source knowledge**: Information preservation assumes some source knowledge is "independently validated" and remains valid in the target context—this can fail when domain shifts are large.

## Open Questions
- How should practitioners prioritize the three calibration layers when resources are constrained? Is one more critical than others?
- What is the computational cost of the proposed factorial evaluations compared to standard A/B testing?
- How sensitive are the non-degradation guarantees to misspecification of capability measures?
- Can the framework be extended to agents that learn or adapt online (continual learning), rather than only pre-trained, frozen-backbone agents?
- How do you handle conflicts between user requirements in different jurisdictions (e.g., transparency vs. privacy)?
- Are there automated methods to suggest which information, harness components, or user contracts need updating for a given target scenario?

## Key Takeaway
Agents require systematic multi-layer adaptation—not just interface changes—when deployed to new models, regions, or scales while preserving core capabilities.
