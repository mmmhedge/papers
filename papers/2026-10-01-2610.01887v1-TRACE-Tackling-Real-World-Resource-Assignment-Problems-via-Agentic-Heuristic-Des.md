# TRACE: Tackling Real-World Resource Assignment Problems via Agentic Heuristic Design

**Authors:** Jose A. Ayala-Romero, Andres Garcia-Saavedra, Xavier Costa-Perez
**Published:** 2026-10-01 | **arXiv:** [2610.01887v1](http://arxiv.org/abs/2610.01887v1)

## Summary
This paper presents TRACE, a system that automatically designs scheduling rules for allocating computational tasks to servers in real-time. The key innovation is combining evolutionary algorithm-based heuristic generation with AI agents that analyze system logs to understand *why* certain rules work better—filling a gap where existing methods only see a performance score without understanding the underlying system behavior. The work bridges the gap between theoretically optimal ML schedulers and practical industrial systems that need human-readable, auditable rules.

## Theoretical Background
The paper builds on **Automatic Heuristic Design (AHD)**, an emerging approach that uses LLMs and evolutionary algorithms to generate hand-crafted scheduling rules instead of training neural networks. Traditional approaches fall into two camps: learning-based schedulers (deep reinforcement learning, neural networks) that optimize well but are hard to understand and deploy in production, and hand-written heuristics that operators can reason about but require manual tuning.

TRACE extends prior AHD work by recognizing that in real systems, evaluation produces rich telemetry (system logs) that contains causal signals—processor speeds, queue lengths, power draw—that explain *why* a heuristic succeeds or fails. The paper frames this as an **agentic knowledge extraction** problem: use LLM agents to parse heterogeneous logs, form hypotheses about system dynamics, and test them programmatically to produce insights that feed back into the heuristic design loop.

## Core Contributions
1. **Agentic log analysis**: A two-agent system (Reasoner and Coder) that autonomously interprets arbitrary log schemas, formulates hypotheses about system behavior, and executes schema-specific code to validate them—solving the non-trivial problem of extracting signal from massive, noisy, format-varied logs.

2. **Closed-loop evolutionary design**: Coupling evolution-based AHD with interpretable tool generation; the agents don't just explain why a heuristic works, they produce executable code that the evolved heuristics can call, increasing expressiveness.

3. **Empirical validation on realistic workloads**: Evaluation on both a cloud scheduling benchmark and a 5G RAN (radio access network) scenario derived from real operational data and traffic traces, not toy problems.

4. **Production feasibility**: Demonstrated heuristics are more auditable than neural schedulers, with <2% performance overhead compared to learning-based baselines while maintaining readability.

## Connections to Other Work
TRACE sits at the intersection of several trends:
- **[[Automatic Heuristic Design]]** / LLM-based program synthesis: extends prior work by adding feedback loops through log analysis
- **[[Reinforcement Learning]]** for scheduling: contrasts with end-to-end RL approaches by prioritizing interpretability and operational constraints
- **Multi-agent reasoning**: related to approaches like [[ReAct]] and tool-use in LLM agents, but applied to system optimization rather than QA or reasoning tasks
- **[[Mechanistic Interpretability]]**: shares the goal of understanding system behavior, but targets domain-specific log signals rather than neural network internals

## Practical Applications
1. **Cloud scheduler optimization**: Automatically tune task-to-VM assignment rules for heterogeneous data center workloads without manual tuning by operators.

2. **5G RAN resource allocation**: Optimize slice and resource block assignment to base stations under varying traffic, hardware constraints, and power budgets—the industrial 5G use case explored in the paper.

3. **Network packet scheduling**: Automatically design queue-management rules for routers or software-defined networking based on real traffic telemetry.

4. **Batch job scheduling in HPC clusters**: Evolve job-to-node assignment heuristics that respect heterogeneous hardware (different CPU/GPU types, memory, interconnect) and operational objectives (throughput, fairness, energy).

5. **Edge computing task placement**: Assign workloads to edge nodes with varying compute, latency, and energy constraints based on live system behavior.

## Product & Startup Ideas
1. **Heuristic-as-a-Service platform**: A SaaS tool for cloud operators to upload system logs and optimization objectives, receive automatically designed, auditable scheduling rules via TRACE, and A/B test them safely in production.

2. **AI-powered operations consulting for telecom**: Specialize TRACE for 5G/6G RAN resource allocation; offer managed service where you absorb operational logs, incrementally improve allocation rules, and charge per improvement in KPIs (throughput, latency, power).

3. **Open-source scheduler synthesizer**: Productize TRACE as a framework that teams can run on their own infrastructure; offer enterprise support for log schema parsing and hypothesis validation across diverse stacks.

4. **Compliance-first ML orchestration**: Target regulated industries (finance, healthcare) where neural schedulers are seen as black boxes; position TRACE-generated heuristics as interpretable, auditable alternatives that satisfy governance requirements while outperforming hand-written rules.

5. **Real-time digital twin optimizer**: Embed TRACE into digital twin platforms used in manufacturing and logistics; automatically refine scheduling heuristics as physical system behavior drifts over time, using telemetry from sensors to close the feedback loop.

## Technical Limitations
1. **Log parsing is still manual at the schema level**: While agents analyze logs *given* the schema, defining what fields exist and how to parse them requires human input or external tooling; the approach doesn't fully automate data preparation.

2. **Scalability of hypothesis testing**: Testing many hypotheses via code execution could become slow as log volume grows; the paper doesn't report latency or computational cost for the agentic loop.

3. **Generalization across hardware/software stacks**: Tested on cloud and 5G scenarios, but unclear how well the approach transfers to fundamentally different resource types (e.g., GPU scheduling, memory allocation) where log schemas and dynamics differ radically.

4. **Limited exploration of adversarial log distributions**: No evaluation on edge cases where logs are sparse, highly correlated, or where ground-truth system dynamics are hidden; robustness to log quality is unexplored.

5. **Assumption of stable objectives**: The evolved heuristics are optimized for a fixed objective (throughput, latency, power). Objectives that shift over time (e.g., SLAs that change seasonally) are not addressed.

6. **Agent hallucination risk**: LLM agents can generate plausible but incorrect hypotheses or code; the paper doesn't discuss validation or rollback mechanisms if the agent's insights mislead the evolved heuristics.

## Open Questions
1. How does TRACE perform on warm-start scenarios where an existing hand-written heuristic or legacy scheduler already exists? Can it learn to refine rather than replace?

2. Can the agentic knowledge extraction be made more efficient or more rigorous—e.g., via statistical hypothesis testing rather than agent-driven exploration?

3. How do the evolved heuristics degrade if log features drift over time (e.g., hardware replaced, traffic patterns shift)? Do they need periodic re-optimization?

4. Can TRACE be extended to multi-objective optimization where operators want to trade off latency, throughput, and power simultaneously, not a single scalar fitness score?

5. What is the sample efficiency of the evolutionary loop? How many system evaluations (deployments) are needed to converge to a good heuristic, and can this be reduced with active learning or transfer from related domains?

6. Do the evolved heuristics exhibit undesirable emergent behaviors (e.g., starvation of low-priority tasks) that the fitness function doesn't capture but logs could reveal?

## Key Takeaway
AI agents can automatically design interpretable, auditable scheduling rules by analyzing system logs to understand *why* rules succeed—beating black-box ML while staying production-ready.
