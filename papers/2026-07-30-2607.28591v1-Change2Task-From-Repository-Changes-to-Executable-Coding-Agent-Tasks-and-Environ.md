# Change2Task: From Repository Changes to Executable Coding Agent Tasks and Environments

**Authors:** Haomin Qi, Xingliang Wang, Xuanqi Gao, Baihui Sang, Xin Zhang et al.
**Published:** 2026-07-30 | **arXiv:** [2607.28591v1](http://arxiv.org/abs/2607.28591v1)

## Summary
This paper presents Change2Task, a system that automatically converts pull requests from software repositories into executable training tasks for coding agents. The system reconstructs realistic code states, validates task correctness, and generates diverse coding tasks (bug fixes, feature additions, tests, API migrations, security repairs) at 79.6% success rate—solving a key bottleneck in scaling coding agent development: the scarcity of quality training data with verified solutions.

## Theoretical Background
The work builds on two intersecting areas: (1) **coding agents** — AI systems that write and modify code, typically powered by large language models (LLMs) that can process code as text; and (2) **automated task generation and evaluation** — using repository history as a signal for realistic software engineering problems. It leverages the insight that merged pull requests encode developer intent and verified solutions, making them valuable training signals. The paper extends prior work on mining software repositories for task construction by adding mechanisms to align historical changes with evolved modern codebases and reconstruct intermediate states through techniques like patch reversal and code mapping.

## Core Contributions
1. **Change2Task pipeline**: A systematic approach to extract coding tasks from pull request history, with three reconstruction strategies (Patch Reversal for direct application, Code Mapping for evolved APIs, Agent Reconstruction as fallback).
2. **Task state validation**: A lifecycle verification system ensuring tasks transition correctly from healthy base → task state → restored state, reducing false positives in training data.
3. **Empirical scaling results**: Demonstration across five task families with 79.6% verified success and 29.2% recovery gain over baseline, plus 10.8% cost reduction through environment reuse.
4. **Task diversity evidence**: Proof that historical reconstruction achieves 98.0% outcome agreement with original pull request evidence, validating data fidelity.

## Connections to Other Work
This work directly supports the training and benchmarking of [[agents]] (particularly code-writing agents powered by [[large-language-models]]). It relates to:
- **RLHF and agent training pipelines**: Quality, verified task data is essential for both supervised fine-tuning and reward modeling in [[reinforcement-learning]] from human feedback.
- **Software engineering benchmarks**: Complements existing datasets (HumanEval, SWE-Bench, etc.) by offering a scalable, repository-grounded alternative.
- **Code understanding and mapping**: Leverages techniques from code search and semantic code matching to handle API evolution.
- **Automated program repair**: Shares methodologies with bug-fix and security-repair communities.

## Practical Applications
1. **Coding agent training at scale**: Continuously supply verified tasks to train models like GitHub Copilot, Claude Code, or open-source code LLMs without manual labeling.
2. **Continuous benchmarking**: Automatically generate fresh evaluation tasks from real repository changes to track agent performance over time without benchmark saturation.
3. **Enterprise code automation**: Internal tool development teams can use Change2Task on their own repositories to train domain-specific coding agents on proprietary patterns.
4. **Security and compliance**: Automatically curate security repair and API migration tasks to train agents on organizational best practices and migration patterns.
5. **Open-source maintainer tooling**: Reduce onboarding friction by generating realistic coding tasks that teach new contributors patterns from merged pull requests.

## Product & Startup Ideas
1. **SaaS Coding Agent Training Platform**: Offer Change2Task as a hosted service where teams upload repositories, receive a stream of verified tasks, and get a fine-tuned internal coding agent. Pricing by task volume or model performance gains.
2. **Continuous Benchmark-as-a-Service for Code Models**: Automatically generate fresh, repository-grounded evaluation benchmarks for code LLM providers (OpenAI, Anthropic, etc.) to test real-world performance without saturation or data leakage.
3. **Enterprise Code Migration Automation**: Specialize Change2Task for large-scale migrations (Java → Kotlin, Python 2 → 3, framework upgrades). Sell as a tool that learns from a company's past migrations and auto-generates migration tasks for AI-assisted execution.
4. **Security Posture Improvement Engine**: Extract security repair tasks from merged PRs in open-source projects, train a specialized agent, and offer it as a SaaS security scanner that not only flags issues but proposes fixes with high confidence.
5. **Developer Onboarding via AI**: Generate personalized coding tasks for new hires by mining the company's repository history, creating a self-paced, AI-guided onboarding program that teaches codebase patterns and company conventions.

## Technical Limitations
1. **Reconstruction fidelity**: Patch Reversal may fail if code has evolved significantly; Code Mapping requires semantic equivalence detection (imperfect for complex refactors). Agent Reconstruction is a last-resort fallback with lower reliability.
2. **Environment setup assumptions**: Assumes repositories have stable, testable build pipelines; brittle or legacy codebases may have high failure rates. Windows-specific or cloud-dependent tests may not generalize.
3. **Task diversity bias**: Tasks are biased toward changes that are easy to reverse-engineer; refactors, large architectural changes, or undocumented patches may be underrepresented.
4. **Verification cost**: Lifecycle validation requires test execution, which scales with repository size and complexity. Tasks with flaky tests or slow suites become expensive to verify.
5. **Historical context loss**: A task extracted from a pull request loses soft signals (reviewer comments, iteration history, team context) that inform real coding work.
6. **Generalization uncertainty**: Tasks grounded in specific repositories may not generalize; what works for Django may not transfer to Flask without fine-tuning.

## Open Questions
1. **Cross-repository transfer**: How well do agents trained on Change2Task tasks from one repository transfer to different codebases or languages? Can we measure and improve transfer learning?
2. **Task difficulty calibration**: Can we automatically assess task difficulty (bug severity, code complexity, API surface area) and use that for curriculum learning? Does difficulty-balanced task ordering improve agent convergence?
3. **Downstream agent performance**: What is the actual end-to-end impact on agent coding accuracy when trained on Change2Task data vs. manually curated tasks or synthetic data? How much task volume is needed?
4. **Handling refactors and large changes**: How should the system handle non-linear changes (large refactors, architectural shifts)? Can semantic code search improve reconstruction beyond current approaches?
5. **Multi-language and framework scaling**: Does the pipeline work well for languages beyond Python/JavaScript (e.g., Rust, Go, compiled languages)? What adaptations are needed?
6. **Continuous training dynamics**: If Change2Task runs continuously on a live repository, does the agent training become unstable (distribution shift, task leakage) or improve? How do you avoid agents learning only recent coding trends?

## Key Takeaway
Automated pull request mining creates massive verified training task supply for scaling code agents from real repository history.
