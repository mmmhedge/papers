# cua-speedrun: Standardized Benchmarking of the Speed of Computer-Use Agents

**Authors:** Pranjal Aggarwal, Lawrence Keunho Jang, Sean Welleck, Daniel Fried, Ruslan Salakhutdinov et al.
**Published:** 2026-09-30 | **arXiv:** [2609.40284v1](http://arxiv.org/abs/2609.40284v1)

## Summary
This paper introduces cua-speedrun, a standardized benchmarking framework for evaluating the speed and efficiency of computer-use agents (CUAs) — AI systems that interact with graphical user interfaces to complete tasks. While CUAs have recently matched or exceeded human performance on many benchmarks, their practical adoption is limited by speed and cost; this work provides reproducible infrastructure and metrics to measure and optimize these critical dimensions.

## Theoretical Background
Computer-use agents operate at the intersection of language models, vision systems, and reinforcement learning. Prior CUA benchmarks (like OSWorld, WebVoyager, and others) evaluate task completion and reasoning quality but lack standardized measurement of execution speed and cost. The paper builds on foundational work in agent design—where agents use language models to reason about and interact with environments—and extends it with systematic performance profiling. Key concepts include reasoning effort (how much computation an agent invests in planning vs. acting), agent harnesses (the infrastructure binding the agent to the environment), and environment latency (delays in GUI response times). The paper treats speed as a first-class evaluation dimension alongside accuracy.

## Core Contributions
- **cua-speedrun framework**: Introduces standardized virtual machine setup, execution pipeline, and common agent interface, eliminating infrastructure variability that confounds speed measurement across different benchmarks.
- **Multi-benchmark evaluation**: Conducts systematic evaluation across four CUA benchmarks, isolating how reasoning effort, agent harnesses, and environment latency independently affect speed, accuracy, and cost.
- **Non-intuitive findings**: Demonstrates that no single model family dominates all three metrics (speed, accuracy, cost); shows that increasing reasoning effort can paradoxically speed up task completion in some cases; reveals that reducing environment latency can sometimes increase overall completion time.
- **Benchmark reduction**: Demonstrates that CUA benchmarks can be substantially reduced without losing statistical power, enabling faster iteration and comparison.

## Connections to Other Work
This work addresses reproducibility and benchmarking standardization—problems also central to ML evaluation broadly. It complements recent advances in [[large-language-models|LLMs]] applied to agent control and [[vision]] integration (multimodal reasoning). The speed-vs.-accuracy tradeoff mirrors classic problems in [[reinforcement-learning]] and online learning. The finding that reasoning effort has non-monotonic effects on speed echoes results in chain-of-thought prompting literature, where intermediate reasoning quality and computational cost interact in complex ways. The infrastructure contribution parallels efforts in the broader benchmarking community (e.g., MLPerf) to standardize evaluation.

## Practical Applications
- **Enterprise automation**: Organizations can now reliably compare and deploy CUAs for document processing, data entry, and workflow automation, with clear understanding of cost and latency tradeoffs.
- **Cloud service optimization**: Cloud providers can offer CUA services with predictable SLAs, using cua-speedrun to validate performance claims and tune instance types.
- **Mobile and edge deployment**: Speed metrics enable optimization of lightweight agents for resource-constrained environments (phones, embedded systems).
- **Real-time systems**: Use cases like live customer support automation or time-sensitive data analysis require speed guarantees that this benchmark enables.

## Technical Limitations
- **Scope**: Evaluation limited to four benchmarks; generalization to novel CUA tasks or domains untested.
- **Reasoning effort operationalization**: Paper varies reasoning budget, but doesn't deeply explain *why* some budgets paradoxically accelerate completion (mechanism remains unclear).
- **Real-world latency variability**: Standardized VM setup may not capture realistic network jitter, interrupts, or hardware heterogeneity in production deployments.
- **Model-specific effects**: Results may reflect idiosyncrasies of tested models rather than fundamental principles; unclear how insights transfer to future architectures.
- **Task set reduction**: While reduction preserves statistical power, it may miss rare but important failure modes or edge cases.
- **Cost measurement**: Assumes fixed pricing models; doesn't account for dynamic cloud pricing or hybrid human-AI execution.

## Open Questions
- What is the causal mechanism behind the non-monotonic effect of reasoning effort on speed? When is more reasoning helpful vs. harmful, and can we predict this without expensive evaluation?
- How do cua-speedrun metrics transfer to real-world deployments with varying network conditions, hardware, and interruptions?
- Can we design agents that dynamically adjust reasoning effort based on task properties (complexity, time constraints)?
- How do vision-based reasoning and action selection interact with speed? The paper focuses on LLM-based reasoning—do vision-heavy agents exhibit different tradeoffs?
- Can we establish principled lower bounds on speed for a given accuracy target across benchmarks?

## Key Takeaway
Standardized benchmarking reveals that AI computer-use agents face complex speed-accuracy-cost tradeoffs with non-obvious optimization paths.
