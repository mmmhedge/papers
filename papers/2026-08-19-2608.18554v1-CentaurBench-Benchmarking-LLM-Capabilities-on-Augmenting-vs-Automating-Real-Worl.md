# CentaurBench: Benchmarking LLM Capabilities on Augmenting vs. Automating Real-World Work Tasks

**Authors:** Pattaraphon Kenny Wongchamcharoen, Kris Gulati, Min Min Fong, Abhishek Nagaraj
**Published:** 2026-08-19 | **arXiv:** [2608.18554v1](http://arxiv.org/abs/2608.18554v1)

## Summary
This paper challenges how we measure LLM capabilities by showing that the models best at automating tasks aren't necessarily best at helping weaker agents complete those tasks. Using seven real-world tasks, researchers compare "automation mode" (LLM produces the output directly) against "augmentation mode" (LLM assists a weaker worker who produces the final output), and find these two rankings are only weakly correlated—suggesting current benchmarks miss a critical use case.

## Theoretical Background
LLM evaluation has historically focused on absolute task performance: how well does model X solve problem Y? This framework assumes that maximizing output quality is the goal. However, in deployed systems, LLMs often work alongside humans or other AI agents in collaborative workflows. The paper builds on multi-agent systems theory—the study of how independent agents interact and coordinate—and challenges the implicit assumption that "better automation = better assistance." It also draws on human-computer interaction concepts: the idea that tool utility depends not just on its absolute capability but on how it interacts with its user.

## Core Contributions
1. **Unified evaluation framework** that explicitly separates automation (direct output) from augmentation (assisting another agent) rather than conflating them.
2. **Empirical finding**: a model can rank first in automation but lose on augmentation in 5 of 7 tasks, with only modest rank correlation (≈0.4–0.6 range implied by "modestly correlated").
3. **Counterintuitive result**: assistance is not reliably positive—the unaided worker outperforms all assisted conditions on 3 of 7 tasks; only 1 model's guidance beats no guidance on average across tasks.
4. **Blind pairwise LLM-based evaluation** with domain-specific rubrics and 10-run replication, reducing noise in subjective scoring.

## Connections to Other Work
This work pushes back against the automation-centric paradigm that dominates [[large-language-model]] benchmarking (e.g., MMLU, HumanEval). It aligns with recent interest in [[multi-agent-systems]] where LLMs collaborate with humans or other agents, and resonates with critiques of [[alignment]] research that focus solely on model capabilities without considering real deployment contexts. The paper implicitly addresses **capability mismatch**: when one agent's output becomes input to another, optimization for the first agent's output quality can hurt overall system performance—a problem known in multi-agent reinforcement learning and supply-chain optimization.

## Practical Applications
1. **Enterprise AI tool selection**: Companies deploying LLMs to augment workforce productivity should run augmentation-mode benchmarks rather than trusting public automation leaderboards.
2. **Copilot design**: Coding assistants, writing aids, and design tools need evaluation in context—does the model help a junior engineer or confuse them?
3. **Customer support triage**: Evaluating whether an LLM pre-screening agent actually helps human support staff resolve tickets faster and better.
4. **Educational tutoring systems**: Assessing whether LLM tutors improve student learning outcomes when students (the weaker agent) are responsible for applying suggestions.
5. **Radiology/medical assistance**: Evaluating whether an LLM report generator helps radiologists work faster without increasing error rates.

## Product & Startup Ideas
1. **Model Selection-as-a-Service**: A benchmarking platform that runs augmentation-mode tests on any LLM against a client's specific workflows (coding, legal review, customer service), letting companies pick the best assistant for their team rather than the best absolute performer.
2. **CoPilot Evaluation SaaS**: Offer enterprises a white-glove service to measure whether their chosen LLM actually improves productivity of their actual workers on real internal tasks (documents, code, emails), using blind A/B testing.
3. **Augmentation-Aware Model Ranking**: A public leaderboard ranking models explicitly on augmentation capability, with task-specific rubrics tied to real economic value (cost per output, error rate, time-to-completion).
4. **Human-AI Workflow Optimizer**: Analyze where augmentation fails (e.g., "this model's suggestions confuse junior engineers"), and recommend task-specific model combinations or prompt adjustments.
5. **Downstream Performance Monitoring**: A tool that tracks real-world outcomes when an LLM assists workers—did ticket resolution improve? Did code quality drop?—and alerts when a model swap hurts actual team performance.

## Technical Limitations
1. **Scope**: Only seven tasks tested; generalizability to other domains (law, science, creative work) unclear.
2. **Worker model fixed**: The "lower-capacity worker" is a single standardized model; results may not transfer to diverse human workers with varying skill levels.
3. **LLM judge reliability**: Using another LLM to score pairwise outputs introduces potential bias; the "ten-run" replication helps but doesn't eliminate the risk that the judge itself is a source of error.
4. **Assistance format**: Guidance is text-only; multimodal or iterative assistance (dialogue, refinement loops) not tested.
5. **Economic grounding claim**: Tasks are labeled "economically grounded," but no actual cost-benefit analysis (wages, error penalties, opportunity cost) is provided to validate which augmentation approach maximizes value.
6. **No human baseline**: Would be stronger with human raters or actual human workers in the loop to validate the LLM judge's scores.

## Open Questions
1. **Why does augmentation fail?** Which failure modes dominate—does the assistant's guidance mislead the weaker agent, or is it irrelevant? Qualitative analysis of failed augmentations needed.
2. **Is there a model property that predicts augmentation skill?** Can we characterize which architectures, training methods, or model sizes tend to augment well? (e.g., do smaller models that explain reasoning better assist better than raw capability?)
3. **Does iterative assistance work better?** What if the assistant and worker interact in a loop (worker tries, gets feedback, revises)? Single-pass augmentation may not be the right paradigm.
4. **How do human workers differ?** Test this with actual humans at various skill levels—does a weaker model augment better than a stronger one for expert workers?
5. **Can we design augmentation-optimized models?** Could fine-tuning or prompting for "helpfulness to a peer agent" (rather than task performance) yield models that augment better?
6. **Task-specific thresholds**: For each task, is there a minimum worker capability below which augmentation reliably breaks down?

## Key Takeaway
LLMs that automate best don't necessarily help weaker agents perform better—model selection should distinguish between these two jobs.
