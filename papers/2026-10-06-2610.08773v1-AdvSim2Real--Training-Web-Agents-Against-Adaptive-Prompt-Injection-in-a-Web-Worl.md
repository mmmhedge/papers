# AdvSim2Real : Training Web Agents Against Adaptive Prompt Injection in a Web World Model

**Authors:** Sarim Hashmi, Mukul Ranjan, Kshitij Mishra, Mikhail Kuznetsov, Praneeth Vepakomma et al.
**Published:** 2026-10-06 | **arXiv:** [2610.08773v1](http://arxiv.org/abs/2610.08773v1)

## Summary

This paper tackles a critical vulnerability in web agents—software that browses and acts on web pages to complete user tasks. The problem: attackers can inject misleading instructions into web pages to hijack the agent away from its intended goal. The authors present AdvSim2Real, a training method that co-evolves three things together (the agent, an adaptive attacker, and a curriculum of tasks) inside a simulated web environment to make agents robust against prompt injection attacks that they've never seen before.

## Theoretical Background

Web agents operate by reading HTML, understanding user intent, and executing actions (clicking, typing) to accomplish goals. The core challenge is that agents cannot simply ignore web content—they must read it to find task-relevant information, making them vulnerable to adversarial instructions planted on pages.

The paper builds on two established ideas. First, **adversarial training** — the practice of training models against adaptive attackers to improve robustness. Second, **curriculum learning** — the insight that training on progressively harder or more diverse tasks improves generalization. Prior defenses typically use static adversarial examples (fixed attacks known before training), which fail when attackers adapt to the trained model. The paper's innovation is combining these with a **world model** (a simulator of web environments) to make training efficient and scalable.

## Core Contributions

1. **Co-evolutionary training framework**: Instead of fixing either the tasks or the attacks, AdvSim2Real simultaneously evolves the task difficulty, the adversary's injection strategy, and the agent's policy. The curriculum is rewarded for tasks at ~50% agent success rate (the "zone of proximal development"), and the adversary is rewarded only for "success flips"—injections that flip a correct answer into incorrect.

2. **Generalization to unseen attackers**: The trained agent holds robustness against frontier-model adversaries it never trained against, suggesting the learned robustness is not brittle to the specific training attacker.

3. **Sim-to-real transfer**: Improvements in the simulator transfer to a real browser environment, validating that the frozen world model captures realistic dynamics.

4. **Quantified defense gains**: 33.6% relative improvement in completion rate under unseen adversarial attacks on 150 web tasks.

## Connections to Other Work

This work sits at the intersection of several research areas:

- **Web agent robustness**: Related to work on grounding language models in web environments and making them reliable for real-world automation.
- **Prompt injection attacks**: Extends the growing literature on adversarial attacks against language models deployed in open systems ([[RLHF]], alignment research).
- **Adversarial training for RL**: Similar in spirit to adversarial training in [[reinforcement-learning]], but applied to a multi-agent setting where the adversary is part of the environment.
- **Curriculum learning + adversarial training**: Combines two techniques that are often studied separately; the co-evolution insight is novel.
- **Sim-to-real transfer**: Parallels work in robotics and RL on closing the gap between simulation and real-world deployment.

## Practical Applications

1. **Autonomous web automation**: Web scraping, form-filling, and data extraction tools that must resist adversarial website content.
2. **AI-assisted customer service**: Agents that browse knowledge bases or customer data to answer queries, vulnerable to injected misinformation.
3. **Financial research bots**: Agents reading financial websites and reports that could be compromised by planted false information.
4. **E-commerce automation**: Price comparison, inventory checking, and ordering agents that must ignore misleading injected content.
5. **Security testing**: Red-teaming tools that test web applications for injection vulnerabilities via autonomous agents.

## Technical Limitations

1. **Frozen world model**: The method relies on a fixed simulator of web environments. If real web behavior diverges significantly from the simulation (dynamic content, JavaScript rendering, CAPTCHAs), the method's effectiveness may degrade.

2. **Scalability of co-evolution**: Running three co-evolving optimization loops (agent, curriculum, adversary) is computationally expensive. It's unclear how this scales to agents with billions of parameters or vastly larger task spaces.

3. **Definition of "success flip"**: The adversary is only rewarded for flipping successes to failures, which may miss injections that subtly degrade performance without outright failure.

4. **Limited evaluation scope**: Only 150 web tasks tested. It's unclear how robust the agent is to novel task categories or injection styles fundamentally different from training.

5. **Adversary capability ceiling**: The paper doesn't clearly define the space of possible injections. If the true attacker has access to gradient information or can modify the page structure in ways not seen during training, robustness may collapse.

## Open Questions

1. How does performance scale with agent size and task complexity? Can this method scale to state-of-the-art 70B+ models and thousands of diverse tasks?

2. What injection strategies does the co-evolutionary adversary actually discover? Can we interpret and understand what makes the agent robust?

3. Does robustness transfer across different web domains (e-commerce vs. financial vs. news), or is it domain-specific?

4. How sensitive is the method to the curriculum reward threshold (50%)? What happens if you adjust it?

5. Can you formalize the notion of "success flip" more rigorously, and does the adversary exploit this definition in ways that don't reflect real attacks?

6. What is the trade-off between agent capability and robustness? Does maximizing robustness ever hurt the agent's ability to complete legitimate tasks?

## Key Takeaway

Co-evolving agents, attackers, and task difficulty in a web simulator makes agents resistant to unseen prompt injection attacks while improving core capability.
