# MLLM-Routed Heterogeneous Ensembles for Robust Cross-Dataset Image Classification

**Authors:** Daniel Perkins, John Squires, Janou Milligan, Chandra Raskoti, Linda Ungerboeck
**Published:** 2026-08-13 | **arXiv:** [2608.13463v1](http://arxiv.org/abs/2608.13463v1)

## Summary
This paper introduces ARMDIL, a system that uses a multimodal language model to intelligently choose which vision model to apply to each image, rather than using a single model for all images. The ensemble combines convolutional networks, self-supervised models, and vision-language models trained on diverse datasets, improving robustness when images come from different sources or difficulty levels.

## Theoretical Background
Image classifiers traditionally struggle with domain shift — when test images differ visually from training data (e.g., trained on clean photos, tested on sketches or low-light images). Prior work addresses this via domain adaptation, multi-task learning, or ensemble methods that average predictions. Vision-language models (VLMs) like CLIP combine image and text understanding via contrastive learning. Multimodal large language models (MLLMs) extend language models to process images and reason about them in natural language. This paper builds on ensemble learning theory and leverages MLLMs as routing agents rather than just predictors.

## Core Contributions
1. **MLLM-based routing**: Uses an MLLM (not a learned router network) to assign each image to the best specialist model via natural language reasoning — a novel use of foundation models for ensemble control.
2. **Unified label space across datasets**: Harmonizes label semantics across multiple image datasets with different distributions into one shared taxonomy, enabling fair ensemble comparison.
3. **Empirical analysis of architectural trade-offs**: Systematically maps which vision architectures (ResNets, SSL learners, VLMs) excel in which visual domains and failure modes.
4. **Prompt-based adaptability**: Shows the router can integrate new information or task constraints via simple prompt modifications without retraining, contrasting with traditional trained routers.
5. **Interpretability via reasoning traces**: The MLLM's natural language explanations for routing decisions make decisions transparent, unlike black-box routing networks.

## Connections to Other Work
Relates to [[ensemble learning]] and mixture-of-experts approaches, but replaces learned gating networks with foundation model reasoning. Connects to [[domain adaptation]] and [[domain generalization]] literatures addressing distribution shift. Similar in spirit to [[in-context learning]] with MLLMs — using prompts to steer behavior without gradient updates. Differs from [[vision-language models]] as primary classifiers by positioning them as one component in a larger system, and from [[neural architecture search]] by using interpretable routing rather than optimized selection.

## Practical Applications
- **AI assistants and chatbots**: Handling diverse user-uploaded images (photos, screenshots, medical scans, artwork) without per-domain retraining.
- **Autonomous systems**: Robots operating in varied lighting, weather, and terrain conditions — different visual conditions trigger appropriate vision models.
- **Medical imaging**: Route chest X-rays, retinal scans, and pathology slides to architectures optimized for each modality.
- **Content moderation**: Different image types (faces, documents, products) routed to specialized classifiers with better accuracy.
- **Mobile/edge deployment**: Select lightweight vs. powerful models based on image characteristics and device constraints, improving latency and accuracy trade-offs.

## Product & Startup Ideas
1. **Adaptive Vision API**: Cloud service offering MLLM-routed classification as an API; users upload images and get high accuracy across domains without tuning. Monetize via per-request pricing or SLA tiers.
2. **Enterprise multi-domain classifier**: SaaS platform for companies ingesting mixed image types (e-commerce products, user photos, documents) — handles domain heterogeneity out-of-the-box with interpretable routing logs.
3. **Robotics/autonomous vehicle vision stack**: Sell ARMDIL as a plug-in vision backbone that improves perception robustness across lighting, weather, and scene types. License to robotics firms.
4. **Medical imaging triage system**: Route medical images to specialized models, generating confidence scores and explanations for clinician review; target hospitals and diagnostic centers.
5. **Interpretable visual QA assistant**: Consumer app where users ask questions about diverse images; MLLM routes to best vision model and provides natural language reasoning, differentiating on transparency vs. black-box competitors.

## Technical Limitations
- **Computational cost**: Running an MLLM for every image adds latency and compute overhead; may be impractical for real-time mobile or embedded applications.
- **MLLM reliability**: Routing quality depends on the MLLM's own biases and limitations; no guarantees the model will reason about images correctly or consistently.
- **Unified label space assumption**: Forcing diverse datasets into one label taxonomy risks losing domain-specific nuances or introducing label noise where definitions conflict across sources.
- **Specialist model heterogeneity**: Assumes component models are truly diverse; if they fail similarly on edge cases, routing cannot recover. No analysis of failure correlation.
- **Prompt brittleness**: Prompt modifications for new tasks lack principled design; minor wording changes could alter routing unpredictably.
- **Limited scalability of ensemble**: Adding new models requires retraining the unified label space and may degrade existing components if not carefully engineered.

## Open Questions
- How does routing latency scale with ensemble size? Is there a practical ceiling on the number of specialist models?
- Can the MLLM's routing be validated or corrected in a human-in-the-loop setting, and how does feedback improve future routing?
- How sensitive is ARMDIL to prompt design? What systematic methodology ensures robust routing across prompt variations?
- Does the unified label space introduce systematic bias toward any of the source datasets? How does label harmonization quality affect downstream performance?
- Can the system detect when it is uncertain or out-of-distribution, and abstain from classification? Does the MLLM reasoning help with calibration?
- How does ARMDIL compare to recent test-time adaptation or in-context learning approaches that also avoid retraining?

## Key Takeaway
An MLLM dynamically routes images to specialized vision models, achieving robust cross-domain classification with interpretable reasoning and prompt-based adaptability.
