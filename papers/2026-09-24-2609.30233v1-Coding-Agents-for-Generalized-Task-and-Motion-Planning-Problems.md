# Coding Agents for Generalized Task and Motion Planning Problems

**Authors:** Matteo Merler, Bowen Li, Josh Roy, Yichao Liang, Qianwei Wang et al.
**Published:** 2026-09-24 | **arXiv:** [2609.30233v1](http://arxiv.org/abs/2609.30233v1)

## Summary
This paper shows that large language models (LLMs) can automatically generate programs that solve task and motion planning (TAMP) problems — complex robotics challenges involving both discrete decisions and continuous physics constraints — without requiring hand-crafted planning algorithms. By giving coding agents like Claude and GPT access to a simulator and a "thinking budget," the agents learn to write reusable programs that generalize to new problem instances better than traditional planners, even as problem complexity grows.

## Theoretical Background
Task and motion planning (TAMP) combines two hard problems: deciding *what* sequence of high-level actions to take (discrete planning) and *how* to execute each action while respecting physical constraints like geometry and dynamics (continuous motion planning). Traditional approaches use hand-engineered solvers that reason about these constraints symbolically; recent work in generalized TAMP tries to learn patterns across similar problems to speed up planning on new instances. This paper builds on the emergence of [[large-language-models]] as code generators — systems trained on vast text corpora that can write and refine computer programs. The key innovation is treating program synthesis (automatically generating working code) as a way to discover generalizable TAMP solutions through interaction with a physics simulator.

## Core Contributions
1. **Coding agents as TAMP solvers**: First systematic study showing LLMs can synthesize generalizable TAMP programs by exploring a simulator during a fixed "synthesis budget" phase.
2. **Empirical scale**: Evaluated 980 generated programs across 28 environments on 98,000 total episodes — substantially larger evaluation than prior generalized planning work.
3. **Robustness to scaling**: Agent-generated programs maintain success rates as object counts grow beyond training distribution, whereas traditional planners degrade — and use 10× less computation per instance.
4. **Interaction patterns revealed**: Analysis of agent logs shows concrete strategies: calibrating physics models, testing edge cases, and iteratively refining heuristics.
5. **Open release**: Full prompts and code made public, enabling reproducibility and future work.

## Connections to Other Work
This work sits at the intersection of [[large-language-models]] for code generation (e.g., Codex, GitHub Copilot), program synthesis, and robotics. It differs from prior LLM-based planning work that uses language models directly for reasoning; instead, it treats LLMs as *programmers* that learn by doing. It relates to [[reinforcement-learning]] in robotics by using interaction to refine behavior, but avoids explicit RL training loops. The emphasis on generalization across instances connects to meta-learning and few-shot learning paradigms. The work also engages with symbolic TAMP solvers (PDDLStream, classical planners) and newer learned planning baselines, positioning coding agents as a new middle ground.

## Practical Applications
1. **Robot manipulation in variable environments**: Manufacturing or warehouse robots that must adapt to different object sets, layouts, or constraints without retraining.
2. **Autonomous assembly systems**: Programs that generalize across assembly tasks with different part counts or configurations.
3. **Space exploration rovers**: Robots deployed to unknown terrain that must solve novel TAMP instances (movement, manipulation, sensing) with limited computational resources and no option to retrain.
4. **Collaborative robotics**: Robots that learn to work with humans by synthesizing task-specific programs during a brief observation/interaction phase.
5. **Game AI and simulation**: Procedurally generated environments in games or simulations that require adaptive task-motion strategies.

## Product & Startup Ideas
1. **"Generalized Robotics-as-a-Service"**: A cloud platform where users describe a task class (e.g., "pick-and-place with variable object counts"), upload a simulator, and receive a deployed program that runs locally on robots. Charge per task class or per robot deployment.
2. **Interactive robot programming IDE**: A visual tool where roboticists or non-experts describe tasks; an LLM coding agent iteratively builds and tests programs in a simulator, with one-click deployment to real hardware.
3. **TAMP benchmark and certification service**: Offer standardized testing suites (like KinDER) where enterprises can certify that their robotic systems generalize across problem scales before deployment.
4. **Simulator-in-the-loop training platform for robotics startups**: Host physics simulators and LLM-based program synthesis as a service; startups upload task specs, get back generalizable programs, then validate on real robots. Monetize via API calls and compute.
5. **Zero-shot robot adaptation layer**: Middleware that runs coding agents on-device (with a cached LLM or smaller model) to auto-generate task programs when a robot encounters a novel instance, enabling true generalization without cloud connectivity.

## Technical Limitations
1. **Simulator fidelity gap**: Programs learned in simulation may not transfer to real robots due to unmodeled friction, perception noise, and actuator delays — the paper only evaluates in simulation.
2. **Synthesis budget trade-off**: The fixed budget for program synthesis is arbitrary; unclear how to set it adaptively or whether longer budgets plateau in performance.
3. **Scalability to continuous complexity**: Tested on up to ~12 objects; unclear how programs degrade with very large object counts, complex dynamics (deformables, fluids), or high-dimensional state spaces.
4. **Cost and reproducibility**: Depends on proprietary LLMs (Claude, GPT models); results may not hold for open-source or smaller models, and API costs may be prohibitive for large-scale deployment.
5. **Limited failure analysis**: While agent logs show some strategies, there's no systematic analysis of *why* programs fail or how to debug them — important for safety-critical applications.
6. **Comparison scope**: Baseline comparisons are limited to classical planners and one LLM baseline; missing comparisons to learned planning methods (e.g., neural network policies trained with RL) or hybrid approaches.

## Open Questions
1. **Real-world transfer**: Do these programs work on real robots, and if so, how much sim-to-real gap exists? What minimal sim updates are needed?
2. **Explainability and debugging**: Can we extract interpretable insights from generated programs, or provide explanations for failures? How do non-experts debug or modify them?
3. **Scaling laws**: How does success rate scale with object count, state dimensionality, and environment diversity? Is there a fundamental limit?
4. **Theoretical guarantees**: Can we prove bounds on generalization error or characterize when programs are guaranteed to work?
5. **Smaller models and open-source**: Do smaller LLMs or open-source models (Llama, Mistral) achieve similar results, and at what synthesis budget?
6. **Hybrid approaches**: Can we combine coding agents with classical planners (e.g., agent generates heuristics for a planner) to get the best of both worlds?
7. **Multi-agent TAMP**: Can agents synthesize programs that coordinate multiple robots solving shared TAMP instances?

## Key Takeaway
LLM-based coding agents synthesize generalizable robotic task-motion programs better than hand-engineered planners, with low computational cost and scaling robustness.
