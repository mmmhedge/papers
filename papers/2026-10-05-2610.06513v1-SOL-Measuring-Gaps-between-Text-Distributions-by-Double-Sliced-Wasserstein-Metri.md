# SOL: Measuring Gaps between Text Distributions by Double Sliced Wasserstein Metrics

**Authors:** Gregor Kornhardt, Moritz Piening, Jannis Chemseddine, Gabriele Steidl
**Published:** 2026-10-05 | **arXiv:** [2610.06513v1](http://arxiv.org/abs/2610.06513v1)

## Summary
This paper proposes SOL, a new metric for measuring the distance between text distributions using double sliced Wasserstein distance. Current evaluation methods like perplexity work well for autoregressive language models but fail or give loose bounds for diffusion and flow-based models; SOL fills this gap by comparing the distributions of hidden representations from a fixed transformer, providing a principled way to evaluate any generative text model.

## Theoretical Background
The paper builds on optimal transport theory, specifically Wasserstein distances — mathematical tools for measuring how different two probability distributions are. Sliced Wasserstein distance reduces computational cost by projecting high-dimensional distributions onto random lines and computing distances in 1D. Double slicing further optimizes this by learning projection directions. The authors combine this with transformer embeddings — neural networks that encode text into high-dimensional hidden states using attention mechanisms. Traditional evaluation relies on perplexity (a likelihood-based metric), but this breaks down for non-autoregressive models like diffusion models, which only provide lower bounds on likelihood.

## Core Contributions
1. **SOL metric definition**: A principled distance measure between text distributions by representing each sequence as an empirical measure over its transformer hidden states, then comparing these distributions via double sliced Wasserstein distance.
2. **Theoretical grounding**: Proves SOL is a valid metric (satisfies metric properties: non-negativity, symmetry, triangle inequality) when the underlying transformer is injective.
3. **Empirical validation**: Demonstrates SOL detects distributional failures, recovers expected trends across model families, and provides stable sample-based estimates without requiring likelihood computation.
4. **Comprehensive re-evaluation**: Re-evaluates multiple generative models on OpenWebText using SOL, revealing evaluation insights obscured by traditional metrics.

## Practical Applications
1. **Model development benchmarking**: Researchers developing new generative models (especially diffusion, flow, and other non-autoregressive approaches) can use SOL to fairly compare against existing baselines without being penalized by loose likelihood bounds.
2. **Production model monitoring**: Text generation systems in production can track SOL divergence over time to detect when generated text distributions drift from training data, enabling retraining triggers.
3. **Synthetic data quality assessment**: Organizations generating synthetic text data can measure how well their generative model matches the target distribution before using synthetic data for downstream tasks.
4. **Cross-model comparison**: Comparing models trained on different objectives (e.g., autoregressive vs. diffusion) on equal footing for tasks like machine translation or summarization.

## Product & Startup Ideas
1. **Text Model Evaluation SaaS**: A platform offering SOL-based evaluation dashboards for teams training and comparing generative text models, with alerts for distributional drift and automated benchmark reports.
2. **Synthetic Data Quality Assurance Tool**: Software for enterprises generating synthetic text data that validates distribution alignment with real data before deployment, reducing quality risks.
3. **Model-Agnostic Leaderboard**: A public benchmark website similar to Hugging Face Model Hub but using SOL as the primary metric, enabling fair comparison of diffusion, flow, and autoregressive models.
4. **Continuous Model Monitoring Service**: Infrastructure for production text generation pipelines that tracks SOL metrics in real-time, alerts on distributional failures, and recommends retraining.
5. **Research Collaboration Platform**: A tool for academic groups to collaboratively re-evaluate published models using SOL, building a database of model quality scores that corrects for metric bias.

## Technical Limitations
1. **Transformer dependency**: SOL's validity as a metric requires the transformer to be injective (one-to-one mapping), which is unproven and likely false for real transformers with finite capacity and training data.
2. **Computational cost**: Computing double sliced Wasserstein distances requires sampling and projection operations; scalability to very large text corpora or extremely high-dimensional embeddings is unclear.
3. **Hidden state representation choice**: Results depend on *which* transformer layer's hidden states are used; no clear guidance on optimal layer selection is provided.
4. **Limited scope of evaluation**: Experiments focus on OpenWebText; generalization to other domains (code, scientific text, low-resource languages) is unknown.
5. **Gradient flow for learning**: Unlike likelihood-based metrics, SOL (as a sample-based metric) does not provide gradients for direct model training, limiting its use in loss functions.
6. **Finite-sample bias**: Empirical measures computed from finite samples introduce bias; correction strategies are not discussed.

## Open Questions
1. How does injectivity of transformers affect SOL's theoretical guarantees in practice? Can we characterize which architectures or layer depths violate this assumption?
2. How sensitive is SOL to the choice of transformer? Does using different pre-trained models substantially change rankings or comparisons?
3. Can SOL be differentiated w.r.t. model parameters to enable gradient-based optimization, and would this be a viable training objective?
4. How does SOL performance scale with sequence length and vocabulary size? Are there degeneracies for very long documents?
5. How does SOL relate to downstream task performance (e.g., classification accuracy on text generated by evaluated models)? Is distributional alignment predictive of utility?
6. Can SOL be extended to other modalities (images, code, structured data) and does the method generalize cleanly?

## Key Takeaway
SOL uses optimal transport on transformer embeddings to fairly compare generative text models without relying on likelihood, enabling evaluation of diffusion and flow-based models.
