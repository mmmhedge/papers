# One Block, Multiple Depths: Recurrent Vision Transformers with Depth-Programmed Experts

**Authors:** Adrian Bulat, Yassine Ouali, Georgios Tzimiropoulos
**Published:** 2026-10-08 | **arXiv:** [2610.12448v1](http://arxiv.org/abs/2610.12448v1)

## Summary
This paper proposes reViT, a vision transformer that achieves full-depth network accuracy using a single transformer block applied repeatedly, with depth-specific behavior encoded through a mixture-of-experts (MoE) mechanism. Instead of stacking many blocks, the authors reuse one block multiple times and use a "depth coordinate" to blend parameters from a small expert bank, reducing model size by ~70% while maintaining accuracy. This matters because it opens a path to more parameter-efficient vision models and single-checkpoint systems that can operate at multiple computational depths.

## Theoretical Background
Vision transformers (ViTs) apply transformer architecture — neural networks using attention mechanisms to process sequences — to images by treating image patches as tokens. Typically, ViTs stack many identical transformer blocks to build depth. Mixture-of-experts (MoE) systems use a router to select or blend outputs from multiple expert networks based on input, allowing capacity scaling without proportional parameter growth. The paper builds on prior work showing that recurrent application of a single module can approximate deep networks, and extends this by parameterizing the recurrent block as a smooth blend of expert FFN layers (feed-forward networks — the non-attention sublayers in transformers) indexed by a learned depth coordinate. The key insight is that depth-specific transformations can be recovered not by storing separate blocks, but by routing through a continuous parameter space.

## Core Contributions
1. **Depth-programmed experts**: A novel MoE design where each recurrent application of a block uses a normalized depth coordinate to blend expert FFNs (via convex combinations) rather than discrete routing. This creates a smooth, resampleable trajectory through parameter space.
2. **Elastic-depth training**: A single trained checkpoint can operate at multiple depths by simply resampling the same coordinate interval—enabling adaptive computational cost at inference.
3. **Empirical validation of MoE family**: Controlled comparison showing weight-space merging (direct convex blending of expert weights) outperforms token-dispatch and output-mixture MoE variants at fixed parameter budget.
4. **Materialization as dense graph**: The recurrent block can be "unrolled" into a conventional feed-forward graph without online routing, maintaining FLOPs while expanding storage—useful for deployment scenarios.
5. **Competitive results across tasks**: reViT-B/16 matches DeiT III accuracy from scratch with ~70% fewer parameters; when distilled from DINOv2, retains nearly all teacher performance and transfers to segmentation and depth prediction.

## Connections to Other Work
This work sits at the intersection of several active areas: efficient transformers ([[Vision Transformers|ViT]]), [[mixture-of-experts]] scaling, and depth-adaptive neural networks. It relates to parameter sharing schemes and knowledge distillation ([[RLHF]] conceptually shares machinery, though applied differently). The "elastic depth" concept echoes adaptive computation ideas but implements it through expert blending rather than hard routing. The weight-space merging finding contributes to understanding MoE design choices, complementing recent work on merging and unlearning in foundation models.

## Practical Applications
1. **Mobile and edge vision**: Deploying large vision models on constrained devices by running fewer recurrent steps, using the same checkpoint trained for full depth.
2. **Adaptive inference systems**: Real-time classification/segmentation that trade accuracy for speed by choosing depth at inference time (e.g., fast filtering followed by careful inspection).
3. **Transfer learning**: A single DINOv2-distilled checkpoint that works out-of-the-box for classification, segmentation, and depth prediction without retraining.
4. **Model compression for deployment**: Reducing stored model size by 70% enables storing multiple vision models in embedded systems or federated learning scenarios.
5. **Hybrid compute platforms**: Systems mixing high-capacity servers (full depth) with lightweight edge nodes (shallow depth) using the same model.

## Product & Startup Ideas
1. **Adaptive vision API**: Cloud service that auto-scales model depth based on query complexity and latency SLA, charging by actual compute used rather than peak capacity.
2. **On-device video analytics**: SDK for smartphones/cameras that transparently switches vision model depth based on battery, network, and task urgency—same checkpoint for all phones.
3. **Model-as-a-Service compression**: SaaS tool that auto-compresses customer vision models into elastic-depth variants, reducing inference cost and storage without retraining.
4. **Federated learning platform**: Distributed ML system where central coordinator trains a single reViT, broadcasting to heterogeneous edge devices that run different depths based on hardware.
5. **Surgical/medical imaging**: Real-time in-OR vision system that adjusts depth on-the-fly (shallow for real-time preview, deep for diagnostic-quality segmentation) from one model checkpoint.

## Technical Limitations
1. **Expert bottleneck under scaling**: Unclear how the small expert bank scales to very large models or to longer recurrence chains—does depth-programmability degrade with many iterations?
2. **Coordinate design choice**: The paper introduces a "normalized-depth coordinate" but doesn't deeply justify this design or compare to alternatives (e.g., learnable per-layer mixing weights, adaptive routing).
3. **Distillation dependency**: The DINOv2 distillation results are strong, but it's unclear how well the method performs *from scratch alone* at comparable model scales, or on non-vision tasks.
4. **Limited analysis of parameter trajectory**: What does the learned FFN parameter space actually look like? Are there sharp transitions or singular points that break smooth interpolation?
5. **Materialization trade-off**: Unrolling to a dense graph removes online routing overhead but *expands* storage—for many deployment targets (mobile, embedded), the 70% parameter reduction is lost.
6. **Comparison fairness**: Baselines (DeiT III, other efficient ViTs) may not be optimized for the same budget regime; some comparisons conflate parameter count with FLOPs and latency.

## Open Questions
1. How does performance scale if you increase the expert bank size or use heterogeneous experts (e.g., different expert types at different depths)?
2. Can the depth coordinate be made fully learnable or data-dependent, rather than fixed at training time?
3. Does the method work for other domains (NLP, 3D vision) or is the benefit specific to 2D image transformers?
4. What is the actual latency profile on real hardware (TPU, GPU, mobile accelerators) when running recurrent blocks vs. stacked blocks?
5. Can you train a single reViT model that is simultaneously elastic in *both* depth and width (e.g., mixing expert selection with token pruning)?
6. How sensitive is the method to the choice of expert bank size and initialization?

## Key Takeaway
One recurrent transformer block with depth-programmed experts matches deep networks' accuracy while using 70% fewer parameters and enabling single-checkpoint multi-depth inference.
