# Judge, Retrieve, or Abstain: Uncertainty-Guarded LLM Judging with Provable Risk Guarantees

**Authors:** Sher Badshah, Ali Emami, Hassan Sajjad
**Published:** 2026-08-18 | **arXiv:** [2608.17994v1](http://arxiv.org/abs/2608.17994v1)

## Summary
This paper tackles a core problem in using LLMs as automated judges: how to evaluate factual correctness reliably when no reference answer exists. The authors propose a framework that combines parametric judgment (using the LLM's built-in knowledge) with retrieval-augmented judgment (using web search) and routes between them based on calibrated uncertainty thresholds—ensuring that false verdicts stay below a user-specified error rate with mathematical guarantees.

## Theoretical Background
LLMs as judges are now widely used to evaluate open-ended tasks like helpfulness or safety, where subjective assessment is acceptable. But for objective tasks (questions with factually correct answers), this creates a fundamental problem: without a reference answer, how does the judge know if it's right? 

The paper builds on two key ideas: (1) **parametric knowledge**—using the LLM's internal weights to answer questions directly, which is fast but risks hallucination; and (2) **retrieval-augmentation** (e.g., [[Retrieval-Augmented Generation]], [[RAG]])—fetching external evidence to improve accuracy, which costs more computation.

The paper's core novelty is a **risk-control framework** based on finite-sample statistics. It uses Clopper–Pearson confidence intervals (a classical statistical tool for estimating true error rates from finite samples) to calibrate uncertainty thresholds so that the **false discovery rate** (FDR—the fraction of accepted verdicts that are actually wrong) stays below a specified tolerance $\alpha$ with provable guarantees. This is different from just hoping the judge is accurate; it's a formal contract.

## Core Contributions
1. **Risk-controlled two-mode routing**: A framework that automatically decides whether to use parametric judgment alone or escalate to retrieval-augmented judgment, based on the judge's confidence on a held-out calibration set.

2. **Finite-sample guarantees**: Unlike empirical confidence intervals (which assume infinite data), this method uses Clopper–Pearson bounds to guarantee the FDR stays below $\alpha$ even with limited calibration data, with high probability.

3. **Routing without additional assumptions**: The two-threshold routing (parametric mode → retrieval mode) preserves the FDR guarantee without requiring independence assumptions or retraining.

4. **Empirical validation**: Across open-domain QA benchmarks (likely SQuAD-style datasets), the framework maintains the target error rate while keeping coverage substantially higher than baselines that use a single threshold for both modes.

## Connections to Other Work
This relates to several important threads:

- **[[RLHF]] and LLM evaluation**: As LLMs are increasingly trained via reinforcement learning from human feedback, automated judging becomes critical infrastructure; this work makes that infrastructure more trustworthy.
- **Retrieval-augmented generation**: Similar to [[RAG]], but focuses on *when* to retrieve and under what confidence conditions, rather than always retrieving.
- **Calibration and uncertainty**: Connects to broader work on calibrating LLM confidence (e.g., temperature scaling, conformal prediction) but with a focus on controlling a specific error metric (FDR) rather than overall accuracy.
- **Formal verification and risk bounds**: Echoes ideas from conformal prediction and robust statistics—using finite-sample theory to guarantee worst-case behavior.

## Practical Applications
1. **Automated evaluation at scale**: Companies like Anthropic or OpenAI use LLM judges to evaluate model outputs across millions of examples; this ensures those verdicts meet a reliability SLA.
2. **QA system auditing**: Deployed QA systems need to flag uncertain predictions; this framework can route uncertain cases to human review or external sources before the user sees them.
3. **Legal and healthcare document review**: In sectors where errors are costly, the framework can guarantee that accepted classifications (e.g., "this document is compliant") meet a specified false positive rate.
4. **Content moderation at scale**: Social media platforms could use this to auto-moderate with formal guarantees on the error rate of accepted decisions.

## Product & Startup Ideas
1. **"JudgeGuard" SaaS**: A hosted LLM judging service (via API) that clients can use to evaluate their own model outputs with certified error rates—pricing based on target FDR and coverage level.

2. **Enterprise QA auditor**: A tool that plugs into existing QA pipelines (e.g., customer support chatbots) to continuously evaluate correctness with formal guarantees and auto-escalate uncertain cases.

3. **Regulated AI compliance suite**: Software for fintech or healthcare companies to certify that their LLM-based recommendations meet regulatory false positive bounds (e.g., "at most 1% false verdicts").

4. **Web-search-powered fact-checker API**: A fact-checking service that combines LLM judgment with retrieval, routing to web search only when parametric confidence is low, ensuring verified claims.

5. **Interactive LLM training playground**: A tool for researchers/teams to interactively tune the FDR threshold on their own data and automatically calibrate routing, visualizing the tradeoff between error rate and coverage.

## Technical Limitations
1. **Calibration set size**: The finite-sample guarantees only hold if the calibration set is representative of test data; in distribution shift scenarios, guarantees degrade. The paper doesn't address cold-start or out-of-distribution generalization.

2. **Computational cost of retrieval**: The framework assumes retrieval (web search) is always available and cheap enough to call in the second mode; in low-latency or offline settings, this may not be practical.

3. **Judge-dependent**: The thresholds are calibrated per judge (per LLM model and size). Retraining thresholds for each new model or prompt change is required, limiting reusability.

4. **False discovery rate only**: The framework controls FDR (false positives among accepted verdicts) but does not directly control false negatives (cases where the judge abstains when it could have been confident). Some tasks may care equally about both.

5. **Two-mode assumption**: The paper assumes a clean split between parametric and retrieval modes. In practice, the boundary may be fuzzy (e.g., the parametric judge's uncertainty may not align well with "I can verify this with web search").

6. **No handling of ambiguous questions**: Questions with no ground truth or multiple valid answers are not addressed; the framework assumes binary correctness.

## Open Questions
1. How does the framework perform under distribution shift (e.g., when test data drifts from calibration data)? Are there adaptive or online calibration approaches?

2. Can the framework be extended to **cost-aware routing**—balancing FDR guarantees with the computational cost of retrieval?

3. How sensitive is the method to the choice of Clopper–Pearson interval? Would other finite-sample confidence bounds (e.g., Agresti–Coull) yield tighter guarantees with similar simplicity?

4. Can the framework be **multi-stage** (parametric → retrieval → human) while preserving guarantees, and what is the optimal allocation of cases to each stage?

5. What is the relationship between the judge's internal uncertainty (e.g., logit distribution) and the true false discovery rate? Are there judges where parametric confidence is poorly calibrated to correctness?

6. How does this extend to **partial credit** or **continuous correctness scores** rather than binary verdicts?

## Key Takeaway
LLMs can judge factual correctness reliably by routing uncertain cases to retrieval, with mathematical guarantees that errors stay below a specified rate.
