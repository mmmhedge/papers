# KaliBench: A Fine-Grained Benchmark for Cybersecurity Tool Use on Kali Linux with Runtime-Free Verifiable Rewards

**Authors:** Pengfei Li, Naufal Suryanto, Sicheng Zhang, Muzammal Naseer
**Published:** 2026-10-01 | **arXiv:** [2610.02206v1](http://arxiv.org/abs/2610.02206v1)

## Summary
This paper introduces KaliBench, a benchmark for evaluating how well language models can translate natural language requests into executable commands for Kali Linux cybersecurity tools. The work addresses a critical gap: existing evaluations don't measure whether models can generate syntactically correct CLI commands that actually run, which matters because cybersecurity work requires precision at the command line. The authors show that even large models struggle with this task (under 42% accuracy), but that training with their verifiable reward signals significantly improves performance.

## Theoretical Background
The paper builds on two main foundations. First, it extends work on [[large-language-models|LLMs]] as tool-using agents — systems that must select appropriate tools and generate correct invocations to accomplish goals. Prior work has evaluated [[agents|agent]] performance on high-level task completion, but typically doesn't measure the fine-grained correctness of command generation. Second, it draws on [[reinforcement-learning|RL]] training methods, particularly the idea that reward signals derived from deterministic verification (rather than human annotation) can guide model improvement. The critical innovation is recognizing that cybersecurity tool use requires strict verification: a command with a single flag typo is not "close to correct" — it simply fails.

## Core Contributions
1. **KaliBench dataset**: 8,504 natural-language-to-command pairs across 1,642 Kali Linux tools, spanning 23 capability dimensions and 5 security phases — significantly larger and more detailed than prior cybersecurity datasets.
2. **Deterministic verification pipeline**: A multi-stage system combining LLM validation, sandboxed terminal execution, and human refinement that enables reproducible assessment without relying on subjective grading.
3. **Runtime-free verifiable rewards**: A method to generate training signals without actually executing every command, enabling efficient [[reinforcement-learning|RL]] or supervised fine-tuning.
4. **Empirical findings**: Demonstrating that open-weight models plateau around 42% accuracy, and that training with KaliBench rewards can bring an 8B model to 685B MoE-level performance on this task.

## Connections to Other Work
This work sits at the intersection of three areas. It extends [[agents|agent]]-based LLM research (like ReAct, WebShop) by focusing on a specific, high-stakes domain where execution matters. It complements [[alignment|alignment]] research by showing how to construct verifiable reward signals for specialized tasks without expensive human labels. It also relates to instruction-tuning and [[reinforcement-learning|RLHF-style]] training, but with deterministic, domain-specific rewards rather than learned reward models. The emphasis on *executable* correctness parallels concerns in code generation (e.g., HumanEval, MBPP), but extends into real system tools rather than synthetic programming problems.

## Practical Applications
1. **Automated security operations**: LLMs acting as junior analysts, translating analyst queries ("find open ports on 192.168.1.0/24") into correct nmap/nessus commands without human review.
2. **Incident response acceleration**: During active breaches, LLMs generate incident-response tool chains (log analysis, network capture, forensics) with verified correctness, reducing response time.
3. **Security training**: Automated systems that teach junior analysts by generating explanations + executable commands, with guaranteed command validity.
4. **Threat hunting automation**: LLMs discover attack patterns by orchestrating sequences of Kali tools (e.g., reconnaissance → vulnerability scanning → exploitation verification).

## Product & Startup Ideas
1. **"SecurityCopilot for Kali"**: A VS Code-like IDE for penetration testers where you describe attacks in plain English and the system generates and validates executable command sequences, with real-time sandboxed preview.
2. **"Automated Red Team as a Service"**: SaaS platform offering synthetic attack campaigns by fine-tuning models on KaliBench, generating reproducible, auditable attack playbooks for enterprises.
3. **"LLM-Powered Security Lab for Education"**: Online platform where cybersecurity students describe defensive scenarios and the system generates correct Linux/Kali commands to set up lab environments, with instant validation.
4. **"CLI Compliance Checker"**: Enterprise tool that audits security tool usage by checking whether human-generated or AI-generated commands match best practices, using KaliBench as ground truth.
5. **"Fine-Tuning as a Service for Security Teams"**: API service that lets enterprises fine-tune smaller LLMs on their proprietary tools and internal command conventions using the KaliBench methodology.

## Technical Limitations
1. **Scope limitation**: Covers only Kali Linux tools; doesn't generalize to Windows security tools, cloud CLIs (AWS, Azure), or proprietary enterprise tools.
2. **Static benchmark**: Commands are validated against current Kali versions; tool flags and behavior evolve, requiring frequent re-validation.
3. **Alias ambiguity**: The paper handles command aliases, but real-world scripting often relies on tool-specific configurations, environment variables, or piped output that the benchmark doesn't capture.
4. **Semantic gaps**: A syntactically correct command might still be semantically wrong (e.g., scanning the wrong subnet due to misunderstood intent), but the benchmark primarily checks syntax and executability.
5. **Scalability of sandboxed verification**: Validating every training example via terminal execution is slow; runtime-free rewards are an approximation that may miss subtle execution failures.

## Open Questions
1. How well does KaliBench training transfer to *novel* Kali tools or tool versions not seen during fine-tuning?
2. Can the verifiable reward signal be extended to multi-step attack chains where earlier command errors propagate to later steps?
3. How do models perform on ambiguous or underspecified requests where the analyst intent is unclear (e.g., "scan for vulnerabilities" without specifying targets)?
4. Does training on KaliBench degrade performance on non-cybersecurity CLI tasks, or is the learned signal domain-specific?
5. Can this approach scale to proprietary enterprise security tools, where ground-truth command pairs are sensitive or unavailable?

## Key Takeaway
Language models struggle to generate correct Linux commands for security tools, but training on verified reward signals significantly closes this gap.
