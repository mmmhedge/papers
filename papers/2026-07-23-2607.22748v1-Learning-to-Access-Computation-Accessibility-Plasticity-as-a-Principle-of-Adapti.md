# Learning to Access Computation: Accessibility Plasticity as a Principle of Adaptive Intelligence

**Authors:** Zhaowen Fan
**Published:** 2026-07-23 | **arXiv:** [2607.22748v1](http://arxiv.org/abs/2607.22748v1)

## Summary

This paper introduces Accessibility Plasticity, a new principle for how neural networks adapt to new tasks and environments. Instead of only changing weights or adding new computation, the key idea is that systems can reorganize *which existing computations can talk to each other* — like rewiring connections without rebuilding components. The authors show this approach can match performance on sequential learning tasks while requiring fewer parameter changes, suggesting accessibility is as important as capability when building adaptive systems.

## Theoretical Background

Modern neural networks adapt primarily through parameter modification — adjusting weights to fit new data. Recent work has explored conditional computation (turning parts of the network on/off based on input), modularity (organizing networks into reusable pieces), and parameter-efficient adaptation (like LoRA, which makes small adjustments to frozen weights). However, all these approaches still assume the fundamental *structure* of what computations exist is fixed. This paper draws on ideas from neuroscience (synaptic plasticity, where the brain reorganizes connections) and builds on decades of work in dynamic neural systems and adaptive control, but frames the problem differently: distinguishing between *having* a computation and *being able to access* it — two things past work conflates.

## Core Contributions

1. **Formal framework for Accessibility Plasticity**: A relationship-based operational model that treats accessibility modification (rewiring connections between existing modules) as distinct from capability modification (adding new parameters or computation).

2. **Reuse-first adaptation hierarchy**: An empirical principle showing that accessibility changes should be attempted before more costly capability or structural changes, prioritizing computational efficiency.

3. **Proof-of-concept on sequential learning**: Demonstrates on sequential task benchmarks that accessibility-only adaptation can maintain performance while reducing parameter changes, validating the principle's practical value.

## Practical Applications

1. **Continual learning systems**: Robots or embodied agents learning new skills sequentially; rewiring existing motor modules is cheaper than retraining from scratch.

2. **Few-shot domain adaptation**: Quickly adapting vision or language models to new domains by routing information through existing specialist modules rather than fine-tuning.

3. **Resource-constrained edge deployment**: Mobile or IoT systems that can't afford new parameters; reconfiguring which computations activate costs far less than adding capacity.

4. **Multi-task learning**: Systems serving 100s of tasks on-device; accessibility adaptation lets shared computation be repurposed without explosion in model size.

## Product & Startup Ideas

1. **Adaptive neural backbone-as-a-service**: Cloud API that hosts a single large modular network; customers rent "access patterns" to subsets of computation rather than separate models, drastically reducing inference cost and latency.

2. **On-device continuous learning toolkit**: SDK for mobile apps that learn from user behavior in real-time by reorganizing which computations fire, without uploading data or retraining centrally.

3. **Dynamic routing engine for LLM inference**: Middleware that learns which layers/modules in a frozen LLM are most useful for each task, reducing compute per inference while keeping model size constant.

4. **Continual learning for autonomous vehicles**: Platform that lets self-driving fleets adapt to new road conditions, weather, or driving rules by reconfiguring which perception modules are accessible, without costly retraining.

5. **Hardware-agnostic model adaptation**: Tool that automatically discovers which computations in a trained network can be reused on a new device (e.g., moving from GPU to TPU), minimizing recompilation overhead.

## Technical Limitations

1. **Limited scope of evaluation**: Tested only on sequential learning benchmarks; unclear how well accessibility adaptation scales to high-dimensional, real-world tasks (vision, language, robotics).

2. **Overhead not fully characterized**: Rewiring connections requires some mechanism to discover good access patterns. The paper doesn't deeply analyze the cost of *search* vs. cost of parameter modification — swapping one for another might not save compute overall.

3. **Modularity assumption**: The principle assumes meaningful, reusable modules already exist. If the network isn't well-structured modularly to begin with, accessibility changes may be ineffective.

4. **No comparison to baselines**: Missing head-to-head comparison to standard fine-tuning, adapters, or conditional computation on identical tasks, making it hard to assess practical advantage.

5. **Scalability unknown**: Doesn't address how to determine *which* accessibility changes matter in very large networks (billions of parameters), or how search cost grows.

## Open Questions

1. **How do we automatically discover good access patterns?** The paper doesn't propose a learning algorithm for which connections to enable/disable. Is gradient descent sufficient, or do you need discrete optimization?

2. **Does this scale to real modular architectures?** Test on actual multi-head attention, mixture-of-experts, or vision transformers with clear module boundaries. Do accessibility changes outperform fine-tuning in practice?

3. **What is the relationship to network lottery tickets?** Is accessibility adaptation finding a subnetwork, or is it qualitatively different? How does it compare to magnitude pruning or layer-wise retraining?

4. **Can you characterize when accessibility beats capability changes?** Under what task structure, network design, or learning regime is reusing computation cheaper than adding it?

5. **How does this interact with [[knowledge distillation]], [[pruning]], or [[quantization]]?** Could you combine accessibility plasticity with these to get even more efficient adaptation?

## Key Takeaway

Neural networks can adapt by rewiring which computations talk to each other, not just by changing parameters — often more efficiently.
