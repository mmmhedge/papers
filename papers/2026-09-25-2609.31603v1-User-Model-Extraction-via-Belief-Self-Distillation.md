# User Model Extraction via Belief Self-Distillation

**Authors:** Ali Holmov, Yiran Huang, Kirill Bykov, Zeynep Akata
**Published:** 2026-09-25 | **arXiv:** [2609.31603v1](http://arxiv.org/abs/2609.31603v1)

## Summary
This paper introduces Belief Self-Distillation (BSD), a technique that extracts and manipulates implicit user models that LLMs build during conversations. The key finding is that LLMs encode beliefs about who they're talking to, and these beliefs causally influence behavior like refusal decisions — meaning you can change how a model responds to requests by changing what it believes about the user, not just the request itself. This matters for AI safety because it reveals a hidden lever for controlling model behavior.

## Theoretical Background
The paper builds on two existing approaches to understanding neural networks. Linear probing — a simple technique that tries to decode information from neural activations by training a linear classifier on top of frozen features — can tell you what information is *present* in a model's hidden states, but not whether that information is *causally used*. Causal probing (or causal interventions) — where you directly manipulate activations and measure the effect on outputs — answers the causal question but requires careful experimental design. BSD combines these: it learns a compact representation of user beliefs that can both be read out (like probing) and written back in (enabling causal testing). The approach leverages the idea that frozen LLMs can serve as their own supervisors, distilling implicit knowledge from natural conversations without hand-labeled data.

## Core Contributions
1. **BSD framework**: A read-write method that recovers user beliefs as a causally-testable internal state, stronger than linear probing alone because interventions via BSD outperform matched hidden-state steering.
2. **User beliefs shape safety**: Demonstrates that refusal decisions depend on model-inferred user intent, not just request content — a user's identity/beliefs are a causal factor in model behavior.
3. **Cross-model geometry regularity**: Independently trained LLMs converge on shared geometric structures for representing users, suggesting user modeling is a universal learned component rather than model-specific.
4. **No external annotations required**: BSD extracts beliefs from natural conversations using the LLM itself as the learning signal, reducing labeling burden.

## Connections to Other Work
This work extends [[mechanistic-interpretability]] by moving beyond passive observation (probing) to active causal intervention. It relates to work on [[RLHF]] and [[alignment]] by showing that model behavior (especially safety/refusal) is conditioned on latent user models, suggesting that training procedures implicitly encode user-aware decision-making. The geometric convergence result echoes findings in representation learning showing that independent training converges on shared feature spaces. It also connects to work on steering and control — if user beliefs are causally writable, they become a control interface for AI safety.

## Practical Applications
1. **Red-teaming and safety auditing**: Researchers can now systematically test how model refusal changes when user beliefs are manipulated, revealing edge cases in safety training.
2. **Adaptive user interfaces**: Systems could detect and adapt to user beliefs in real-time, personalizing tone or explanation depth without explicit user profiles.
3. **Privacy and fairness audits**: Identify and measure bias in how models infer and respond to different perceived user identities.
4. **Fine-grained access control**: Instead of binary allow/deny, systems could enforce policies that condition on inferred user attributes (e.g., different explanations for different expertise levels).

## Product & Startup Ideas
1. **AI Safety Auditing SaaS**: A platform that runs BSD-style probing on customer LLMs to extract hidden user models and report exploitable inconsistencies in refusal behavior; sell to enterprises needing compliance.
2. **Personalized LLM Middleware**: A proxy layer that reads and manipulates user beliefs on-the-fly to enable context-aware responses (different tone/detail for experts vs. novices) without retraining.
3. **Adversarial Robustness Testing as a Service**: Offer red-teaming via belief manipulation — show customers how their models' safety breaks under different inferred user types.
4. **Interpretability Dashboards for Model Ops**: Real-time visualization of what user beliefs a model is inferring and how they drive decisions; help operators detect drift or bias.
5. **Privacy-Preserving Personalization Engine**: Use BSD to extract minimal user-state representations for personalization without storing explicit user profiles, appealing to privacy-conscious orgs.

## Technical Limitations
1. **Scalability**: BSD requires training a distillation model; computational cost and applicability to very large models or long conversation histories unclear.
2. **Limited to conversational beliefs**: Tested on user beliefs inferred from dialogue; unclear how well it generalizes to other implicit model states (e.g., task-specific knowledge, world models).
3. **Causality assumptions**: Assumes that interventions via the learned representation truly reflect the causal pathway; there could be confounds or redundant channels in the model that BSD misses.
4. **Model-family specificity**: While cross-model geometry is observed, method may still require retraining per model family; generalization to unseen architectures untested.
5. **Circular evaluation**: Uses the LLM as its own teacher; if the model's implicit beliefs are inconsistent or contradictory, BSD may learn noisy or aliased representations.

## Open Questions
1. Can BSD extract more complex multi-faceted user models, or does it collapse to a lower-dimensional space? How does performance degrade with increasing user-model complexity?
2. Does the cross-model geometry persist under distribution shift (e.g., out-of-domain users, adversarially-constructed profiles)? How robust is the shared structure?
3. Can similar techniques extract and manipulate other implicit model states (reasoning style, domain expertise, goals) beyond user identity?
4. What is the causal pathway: does the user-belief representation directly gate refusal decisions, or does it indirectly influence them through intermediate computations?
5. How do model-training procedures (RLHF, DPO, etc.) shape the geometry of user models? Are certain training methods more or less likely to produce shared geometric structures?

## Key Takeaway
LLMs secretly build models of who you are, and changing that belief directly changes whether they refuse—revealing a new lever for AI safety and control.
