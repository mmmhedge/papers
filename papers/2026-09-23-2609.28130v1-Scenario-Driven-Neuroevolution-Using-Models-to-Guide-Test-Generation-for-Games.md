# Scenario-Driven Neuroevolution: Using Models to Guide Test Generation for Games

**Authors:** Gijs van Cuyck, Patric Feldmeier, Jan Tretmans, Gordon Fraser
**Published:** 2026-09-23 | **arXiv:** [2609.28130v1](http://arxiv.org/abs/2609.28130v1)

## Summary
This paper combines neuroevolution (evolutionary algorithms that train neural networks) with model-based testing to automatically generate test cases for video games. Instead of trying to cover every code branch exhaustively, the approach lets testers define desired gameplay scenarios as abstract models, then evolves neural network agents to replicate that behavior while improving code coverage by 7%. This matters because testing games is harder than testing traditional software — games have randomness, complex state spaces, and branch coverage doesn't correspond to meaningful gameplay.

## Theoretical Background
The paper builds on **neuroevolution** — a technique from evolutionary computation that uses genetic algorithms to optimize neural network weights and architectures. Prior work (Neatest) applied neuroevolution to game testing by evolving networks that generate dynamic test inputs based on current game state, improving over static random input generation. **Model-based testing** is a complementary approach from formal methods where testers specify abstract models of intended system behavior, then generate concrete tests that satisfy those models. The key insight is combining these: use neuroevolution guided by behavioral models rather than purely by code coverage metrics.

## Core Contributions
1. **Scenario-driven guidance**: Proposes augmenting Neatest with abstract game models that let testers define *what* they want to test (e.g., "reach level 3") rather than *which* code paths to cover. This shifts optimization from code-centric to behavior-centric.
2. **Scalability improvement**: Model-based guidance avoids the combinatorial explosion of trying to cover every branch independently; instead, agents optimize toward high-level scenarios, reducing search space.
3. **Empirical validation**: Demonstrates on 13 Scratch games that the hybrid approach achieves 7% higher branch coverage than code-only Neatest while also producing agents that replicate intended gameplay, not just random coverage.

## Connections to Other Work
This bridges [[reinforcement-learning]] (agents learning to control game behavior) and [[optimization]] (evolutionary algorithms tuning network policies). It relates to work on **search-based software testing** and **automated test generation**, which traditionally optimize for code metrics. The model-based angle connects to formal methods and specification-guided testing. Unlike pure RL approaches that require explicit reward functions, this approach extracts implicit rewards from behavioral model traces.

## Practical Applications
1. **Game QA automation**: Studios can define high-level test scenarios (narrative branches, difficulty modes) and auto-generate robust test agents that explore those scenarios while catching edge cases.
2. **Regression testing**: When games are patched, evolve new agents against existing model definitions to ensure functionality isn't broken.
3. **Accessibility testing**: Define model scenarios for players with different accessibility needs (colorblind modes, control schemes) and verify the game behaves correctly.
4. **Localization testing**: Test games in multiple languages by defining scenario models that exercise UI, dialogue, and branching logic independent of code coverage.

## Product & Startup Ideas
1. **GameTest.ai**: SaaS platform where indie/mid-tier game studios upload builds, define scenario models via a visual editor, and receive auto-generated test suites with coverage reports and video replays of failing scenarios.
2. **Neuroevolution Test Agent Marketplace**: Pre-built, retrained neural network agents for common game genres (platformers, RPGs, puzzle games) that studios can fine-tune on their specific titles.
3. **Model-to-Test Compiler**: Developer tool that ingests formal game specifications (e.g., in a domain language) and automatically compiles them to neuroevolution test configurations, then runs agents in CI/CD pipelines.
4. **Cross-platform Game Testing**: Service that evolves agents for games across mobile, console, and web, ensuring consistent behavior under platform-specific randomness and input latencies.
5. **Accessibility Compliance Tester**: Specialized tool that generates test agents for accessibility scenarios (WCAG compliance, controller support) and flags violations automatically.

## Technical Limitations
1. **Model definition burden**: Requires human expertise to write accurate abstract game models; for complex games, specifying all meaningful scenarios is labor-intensive and error-prone.
2. **Game-specific neuroevolution**: No evidence the approach generalizes across very different game types; each genre may need hyperparameter tuning or network architecture changes.
3. **Scalability to large codebases**: While 13 games is a reasonable sample, they are Scratch games (typically smaller). Unclear if the approach scales to AAA-scale games with millions of lines of code and deeply nested randomness.
4. **Randomness handling**: The paper assumes neuroevolution can learn robust policies despite game randomness, but heavy RNG (procedural generation, complex physics) may make convergence prohibitively slow.
5. **Coverage vs. semantics gap**: Even with model guidance, 7% improvement is modest; achieving *both* high code coverage and semantically meaningful tests may remain fundamentally hard.
6. **Reproducibility**: Neural network training is stochastic; repeatability and determinism for regression testing may be fragile.

## Open Questions
1. How does performance scale to games with millions of branches or complex procedural generation?
2. Can the approach automatically *synthesize* game models from unspecified games (inverse problem), or does every game require manual model authoring?
3. How sensitive is the method to hyperparameters of the neuroevolution algorithm (population size, mutation rate, selection pressure)?
4. Does the learned policy generalize if the game code changes slightly, or must agents be re-evolved after every patch?
5. Can this be combined with search-based testing techniques (e.g., genetic algorithms on input sequences directly) to compare sample efficiency?
6. What is the minimum model complexity (abstraction level) needed to guide effective test generation for different game genres?

## Key Takeaway
Evolving neural network game agents guided by human-defined behavioral models generates better tests faster than chasing every code branch.
