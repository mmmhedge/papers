# LP-NAS: Linear Programming-based Neural Architecture Search

**Authors:** Abhishek Shukla, Ankur Sinha, Faiz Hamid
**Published:** 2026-08-14 | **arXiv:** [2608.14472v1](http://arxiv.org/abs/2608.14472v1)

## Summary
This paper proposes LP-NAS, a method for automating neural network design by formulating architecture search as a linear programming problem. Instead of manually designing networks, the algorithm automatically discovers good architectures by using gradient and curvature information from training to guide the search, achieving better results than existing methods like DARTS.

## Theoretical Background
Neural Architecture Search (NAS) automates the design of neural network structures—the arrangement and types of layers. Early NAS methods were computationally expensive because they treated architecture design as a discrete choice problem. Differentiable NAS relaxes this into a continuous optimization problem, making it faster to solve. The key insight in this paper is applying linear programming—a classical optimization technique for problems with linear constraints and objectives—to guide architecture updates by using the validation-loss gradient (first-order information) and training-loss Hessian (second-order curvature information). DARTS is a prominent differentiable NAS baseline that uses gradient descent; this work improves upon it by using richer optimization theory.

## Core Contributions
1. **LP-NAS framework**: Formulates the architecture update step as a linear program that maximizes generalization while keeping model parameters optimal—a novel mathematical perspective on NAS.
2. **Efficient variants**: Introduces S-LP-NAS and R-LP-NAS, computationally practical versions that avoid expensive Hessian computation while retaining benefits.
3. **Empirical speedup**: Demonstrates faster convergence and better validation performance in early search iterations compared to DARTS and variants (P-DARTS, PC-DARTS, STO-DARTS).
4. **Transferability**: Validates that architectures discovered on CIFAR-10/100 transfer effectively to ImageNet, showing the method finds genuinely good designs, not dataset-specific artifacts.

## Connections to Other Work
LP-NAS sits within the differentiable NAS family, improving upon [[DARTS]] by using second-order information (Hessian) rather than first-order (gradients alone). It relates to broader work on continuous optimization in neural architecture design and shares conceptual ground with other Hessian-based neural network optimization methods. The use of mathematical programming (linear programming specifically) for neural network design is less common than gradient-based methods, positioning this as a bridge between classical optimization theory and modern deep learning.

## Practical Applications
- **AutoML platforms**: Reducing human effort in designing networks for new tasks (image classification, object detection, segmentation).
- **Embedded/mobile deployment**: Discovering efficient architectures for resource-constrained devices by optimizing for both accuracy and model size.
- **Domain-specific vision models**: Automating architecture discovery for medical imaging, satellite imagery, or industrial inspection without manual engineering.
- **Rapid prototyping**: Accelerating time-to-market for vision applications by automating the trial-and-error phase of network design.

## Product & Startup Ideas
1. **AutoML SaaS for vision tasks**: A cloud platform where users upload image datasets and receive optimized architectures in hours instead of weeks of manual experimentation.
2. **Edge AI compiler**: Tool that discovers and deploys efficient neural architectures directly onto edge devices (phones, cameras, IoT), with LP-NAS as the optimization backend.
3. **Computer vision model marketplace**: Pre-discovered architectures optimized for specific domains (medical, retail, autonomous vehicles) sold as modular building blocks.
4. **Hyperparameter & architecture co-optimizer**: Extend LP-NAS to jointly optimize network structure and training hyperparameters, offering a unified AutoML solution.
5. **Hardware-aware NAS service**: Specialize LP-NAS to discover architectures optimized for specific hardware (TPU, GPU, custom chips), targeting enterprises with heterogeneous infrastructure.

## Technical Limitations
- **Linear programming assumption**: The method assumes the architecture update problem can be well-approximated as linear; this may not hold in highly non-convex regions of the search space.
- **Hessian computation cost**: Even though S-LP-NAS and R-LP-NAS are efficient variants, computing or approximating the Hessian still adds overhead compared to pure gradient methods; scalability to very large networks unclear.
- **Search space specificity**: While claimed applicable to "wide range" of continuous spaces, experiments focus on DARTS spaces; generalization to other NAS formulations (e.g., weight-sharing, one-shot methods) not explored.
- **Transferability scope**: Validation is limited to vision tasks (CIFAR, ImageNet); effectiveness on other domains (NLP, audio, multimodal) unknown.
- **Early-stopping bias**: Faster early convergence doesn't guarantee better final architectures; some noise/exploration might be sacrificed.

## Open Questions
- How does LP-NAS scale to much larger networks (e.g., transformer-scale architectures or multi-billion parameter models)?
- Can the linear programming framework be extended to multi-objective optimization (e.g., accuracy vs. latency vs. energy simultaneously)?
- Does LP-NAS benefit tasks beyond image classification (segmentation, detection, reinforcement learning policy search)?
- How sensitive is the method to hyperparameter choices in constructing the linear program (e.g., which second-order information to include)?
- Can this approach discover architectures that are robust to distribution shift or adversarial perturbations?

## Key Takeaway
Using linear programming to guide architecture search achieves faster, more accurate neural network discovery than gradient-only methods.
