# The Bitter Lesson of Tool Calling

**Authors:** Ishan Patel, Sahil Sen, Elias Lumer, Vamse Kumar Subbiah
**Published:** 2026-08-06 | **arXiv:** [2608.06370v1](http://arxiv.org/abs/2608.06370v1)

## Summary
Tool use transforms LLMs into agents that act beyond their training data, and for code-capable models, programmatic tool calling extends this further by replacing rigid JSON calls with scripts that chain and parallelize naturally. However, a systematic evaluation of tools as code on an established benchmark across current and prior model generations under real-world task conditions has not been conducted. In this work, we empirically compare programmatic tool calling (PTC) to native JSON tool calling across 14 language models on BFCL v4.

## Theoretical Background
AI agents combine a language model with tools, memory, and an execution loop. Their quality depends not only on individual answers but on decisions made across a complete trajectory, which makes evaluation and debugging harder than ordinary text generation.

The paper is positioned against prior approaches described in its abstract and asks whether a more targeted representation, evaluation method, or optimization procedure can improve the relevant trade-off.

## Core Contributions
1. Our results demonstrate that programmatic tool calling is a viable and robust alternative to JSON tool calling, with performance tracking model capability across release generations.
2. Tool use transforms LLMs into agents that act beyond their training data, and for code-capable models, programmatic tool calling extends this further by replacing rigid JSON calls with scripts that chain and parallelize naturally.
3. However, a systematic evaluation of tools as code on an established benchmark across current and prior model generations under real-world task conditions has not been conducted.

## Technical Limitations
This note is based on the title, metadata, and abstract rather than a full-paper audit. The abstract cannot establish implementation completeness, statistical robustness, or whether all baselines were tuned comparably. Reported gains may depend on the selected datasets, models, task definitions, and compute environment. Deployment would require independent validation on out-of-distribution inputs, measurement of total runtime and cost, and analysis of failure cases. Any high-stakes use would also need human oversight and domain-specific governance.
