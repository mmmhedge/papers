# Chain-of-Experience for Continual LLM Improvement

**Authors:** Haoqin Tu, Yunhao Fang, Yizhong Wang, Cihang Xie, Shen Yan
**Published:** 2026-08-18 | **arXiv:** [2608.18027v1](http://arxiv.org/abs/2608.18027v1)

## Summary
This paper studies how large language models can improve their performance through iterative test-time feedback—a capability called Chain-of-Experience (CoE). Rather than using models once at inference, the authors show that LLMs can learn and adapt by receiving feedback (from themselves or external signals) and refining their outputs across multiple iterations, achieving measurable gains in math, coding, and knowledge tasks while reducing computational costs.

## Theoretical Background
The work builds on several foundations: test-time adaptation, where models adjust behavior during inference rather than only at training; reinforcement learning principles, where agents improve through feedback loops; and the broader tradition of chain-of-thought reasoning, where LLMs generate intermediate steps to solve problems. The key insight is that feedback—whether from self-reflection, correctness signals, or environmental validation—can drive continuous improvement without retraining. This extends prior work on in-context learning (where models adapt within a single prompt) to multi-turn iterative refinement.

## Core Contributions
1. **Formal framing of Chain-of-Experience**: A structured evaluation paradigm for measuring LLM improvement through iterative test-time feedback, distinct from zero-shot or few-shot baselines.
2. **Multi-feedback mechanism study**: Systematic evaluation of self-feedback, correctness signals, and environmental feedback (e.g., coding test pass rates) across 8 state-of-the-art models (GPT-5, Gemini-2.5 Pro, Claude-4.5 Sonnet).
3. **Quantified improvements**: Demonstrates 5.6% overall accuracy gain and 19% API cost reduction through iterative refinement, with analysis showing most gains emerge in early iterations.
4. **Robustness analysis**: Shows models remain effective even with weak or spurious feedback, and identifies distinct roles for different feedback types.

## Connections to Other Work
This relates to [[Chain-of-Thought]] prompting (intermediate reasoning steps) but extends it to multi-turn adaptation. It echoes reinforcement learning feedback loops and connects to [[RLHF]] (reward-based model alignment), though without explicit retraining. The work also touches [[in-context learning]] but at a coarser grain—full iterative episodes rather than single-prompt adaptation. It shares spirit with test-time optimization strategies in other domains and complements recent work on LLM self-correction and collaborative reasoning.

## Practical Applications
1. **Interactive coding assistants**: Real-time bug fixing where the model iteratively refines solutions using test suite feedback until all tests pass.
2. **Math tutoring systems**: Students receive step-by-step corrections; the model iteratively improves explanations based on "correctness" signals from worked solutions.
3. **Research paper writing tools**: Iterative refinement of paper sections based on internal consistency checks and citation correctness signals.
4. **API-metered applications**: Reduced inference cost by achieving higher accuracy per API call through structured iteration rather than retry loops.
5. **Enterprise knowledge systems**: Continual refinement of retrieval-augmented generation outputs by incorporating user feedback and document relevance signals.

## Product & Startup Ideas
1. **CoE-as-a-Service API**: Wrap popular LLMs in an iteration layer—users submit tasks with feedback signals (tests, correctness labels, reward functions) and pay per iteration, not per call. Lower total cost than single-pass inference for complex tasks.
2. **Iterative Coding Copilot**: IDE plugin that treats code generation as a loop: generate → run tests → refine → repeat. Focuses on test-pass rate as feedback. Monetize per successful refinement cycle.
3. **AI Research Assistant Platform**: Tools for lit review, hypothesis refinement, and experiment planning that use multiple feedback channels (relevance, novelty, logical consistency). Subscription model for researchers.
4. **Self-Improving QA System**: Deploy internal knowledge bases that iteratively improve answers by tracking user satisfaction, correctness, and follow-up queries—model improves with each user interaction.
5. **Adaptive LLM Router**: Route requests through iterative refinement pipelines based on task complexity and feedback availability, optimizing for cost/accuracy trade-off. B2B SaaS targeting enterprises with high inference volumes.

## Technical Limitations
1. **Feedback availability**: Real-world tasks may lack clear correctness signals or environmental validation. Math and coding have well-defined answers; open-ended tasks (writing, translation) lack objective feedback.
2. **Iteration overhead**: Multiple rounds introduce latency and API costs accumulate if iteration inefficient. The 19% cost saving assumes optimal feedback density—sparse or noisy feedback could erode gains.
3. **Model capacity ceiling**: Improvement capacity correlates with base model ability; weaker models plateau faster. For small or specialized models, iterative gains may saturate quickly.
4. **Feedback quality dependency**: Robustness to weak feedback is tested, but adversarial or systematically biased feedback could misdirect refinement.
5. **Scalability to long contexts**: Unclear how CoE scales to reasoning tasks requiring deep context windows or multi-document analysis where feedback becomes complex to define.
6. **Generalization**: Gains shown on math, coding, and knowledge domains—not tested on reasoning-heavy or creative tasks where feedback is ambiguous.

## Open Questions
1. Can CoE be combined with in-context exemplars or retrieval-augmented generation for even larger gains?
2. How sensitive is improvement to the *order* of feedback types or to temporal spacing of iterations?
3. Can models learn a meta-policy for *when to stop iterating* versus continuing?
4. Does CoE transfer across domains—does a model trained to iterate on math problems improve on coding without re-tuning?
5. What happens with truly adversarial feedback? Is there a phase transition in robustness?
6. Can we theoretically characterize the relationship between base model capability and improvement slope?

## Key Takeaway
LLMs can learn and improve through iterative test-time feedback, achieving 5.6% accuracy gains and 19% lower inference costs without retraining.
