# Progressive Skill Discovery as Access Control for Tool-Using LLM Agents: Structural Governance through Role-Scoped Capability Delivery

**Authors:** Michael Stettler, Benjamin Girardet, Jonas Canton, Nicolas Corod
**Published:** 2026-09-23 | **arXiv:** [2609.28693v1](http://arxiv.org/abs/2609.28693v1)

## Summary
This paper addresses a critical safety problem: LLM agents given access to large tool sets become unpredictable and hard to govern, with prompts providing only probabilistic guidance rather than hard constraints. The authors introduce skilder, a framework that bundles tools into role-scoped capability packages that agents must explicitly discover and request, ensuring that governance rules are enforced at the system level rather than left to the model's discretion.

## Theoretical Background
The work builds on two established problems in AI systems. First, there is the challenge of [[tool-use in LLMs]] — models that can invoke external functions to accomplish tasks — which has grown from simple function-calling to managing enterprise-scale tool ecosystems. Second, there is the broader problem of [[alignment]] in autonomous agents: ensuring that systems follow human-defined policies even when those policies are costly or inconvenient. Prior approaches relied on either centralizing all tools (leading to massive context windows and poor selection) or decentralizing through multi-agent orchestration (which creates audit and compliance gaps). The paper frames the core issue as one of access control — a concept borrowed from operating systems and information security — applied to LLM capability delivery.

## Core Contributions
- **Role-scoped capability model**: Tools, instructions, and constraints are bundled into roles that agents must discover and request, rather than all being available by default.
- **Deterministic enforcement layer**: By delivering tools only within explicitly learned skills through a single MCP server, the system guarantees that unauthorized tool calls and parameter violations cannot execute — moving governance from probabilistic prompt guidance to hard system-level constraints.
- **Dynamic cross-role capability acquisition**: Agents can still request additional capabilities mid-task, preserving flexibility while maintaining clear audit trails and policy boundaries.
- **Empirical validation**: Evaluation across 13 tasks and six models shows zero unauthorized calls or policy violations when the discovery protocol is followed, with no false positives in the authorization layer.

## Connections to Other Work
This work sits at the intersection of [[multi-agent systems]], [[agents|agent governance]], and [[alignment]]. It addresses similar concerns to [[RLHF]] and constitutional AI (enforcing human preferences), but at a structural/architectural level rather than through training. It relates to capability control mechanisms in robotics and autonomous systems, and borrows the principle of least privilege from classical information security. Unlike purely prompt-based approaches (which remain probabilistic), skilder treats governance as a system design problem analogous to operating system security kernels.

## Practical Applications
- **Enterprise AI assistants**: Companies can safely deploy LLM agents to handle HR, finance, or operations tasks without fear of tool misuse or policy violations (e.g., preventing spending-limit overruns).
- **Regulated industries**: Financial services, healthcare, and government can use role-scoped delivery to satisfy compliance requirements (SOC 2, HIPAA) with mathematically verifiable audit trails.
- **Multi-tenant SaaS platforms**: Role-based access ensures that a single LLM agent instance can serve customers with different permission models without cross-tenant leakage.
- **Progressive privilege escalation workflows**: Tasks that start simple can dynamically request additional capabilities as needed, without requiring human re-authorization at each step.

## Product & Startup Ideas
1. **Enterprise LLM Agent Governance Platform**: A hosted service that wraps existing LLM agents with skilder-like role management, offering turn-key compliance for companies running internal AI assistants (target: Fortune 500 finance/ops teams).
2. **Skill Marketplace for LLM Agents**: A curated registry where organizations publish pre-vetted, role-scoped skill bundles (e.g., "expense-approval-within-$5k") that other enterprises can safely adopt, with built-in audit and liability insurance.
3. **Zero-Trust LLM Orchestration**: A platform for regulated industries that treats every tool call as potentially hostile, requiring explicit justification and multi-signature approval before execution — akin to hardware security modules for AI.
4. **Compliance-as-Code for AI**: Developer tools that let companies define governance policies in a domain-specific language, automatically generate role hierarchies, and enforce them via skilder-like infrastructure.
5. **LLM Agent Sandbox & Testing**: A CI/CD tool for teams building LLM agents, providing policy simulation and breach detection before production deployment — analogous to security scanning in DevOps.

## Technical Limitations
- **Discovery overhead**: Agents must explicitly learn and request roles, which adds latency and may fail if the model doesn't understand the discovery protocol or misclassifies what roles a task needs.
- **Role definition brittleness**: The framework assumes roles are well-defined in advance; in novel or ambiguous scenarios, agents may request the wrong role or face deadlock if a task genuinely requires capabilities not bundled together.
- **MCP server as single point of failure**: All tool delivery flows through one server, making it a bottleneck and a security target; the paper does not discuss replication, failover, or Byzantine-resilient delivery.
- **Limited to rule-based constraints**: The framework enforces hard bounds (e.g., spending limits), but cannot capture nuanced contextual policies (e.g., "approve only if the requester has been with the company for >1 year"), which still rely on prompt or downstream logic.
- **Evaluation on synthetic tasks**: The 13 tasks tested are controlled; real-world enterprise workflows may involve unforeseen tool combinations or adversarial edge cases not covered.

## Open Questions
- How does skilder scale to hundreds or thousands of roles? Is there a principled way to organize role hierarchies to minimize agent discovery time?
- Can the framework be extended to handle probabilistic policies (e.g., "approve 80% of requests below threshold")? 
- How robust is the system to prompt injection or jailbreak attempts that try to trick the agent into bypassing role boundaries?
- What is the human overhead in defining roles, and can role schemas be inferred from existing tool catalogs or policy documents?
- Does agent performance degrade significantly if roles are intentionally over-scoped (to reduce discovery burden) versus under-scoped (to maximize security)?
- How does this interact with [[reinforcement-learning|fine-tuned or RLHF-trained]] models that have learned to exploit loopholes in previous governance schemes?

## Key Takeaway
LLM agents can enforce enterprise tool policies through structured role discovery and system-level access control, eliminating governance failures from mere prompts.
