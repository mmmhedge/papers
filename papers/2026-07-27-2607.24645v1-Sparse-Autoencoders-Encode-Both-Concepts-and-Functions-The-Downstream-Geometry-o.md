# Sparse Autoencoders Encode Both Concepts and Functions: The Downstream Geometry of Feature Effects

**Authors:** Phu Gia Hoang, Anwoy Chatterjee, Tanmoy Chakraborty, Iryna Gurevych, Subhabrata Dutta
**Published:** 2026-07-27 | **arXiv:** [2607.24645v1](http://arxiv.org/abs/2607.24645v1)

## Summary
This paper investigates why sparse autoencoders (SAEs)—tools designed to extract interpretable features from neural networks—often fail to reliably steer model behavior even when their features appear meaningful. By analyzing how individual feature interventions change model outputs across different contexts, the authors find that most features don't act as simple, reusable directions; instead, their effects depend heavily on context. This challenges the assumption that interpretability and causal control are tightly linked.

## Theoretical Background
Sparse autoencoders are neural networks trained to reconstruct a model's internal activations using relatively few active "features" at a time, making those features easier to interpret. Prior mechanistic interpretability work studied feature geometry *inside* models—how features cluster and relate in the representation space. This paper extends that to "downstream geometry"—what happens to model outputs (logits) when you remove or modify features. The work builds on the premise that understanding *why* features matter requires not just knowing what they encode, but how changing them affects predictions across varied contexts.

## Core Contributions
1. **Feature-Effect Geometry Analysis (FEGA)**: An unsupervised method that removes SAE features and maps the resulting distribution of logit changes, revealing whether effects are stable or context-dependent.
2. **Value-like vs. pointer-like features**: A novel distinction—value-like features encode static information (e.g., facts) and produce structured, low-dimensional effects; pointer-like features handle context-dependent operations and exhibit diffuse, variable effects.
3. **Finding that interpretability ≠ causality**: Features can be clearly interpretable (activating on recognizable concepts) yet have unstable causal effects on outputs, breaking a common assumption in interpretability research.

## Connections to Other Work
This paper directly addresses limitations in [[mechanistic interpretability]] frameworks that assume features map one-to-one onto human-understandable concepts and behaviors. It relates to ongoing debates about [[feature attribution]] and whether neural network features are truly "directions" in representation space (as studied in work on linear representation hypothesis). The distinction between value and pointer semantics echoes ideas in program semantics and cognitive science about static vs. dynamic information processing.

## Practical Applications
- **Model auditing**: Identifying which features can reliably be used to steer models (e.g., reducing bias or toxicity) vs. which will produce inconsistent results.
- **Debugging neural networks**: Understanding why certain interventions work in some contexts but fail in others helps engineers fix unexpected model behaviors.
- **Safety-critical systems**: Before deploying model steering techniques for alignment or safety, practitioners need to know which features actually control behavior reliably.

## Product & Startup Ideas
1. **Interpretability debugging tool**: A SaaS platform that applies FEGA to customer models, reporting which features are "steerable" vs. "context-dependent," with visualizations for steering stability.
2. **Feature-guided model refinement**: A service that identifies value-like vs. pointer-like features and recommends surgical fine-tuning targets for steering specific behaviors.
3. **Mechanistic safety testing**: Automated testing suite for LLM deployments that validates whether safety features (encoded as SAE features) work consistently across prompt contexts before production.
4. **Interactive feature explorer**: Web tool for researchers/practitioners to interactively remove SAE features and see real-time logit distributions, similar to existing model probing tools but with effect geometry focus.
5. **Adversarial steering detection**: Software that identifies features whose effects vary wildly across contexts, flagging potential vulnerabilities in steering-based safety measures.

## Technical Limitations
- **SAE dependency**: Results depend on SAE quality and training; poor SAE training could misrepresent the true feature geometry of effects.
- **Context scope**: Analysis is limited to contexts in the test set; extremely rare or adversarial contexts may reveal different geometry not captured here.
- **Scalability**: Computing effect distributions across all features and all prompt contexts is expensive; unclear how this scales to very large models or datasets.
- **Causality vs. intervention**: Removing features is indirect; measuring causal effects ideally requires interventional experiments on model weights, not just activation suppression.
- **Value/pointer distinction**: The categorization is heuristic-based; intermediate or hybrid features may not fit cleanly, and the boundary is not formally defined.

## Open Questions
1. **Why do pointer-like features behave diffusely?** Is this fundamental to their role, or an artifact of SAE training?
2. **Can we predict effect geometry from feature text descriptions?** Can we build classifiers that identify steerable features without computing full effect distributions?
3. **How do effect geometries change across model scales or architectures?** Are value/pointer distinctions consistent in very large models or different transformer variants?
4. **Can we design SAEs that prefer steerable features?** Can the training objective be modified to encourage value-like structure?
5. **Do attention heads or other internal structures show similar value/pointer splits?** Is this a general principle of neural computation?

## Key Takeaway
Most neural network features don't steer reliably across contexts; interpretability and causal control are separate properties that deserve independent study.
