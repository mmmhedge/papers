# Vero: Can AI Agents Build Formally Verified Software Repositories?

**Authors:** Zhe Ye, Hantao Lou, Yuechun Sun, Peiyang Song, Zhengxu Yan et al.
**Published:** 2026-08-13 | **arXiv:** [2608.13522v1](http://arxiv.org/abs/2608.13522v1)

## Summary
This paper introduces Vero, a benchmark for evaluating whether AI agents can generate both correct code implementations *and* formal mathematical proofs across real multi-module software repositories. Current state-of-the-art agents solve only 27 of 43 test cases, revealing that building trustworthy, formally verified software at scale remains an open challenge for AI.

## Theoretical Background
Formal verification — the practice of mathematically proving that code satisfies its specification — has long been a gold standard in safety-critical systems like cryptographic protocols and distributed systems. Existing work on AI-assisted code generation focuses either on single functions or on proof generation given an already-implemented solution. The key insight here is that real software is *modular*: functions depend on each other across files, and coherent choices in both implementation *and* proof are needed simultaneously. This paper treats verified software synthesis as a multi-module, end-to-end problem requiring agents (AI systems that can plan, act, and reason across multiple steps) to navigate complex formal proof environments like Lean 4 and Dafny.

## Core Contributions
1. **Vero benchmark**: The first repository-scale dataset for joint code-and-proof synthesis, with 43 instances spanning Python, Dafny, Verus, and Coq source material, all expressed as Lean 4 multi-module repositories.
2. **Audit mechanism**: A novel curation safeguard where agents can formally prove that a specification is unsatisfiable or reference code is incorrect, surfacing and correcting latent errors during dataset creation.
3. **Empirical evaluation**: Comprehensive testing of frontier LLM-based coding agents (with Lean toolchain access), showing that the strongest agents fail on most hard instances and solve zero specifications on the hardest repositories.
4. **Structured evaluation modes**: Support for both "proof-only" (given implementation, synthesize proof) and "code-and-proof" (synthesize both) tasks, clarifying where agents struggle most.

## Connections to Other Work
This work sits at the intersection of [[agents]], code generation (often powered by [[large-language-models]]), and formal methods. It builds on prior efforts in automatic theorem proving and verified code generation but extends the scope from toy functions to realistic multi-file systems. Related efforts like DeepSeek-Prover and other proof assistants target isolated theorems or lemmas; Vero demands coherent reasoning across module boundaries. The benchmark also relates to broader questions about [[alignment]] — ensuring AI systems produce trustworthy, verifiable artifacts — and to mechanistic understanding of how [[large-language-models]] reason about logical constraints over extended contexts.

## Practical Applications
1. **Safety-critical systems**: Automatic generation of formally verified code for aerospace, medical devices, and automotive control systems where bugs are intolerable.
2. **Cryptographic libraries**: Synthesis of provably correct implementations of protocols and encryption schemes, reducing the human effort and error risk in security-sensitive software.
3. **Smart contract development**: Automated synthesis of formally verified blockchain code to prevent costly exploits and theft.
4. **Distributed systems**: Auto-generation of consensus protocols and replication schemes with machine-checked proofs of safety properties (e.g., linearizability, eventual consistency).
5. **Regulatory compliance**: Automated code generation for finance and healthcare systems where regulatory bodies increasingly demand formal assurance.

## Product & Startup Ideas
1. **Verified Code-as-a-Service**: A cloud platform where engineers specify requirements in natural language or formal logic; the system auto-generates and formally verifies critical code modules, with human-in-the-loop review gates.
2. **AI-Powered Smart Contract Auditor & Generator**: Firms deploy LLM agents to synthesize, verify, and audit blockchain contracts before deployment, dramatically reducing audit costs and exploits.
3. **Formal Verification IDE Plugin**: A VSCode/IDE extension that uses agents to suggest implementations paired with formal proofs as developers code, enabling "proof as you type."
4. **Regulatory Compliance Engine**: Automated system that translates compliance rules (e.g., HIPAA, PCI-DSS) into formal specifications, then synthesizes and verifies that codebases satisfy them.
5. **Continuous Verification for DevOps**: A CI/CD tool that runs agents on pull requests to verify critical modules (database queries, auth logic, payment processing) before merge, blocking unproven code.

## Technical Limitations
1. **Scalability bottleneck**: Current agents handle only 43 curated instances; real-world repositories are vastly larger and more complex, with hundreds or thousands of interdependent modules.
2. **Module coupling**: The approach requires agents to understand and maintain invariants across multiple modules and namespaces—a hard reasoning problem that grows combinatorially with codebase size.
3. **Specification burden**: Each instance requires manually curated formal specifications; this is labor-intensive and does not scale. Real software rarely ships with formal specs, so adoption requires culture and tooling shifts.
4. **Proof search complexity**: Formal proof search is computationally expensive; agents must balance exploration (trying many proof strategies) against computational budgets. The paper does not deeply address this trade-off.
5. **Language brittleness**: Agents must generate syntactically and semantically correct Lean/Dafny code; small errors halt proof search. The agents show low robustness to specification changes or non-standard problem formulations.
6. **Hardest instances unsolved**: Zero progress on the hardest repositories suggests the benchmark may expose fundamental limits in current LLM reasoning for complex formal logic, not just engineering gaps.

## Open Questions
1. Can agents learn from failed proof attempts to iteratively refine implementations, rather than starting fresh each time?
2. How much does pre-training on formal code and theorem databases help, versus general language model capabilities?
3. Can hierarchical or modular decomposition strategies (breaking a repository into smaller subgoals) improve success rates on complex instances?
4. What is the minimum human guidance (e.g., proof sketches, hints on key lemmas) needed to unlock progress on hard repositories?
5. Do different formal languages (Lean, Coq, Dafny) require fundamentally different agent architectures, or is there a universal strategy?
6. How do agents handle underspecified or ambiguous requirements—a common real-world scenario—in formal settings where precision is mandatory?

## Key Takeaway
AI agents cannot yet build trustworthy verified codebases at scale; a new benchmark shows most fail on multi-module repositories.
