# From Mixing to Tearing: Graph Decomposition in Decentralized Optimization via Message Passing

**Authors:** Kuangyu Ding, Gesualdo Scutari
**Published:** 2026-10-02 | **arXiv:** [2610.03709v1](http://arxiv.org/abs/2610.03709v1)

## Summary
This paper develops a new framework for decentralized optimization where multiple agents cooperatively minimize objective functions over a network graph, communicating only with neighbors. Instead of existing approaches that use the graph primarily to mix information, the authors jointly design both the optimization subproblems and the communication protocol by decomposing the graph into tree-structured blocks—a technique they call GATE (Graph-Tearing message passing). This approach is theoretically more principled and computationally more efficient than prior gossip or tree-routing methods.

## Theoretical Background
Decentralized optimization addresses problems where objective functions are distributed across agents in a network: agent *i* holds function *f_i* and wants to minimize the sum *Σf_i* using only local computation and neighbor-to-neighbor communication. Prior work falls into two camps: **gossip algorithms** (which repeatedly average information across the network) and **spanning-tree methods** (which route information hierarchically). Both treat the network structure as a constraint on *how* to communicate, but don't jointly design the optimization decomposition itself. This paper builds on **dual decomposition** and **message passing** frameworks from convex optimization, extending them to exploit graph structure more deeply. The functions are assumed smooth and strongly convex—standard regularity conditions that enable linear convergence guarantees.

## Core Contributions
1. **Joint design framework**: A first-principles approach that simultaneously chooses (a) how to represent agent agreement constraints as dual variables, (b) how to partition those variables into blocks optimized together, and (c) which connected clusters of agents cooperatively solve each block over their assigned subgraph.

2. **GATE algorithm**: A concrete instantiation using one variable per edge and tree-structured blocks. Agents update edge variables by solving local cost-to-go minimizations and applying relaxation; messages propagate via tree recursion.

3. **GATE-S (surrogate variant)**: A computationally lighter version using tractable local surrogates and compact message representations to reduce per-iteration overhead.

4. **Explicit convergence rate**: Proves linear convergence with a rate that transparently depends on function regularity, network topology, and the chosen graph partition—revealing how decomposition quality affects performance.

## Connections to Other Work
This work sits at the intersection of [[distributed optimization]], [[convex optimization]], and **graph algorithms**. It differs from [[gossip algorithms]] (e.g., dual averaging) by moving beyond simple averaging and from [[spanning-tree methods]] by considering richer block structures. The dual decomposition perspective connects to **Lagrangian relaxation** and **augmented Lagrangian methods**, but adapted to the decentralized, message-passing setting. The graph-tearing idea parallels **graph partitioning** techniques in domain decomposition for PDE solving, but applied to optimization. It also relates conceptually to [[multi-agent-systems]] work on cooperative control, though with a more rigorous optimization lens.

## Practical Applications
1. **Distributed machine learning**: Training models across edge devices (phones, IoT sensors) where data is locally held and communication bandwidth is limited—e.g., federated learning on sparse networks.

2. **Smart grid optimization**: Agents represent distributed energy resources (solar panels, batteries, EV chargers) at each household, cooperatively minimizing total cost or emissions subject to local physics constraints and mesh network connectivity.

3. **Supply chain coordination**: Suppliers and manufacturers in a network jointly optimize production and logistics decisions with only local (supplier–customer) communication.

4. **Sensor network resource allocation**: Distributed agents (sensors) in a spatial network optimize sampling strategies and power allocation while communicating only with nearby neighbors.

## Product & Startup Ideas
1. **Federated ML platform for IoT**: A commercial framework that automatically decomposes a device network and orchestrates decentralized training with minimal bandwidth—targeting smart home and industrial IoT.

2. **Decentralized energy trading platform**: Software that enables households with solar/batteries to optimize collective storage and trading via a mesh protocol (no central server), using GATE-style decomposition for real-time pricing.

3. **Privacy-preserving analytics SaaS**: A B2B service allowing firms to train collaborative models across multiple organizations (hospitals, banks) without central data aggregation, using the framework for regulatory compliance.

4. **Supply chain optimization as a service**: Cloud-managed optimization engine that coordinates distributed suppliers using lightweight message passing—reduces communication overhead vs. traditional central coordinators.

5. **Decentralized autonomous systems simulator**: A development toolkit for robotics/drone swarms to cooperatively plan and optimize in GPS-denied environments, emphasizing graph-aware message passing.

## Technical Limitations
1. **Strongly convex assumption**: The theory requires strong convexity; non-convex objectives (common in deep learning) are not covered and likely require different techniques.

2. **Smooth functions**: Assumes all functions are differentiable with bounded Hessians; non-smooth or discontinuous cost functions are out of scope.

3. **Fixed network topology**: The graph is assumed static; dynamic topology changes (agents joining/leaving, link failures) are not analyzed.

4. **Synchronous updates**: Analysis assumes all agents update synchronously; asynchrony introduces additional algorithmic and theoretical challenges not addressed here.

5. **Tree-block assumption in GATE**: Restricting to tree-structured blocks may be suboptimal for graphs with dense substructure (e.g., cliques); the trade-off between decomposition flexibility and computational cost is not fully explored.

6. **Scalability of message passing**: As the network grows, the number of messages per iteration could still grow significantly—practical scalability to millions of agents is unclear.

## Open Questions
1. **Non-convex extensions**: Can the graph-tearing framework be extended to non-convex optimization (e.g., training neural networks in a federated setting)? What convergence rates are achievable?

2. **Asynchronous variants**: How does asynchrony (agents updating at different rates, stale information) affect the linear convergence rate? Can GATE-S tolerate significant delays?

3. **Adaptive decomposition**: Can the graph partition be chosen or updated adaptively based on network conditions or function structure, rather than fixed a priori?

4. **Non-uniform edge costs**: What if communication costs vary across edges (e.g., low-bandwidth links)? Should the decomposition weight edges differently?

5. **Empirical large-scale benchmarks**: How does GATE scale on realistic networks (100s or 1000s of agents)? How does it compare to recent gossip variants on real federated learning tasks?

6. **Graph heterogeneity**: How do properties like power-law degree distributions or community structure in real networks affect the optimal decomposition strategy?

## Key Takeaway
Graph decomposition into cooperating tree blocks enables agents to solve convex problems faster with less communication than prior gossip or tree-routing methods.
