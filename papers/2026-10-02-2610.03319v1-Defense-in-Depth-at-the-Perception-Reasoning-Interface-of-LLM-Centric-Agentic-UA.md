# Defense-in-Depth at the Perception-Reasoning Interface of LLM-Centric Agentic UAV Swarms

**Authors:** Mohammadhossein Homaei, Yousef Emami, Sajad Homayoun, Rahim Taheri, Hao Zhou et al.
**Published:** 2026-10-02 | **arXiv:** [2610.03319v1](http://arxiv.org/abs/2610.03319v1)

## Summary

This paper addresses adversarial attacks on LLM-powered UAV swarms by implementing a layered defense system at the perception-reasoning interface—the boundary where sensor data enters the language model's decision-making. The authors show that an attacker can redirect drone operations by tampering with structured sensor reports without modifying the model itself, and they implement and test five defensive layers that detect corrupted data before it influences the swarm's schedule.

## Theoretical Background

The work builds on two established concepts: (1) adversarial robustness in machine learning systems, which studies how models behave when inputs are deliberately manipulated; and (2) defense-in-depth, a security principle from systems architecture that uses multiple independent checks rather than relying on a single barrier. LLM-centric agentic systems—where language models read structured data and output decisions that control physical systems—represent a newer frontier where traditional ML robustness meets real-world consequences. The paper treats the LLM as a reasoning engine that reads sensor telemetry and schedules which UAVs visit which targets, making the input sanitization problem critical.

## Core Contributions

1. **Practical implementation and evaluation** of five-layer defense at the perception-reasoning interface, moving beyond theoretical proposals to real system testing.
2. **Closed-form derivation** of attack boundaries for three input-side detectors, allowing deployable thresholds to be computed from system parameters (swarm geometry, service history) without waiting for attack data.
3. **Quantified trade-offs**: the paper measures the cost of defense (79%–74% schedule degradation when rejecting reports) and shows that a safety layer (checking for sensor starvation) reduces attack impact by 37.5% without detecting attacks directly.
4. **Validation that prediction matches measurement** across thirty matched simulation runs, establishing credibility of the closed-form bounds.

## Connections to Other Work

This work sits at the intersection of [[alignment]] concerns (ensuring deployed LLM agents behave as intended despite adversarial inputs), [[multi-agent-systems]] security (protecting coordinated swarms from single-point-of-failure vulnerabilities), and input validation patterns from both traditional cybersecurity and [[mechanistic-interpretability]] (understanding what triggers model decisions). It complements work on adversarial robustness of neural networks but focuses on the structural layer where data enters the reasoning loop, rather than on model internals. The defense-in-depth approach echoes principles used in high-assurance systems but applies them specifically to the LLM interface.

## Practical Applications

1. **Autonomous sensor networks**: Agricultural or environmental monitoring systems using drone swarms that must ignore spoofed data from compromised sensors.
2. **Logistics and delivery coordination**: Multi-agent route planning systems where sensor inputs (package locations, traffic, weather) could be manipulated to disrupt operations.
3. **Search and rescue operations**: Swarms responding to reported emergency locations must reject false reports that redirect resources from genuine incidents.
4. **Military or border surveillance**: UAV swarms that must continue effective patrols despite adversarial jamming or spoofed position/status reports from ground sensors.
5. **Smart grid management**: Distributed energy systems using LLM agents to balance load across sensors—must reject tampered supply/demand reports.

## Technical Limitations

1. **Assumes structured input format**: The defense relies on predictable, machine-readable sensor reports; adversaries could exploit format ambiguities or inject data that bypasses parsing entirely.
2. **No defense against model-level attacks**: If an attacker can modify LLM weights, prompt-inject, or control the deterministic fallback scheduler, the entire architecture collapses.
3. **Performance penalty is substantial**: A 74%–79% cost increase in normal operation may be unacceptable for time-critical or efficiency-constrained applications, forcing real deployments to accept weaker defenses.
4. **Closed-form bounds assume linear/geometric relationships**: Real sensor errors may be non-linear or correlated; the paper derives boundaries for simple distortion models and may not capture complex attack patterns.
5. **Limited adversary model**: Tests assume the attacker can only manipulate input values, not introduce delays, ordering changes, or multi-report coordinated attacks.
6. **Deterministic fallback is brittle**: Reverting to the most recent accepted report is simple but may allow an attacker to freeze the schedule in a suboptimal state for an extended period.

## Open Questions

1. **Can defense layers be combined non-redundantly?** The paper shows each layer's independent performance—can we fuse them probabilistically to reduce false negatives without proportional cost increases?
2. **What happens with adversarial input sequences?** How does the defense perform against an attacker who sends a slow, coordinated stream of subtle distortions designed to evade each layer over time?
3. **Does the approach generalize to unstructured or visual sensor inputs?** Current work assumes numeric telemetry—can these principles extend to image-based reports that an LLM must parse?
4. **How do we tune defenses for unknown threat models?** The paper fixes thresholds from deployment parameters; can we add online learning or confidence intervals to adapt if the threat evolves?
5. **What is the optimal fallback strategy?** Rather than replaying the last accepted report, could a learned or hybrid scheduler further reduce cumulative cost while maintaining safety guarantees?
6. **Can we measure ground-truth swarm intent?** How would a real operator know whether a rejected report was actually an attack or a legitimate sensor failure, and how should that ambiguity inform the response?

## Key Takeaway

Layered input validation can block coordinated-drone redirection attacks with quantified trade-offs, but defenders pay 74–79% performance costs to prevent adversary control.
