# Explainable Reinforcement Learning for assisting Air Traffic Controllers

**Authors:** Anduel Mehmeti, Gabriella Gigante, Salvatore Venticinque
**Published:** 2026-07-24 | **arXiv:** [2607.22525v1](http://arxiv.org/abs/2607.22525v1)

## Summary
This paper applies explainability techniques to reinforcement learning agents operating in air traffic control, a safety-critical domain where humans must trust AI decisions. The authors train an RL agent to plan alternative flight routes while avoiding restricted airspace, then use saliency maps to show controllers which input features most influenced the agent's choices. The work addresses a fundamental barrier to AI adoption in aviation: establishing human trust through transparency.

## Theoretical Background
Reinforcement learning (RL) trains agents to maximize cumulative reward by learning from interaction with an environment — the agent observes state, takes action, receives reward, and refines its policy over time. Deep RL scales this to complex problems but produces "black box" policies that are opaque even to their developers. Explainability in AI refers to techniques that interpret or visualize what a model learned; saliency maps are a common approach that highlight which input features most strongly activated a model's output. Air traffic control is inherently a sequential decision problem: controllers must route aircraft safely while minimizing delays, making it a natural fit for RL. However, aviation is safety-critical — mistakes can cause accidents — so pilots and controllers must understand and trust automated recommendations before accepting them.

## Core Contributions
The paper demonstrates a concrete pipeline for explaining RL decisions in ATC: (1) training an RL agent in a simplified ATC simulator to generate conflict-free flight paths, (2) applying saliency maps to visualize which state features (e.g., aircraft positions, restricted zones, velocities) drove each routing decision, and (3) validating that explanations are interpretable to domain experts (air traffic controllers). This is the first work combining RL explainability with operational ATC constraints in a unified framework, moving beyond generic RL + interpretability research into a domain-specific application.

## Connections to Other Work
This bridges [[Reinforcement Learning]] and [[Mechanistic Interpretability]] — the paper sits at the intersection of RL policy learning and explainable AI (XAI). It relates to broader work on [[alignment]] and human-AI collaboration in safety-critical settings (comparable to autonomous driving and robotics). Saliency maps are a classical interpretability tool; the novelty lies in applying them to RL in aviation rather than inventing new explanation methods. The work also connects to multi-agent path planning (relevant when multiple aircraft must coordinate) and the broader challenge of trustworthy automation in human-critical loops.

## Practical Applications
- **Controller decision support**: Controllers use the agent's recommendations alongside saliency maps to understand *why* the system suggested a particular reroute, enabling faster acceptance or override.
- **Training and certification**: Regulators (FAA, EASA) require explainability for autonomous systems; this methodology provides evidence that an RL-based routing system is interpretable and safe.
- **Conflict resolution**: During peak traffic, the system proposes alternative routes to resolve conflicts; controllers see which aircraft positions or airspace constraints drove each suggestion.
- **Safety auditing**: Post-incident analysis — if an RL system made a questionable decision, inspectors can replay the saliency maps to verify the decision followed expected logic and identify retraining needs.

## Technical Limitations
- **Simplified environment**: The testbed does not reflect real ATC complexity (wind, sensor noise, dynamic airspace changes, wake vortex constraints, human controller overrides). Scalability to 100+ simultaneous aircraft is unproven.
- **Saliency maps as proxy for trust**: Saliency visualizations show feature importance but do not guarantee the agent's reasoning is sound; a controller might misinterpret a saliency map or the map might highlight spurious correlations learned by the network.
- **Single-agent scope**: Real ATC involves multiple aircraft agents; the paper does not address multi-agent RL explainability, where agent interactions create emergent behaviors.
- **Regulatory gap**: Aviation regulators (FAA) have not yet formally approved AI-driven routing; the paper does not address certification pathways or formal verification requirements.
- **Human evaluation**: No user studies with actual controllers; claimed interpretability is not validated empirically.

## Open Questions
- How do saliency-based explanations scale to hundred-aircraft scenarios with continuous state spaces?
- Can controllers reliably distinguish between correct and incorrect RL decisions when only shown saliency maps? (requires user study)
- How should explanations adapt to controller expertise level (novice vs. veteran)?
- Can formal verification methods (e.g., reachability analysis) complement saliency maps to provide stronger safety guarantees?
- Does multi-agent RL — where aircraft coordinate — remain explainable, or does agent-agent interaction create opacity?
- What is the minimal saliency threshold for a controller to trust a recommendation?

## Key Takeaway
Saliency maps can help air traffic controllers understand and trust RL-based routing recommendations, bridging AI automation and human oversight in safety-critical aviation.
