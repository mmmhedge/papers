# Deep Agentic Search for Repository-Level Code Question Answering: An Empirical Study

**Authors:** Amirkia Rafiei Oskooei, Bora Ilci, Alperen Kayim, Mehmet Egemen Uzun, Berat Can et al.
**Published:** 2026-08-02 | **arXiv:** [2608.01507v1](http://arxiv.org/abs/2608.01507v1)

## Summary
This paper empirically compares two architectural approaches for code-based question answering over repositories: semantic search (using vector indices) versus deep agentic search (delegating exploration to a specialized subagent). The key finding is counterintuitive — semantic search significantly outperforms the increasingly popular deep agentic approach (65.2% vs 46.2% accuracy) while costing less than half as much, revealing that the "context pollution" problem deep agentic search aims to solve may introduce new failure modes at agent handoff points.

## Theoretical Background
Modern code agents — AI systems designed to read, understand, and answer questions about large codebases — face two competing challenges. First, repository code is massive and unstructured; agents need a way to locate relevant code efficiently. Second, [[large language models]] suffer from "context pollution" or "context rot," where irrelevant information accumulated in the context window degrades reasoning quality. Semantic search addresses the first challenge by pre-indexing code into a vector database (using embeddings — numerical representations of meaning). Deep agentic search addresses both by introducing a hierarchical [[multi-agent-systems|multi-agent]] architecture: a main planning agent delegates search to a specialized subagent with a limited context window, reducing pollution but requiring coordination. The paper evaluates which trade-off better serves repository-level code question answering on the SWE-QA benchmark.

## Core Contributions
1. **Empirical comparison on a realistic benchmark**: First rigorous head-to-head evaluation of semantic search vs. deep agentic search on SWE-QA, showing semantic search wins decisively (65.2% vs 46.2% accuracy).
2. **Cost analysis**: Demonstrates semantic search achieves correct answers at less than half the computational cost of deep agentic search.
3. **Failure mode taxonomy**: Coded all failures into a structured taxonomy, revealing that deep agentic search's largest failure class (41.8%) occurs silently at the planner–subagent handoff, where agents produce fluent but incorrect answers.
4. **Challenge to architectural assumptions**: Contradicts the implicit assumption in recent production code agents (Claude Code, Codex, Antigravity) that deep agentic search is superior for context engineering.

## Connections to Other Work
This work directly critiques the architectural choice adopted by recent [[large-language-models|LLM]]-based code systems. It relates to broader work on [[agents|agent architectures]] and [[multi-agent-systems]] (hierarchical vs. flat designs), [[mechanistic-interpretability|interpretability]] of agent reasoning (the "fluent but wrong" failure mode), and retrieval-augmented generation (RAG) — the practice of grounding language models with external knowledge. The failure mode analysis echoes concerns in [[alignment]] literature about deceptive failures and confident incorrectness in AI systems. The cost analysis connects to optimization concerns in deployed code agents.

## Practical Applications
1. **Production code agents**: Guide architectural decisions for IDE plugins, CI/CD assistants, and repository exploration tools (VS Code plugins, GitHub Copilot variants, Cursor, etc.).
2. **Enterprise code search**: Inform whether companies should invest in semantic indexing infrastructure for internal codebases vs. agentic exploration.
3. **Bug bounty and security tools**: Tools that must locate vulnerabilities in large repos should prefer semantic search's higher accuracy and lower latency.
4. **Code review automation**: Systems that answer code review questions ("where is this variable defined?") can now be designed more efficiently.
5. **Developer onboarding**: Reduce time for new engineers to learn large codebases by deploying semantic search backends.

## Product & Startup Ideas
1. **Smart Repository Search Engine**: A SaaS layer that indexes proprietary or open-source codebases and offers a semantic search API, positioning it as the cheaper/faster alternative to agentic search for engineering teams.
2. **Agentic Search with Fallback Optimization**: A middleware service that combines both approaches — try agentic search first for complex questions, fall back to semantic search for efficiency, learning which questions suit which mode.
3. **Failure Detection for Code Agents**: A monitoring product that detects "confident but wrong" answers from code agents (the silent failure mode), flagging them for human review before they reach engineers.
4. **Repository Indexing for Legacy Systems**: Automated semantic indexing service for enterprises with massive undocumented codebases, enabling fast code Q&A without requiring agentic agents.
5. **Developer Analytics Dashboard**: Track repository question patterns and index effectiveness, helping teams understand which parts of their codebase are most searched and recommend areas for documentation.

## Technical Limitations
1. **Benchmark specificity**: Evaluation limited to SWE-QA (read-only Q&A). The results may not generalize to code modification, generation, or multi-step reasoning tasks where agentic exploration might shine.
2. **Single taxonomy, human-coded failures**: Failure categorization is manual and potentially prone to coder bias; no inter-rater reliability metrics reported.
3. **No error analysis of semantic search**: The paper doesn't deeply examine why semantic search fails on the 34.8% of questions it misses — weak baselines may inflate apparent success.
4. **Hyperparameter and prompt optimization**: Unclear whether deep agentic search was optimized equally well as semantic search; prompt engineering and temperature tuning could shift results.
5. **Scalability not addressed**: No analysis of how both approaches scale to 10M+ line codebases or how retrieval latency affects real-time agent performance.
6. **Context window size assumption**: Results may be specific to current LLM context windows; future longer contexts could reduce the need for subagent delegation.

## Open Questions
1. **Hybrid architectures**: Can a smarter router use question characteristics to decide between semantic search and agentic search per query? Would an ensemble approach outperform both?
2. **Why the handoff fails**: What specific prompt formulations, context lengths, or agent coordination patterns cause the 41.8% of silent failures? Can better instruction engineering fix them?
3. **Generalization to other tasks**: How do the results change for code generation, modification, debugging, or multi-file refactoring tasks?
4. **Retrieval quality vs. agentic reasoning**: Is the gap purely a retrieval problem (semantic search finds better code), or does deep agentic search actually hurt reasoning itself?
5. **User experience and trust**: How do users perceive failures in each approach? Do confident-but-wrong answers erode trust more than "not found" responses?
6. **Cost-accuracy trade-offs**: Can simpler agentic designs (e.g., single-shot instead of iterative) close the cost gap while maintaining higher accuracy?

## Key Takeaway
Semantic search outperforms hierarchical agentic search for code Q&A: higher accuracy, half the cost, fewer silent failures.
