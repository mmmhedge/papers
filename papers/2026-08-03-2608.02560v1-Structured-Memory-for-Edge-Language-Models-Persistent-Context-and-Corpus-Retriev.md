# Structured Memory for Edge Language Models: Persistent Context and Corpus Retrieval via O(1) SSM State Injection

**Authors:** Anusha Madan Gopal, Aras Pirbadian, Kristofor D. Carlson, M Anthony Lewis, Jonathan Tapson
**Published:** 2026-08-03 | **arXiv:** [2608.02560v1](http://arxiv.org/abs/2608.02560v1)

## Summary
This paper introduces PRECOG, a retrieval mechanism that speeds up language models by pre-encoding document corpora as fixed neural states and injecting them directly during inference, rather than re-reading them each time. By exploiting a unique property of State-Space Models (SSMs) — their fixed-size hidden states — the authors achieve a 4500× speedup in retrieval latency on edge hardware while maintaining answer quality, making interactive language model inference practical on resource-constrained devices.

## Theoretical Background
Retrieval-augmented generation (RAG) augments language models with external knowledge by retrieving relevant documents and prepending them as context, but this incurs a "prefill cost" — the model must re-process all retrieved text before answering. Transformer models (the dominant architecture) store all processed context in a "KV-cache" that grows linearly with input length, making long-context retrieval expensive. State-Space Models (SSMs — recurrent architectures like Mamba that process sequences via hidden state dynamics) avoid this cache explosion by maintaining a fixed-size hidden state that summarizes everything read so far, regardless of sequence length. The key insight here is that an SSM's hidden state is "position-agnostic" — it encodes context information in a way that doesn't depend on where in the sequence that information appeared.

## Core Contributions
1. **PRECOG (Pre-Computed Context Injection)**: A mechanism that pre-encodes entire document corpora offline as SSM hidden states, then retrieves and injects the matching state directly at query time in O(1) time, bypassing the O(L_context) prefill cost entirely. This is architecturally impossible for Transformers because their KV-caches are "position-entangled" (context placement matters).

2. **SMC (Structured Memory Consolidation)**: A hierarchical persistent memory system that consolidates short-term episodic memories (recent conversation states) into long-term semantic memory (domain-clustered summaries) using the same state-injection mechanism, with adjustable storage-fidelity tradeoffs and O(1) session initialization.

3. **Empirical validation on edge hardware**: Demonstrates the system on TENNs-LLM (a 1.2B-parameter gated-SSM) with a 192 KB hidden state, achieving ~4500× latency reduction (27 seconds → 6 milliseconds per query) while matching in-context RAG answer quality.

## Connections to Other Work
This builds on recent SSM architectures ([[Mamba]]-style models) and challenges the Transformer dominance in long-context modeling. It relates to broader RAG approaches (e.g., [[REALM]], [[DPR]]) but sidesteps their prefill bottleneck through architectural choice. The hierarchical memory mechanism echoes cognitive science work on episodic vs. semantic memory consolidation. It also connects to edge AI and model compression literature — achieving practical inference on low-power devices without quantization tricks.

## Practical Applications
1. **On-device chatbots**: Interactive conversational agents on smartphones, tablets, or IoT devices with personal knowledge bases (emails, notes, documents) without cloud round-trips.
2. **Real-time customer support**: Edge-deployed support bots that retrieve from a company's knowledge base in <10 ms, enabling live chat without latency.
3. **Autonomous robots**: Robots with persistent memory of past interactions and environments, injecting relevant context in constant time during navigation or task planning.
4. **Low-power monitoring systems**: Edge devices that continuously monitor sensor data and alert users by retrieving relevant historical context in real-time.
5. **Offline-first productivity tools**: Note-taking or writing apps that augment user text with relevant past notes retrieved instantly without network access.

## Product & Startup Ideas
1. **EdgeMemory**: An edge-first RAG platform that lets enterprises run domain-specific retrieval on-device, replacing cloud-based search APIs; sells as an API or SDK for mobile/IoT.
2. **PrivateChat**: A consumer app that runs a personal AI assistant locally on a phone, securely memorizing conversations and documents without sending data to the cloud.
3. **RobotCognition**: A robotics middleware that equips robots with persistent, fast episodic memory; enables real-time task learning and context-aware manipulation.
4. **EdgeKnowledge**: A B2B SaaS platform that helps organizations pre-encode their corpora as SSM states and deploy retrieval-augmented models on edge hardware with sub-millisecond latency.
5. **MemoryOS**: A personal OS-level memory layer for devices that consolidates user data (photos, messages, documents) into queryable semantic memory, accessible to any local app without permission dialogs.

## Technical Limitations
1. **SSM-only approach**: The mechanism is fundamentally tied to SSM architectures; it does NOT work with Transformers (the current standard in industry). Limited to SSM model sizes and architectures available today.
2. **Hidden state size constraints**: Larger hidden states (>192 KB) may become impractical for edge deployment; the fidelity-vs-storage tradeoff may limit answer quality on large, diverse corpora.
3. **Offline pre-encoding latency**: Corpora must be pre-encoded before deployment; updating with new documents requires re-encoding and redeployment, not suitable for real-time corpus growth.
4. **Evaluated only on one model**: TENNs-LLM is a relatively small 1.2B-parameter model; unclear how this scales to larger SSMs or how answer quality degrades as corpus size grows.
5. **No comparison to pruning/quantization**: The paper does not compare against aggressive KV-cache pruning or quantization tricks on Transformers, which might close some of the latency gap.
6. **Domain-specific clustering**: SMC's "cognitive-domain clustering" requires manual or learned domain definitions; no guidance on how to set this for arbitrary corpora.

## Open Questions
1. **Scaling**: How does PRECOG perform with very large corpora (millions of documents)? Is there a state-injection search cost as the index grows?
2. **Update dynamics**: Can corpora be updated incrementally without full re-encoding? Can you merge or patch pre-encoded states?
3. **Hybrid retrieval**: How do you combine PRECOG with sparse retrieval (BM25) or multi-hop reasoning that requires refining queries?
4. **State alignment**: Does an SSM state from one checkpoint align with states from a different model version? Can you transfer pre-encoded corpora across model updates?
5. **Semantic fidelity**: How much information is lost when compressing a long document into a 192 KB hidden state? Is there a principled way to measure state "information capacity"?
6. **Larger models**: Does this scale to 7B, 13B, or larger SSM models? What is the latency-quality tradeoff as state size grows?

## Key Takeaway
SSMs enable ultra-fast corpus retrieval by pre-encoding documents as fixed neural states, making edge language models practical for real-time, offline-first applications.
