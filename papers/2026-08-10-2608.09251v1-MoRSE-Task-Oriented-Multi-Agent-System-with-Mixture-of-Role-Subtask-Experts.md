# MoRSE: Task-Oriented Multi-Agent System with Mixture of Role-Subtask Experts

**Authors:** Peiwen Li, Shiyang Zhang, Yangtian Zhang, Sizhuang He, David van Dijk et al.
**Published:** 2026-08-10 | **arXiv:** [2608.09251v1](http://arxiv.org/abs/2608.09251v1)

## Summary
This paper introduces MoRSE, a system that improves multi-agent LLM teams by giving each agent specialized skills through role and subtask assignment. Rather than using generic prompts for all agents, MoRSE decomposes tasks into dependency-aware subtasks, assigns agents specific roles, and fine-tunes their parameters separately — enabling agents to develop genuine expertise. The approach shows meaningful improvements on code-generation tasks while keeping computational costs low.

## Theoretical Background
Multi-agent systems using large language models have emerged as a promising approach for complex tasks by decomposing them across specialized agents. Prior work typically differentiates agents only at the prompt level — different instructions for different agents — but without changing the underlying model parameters. This paper builds on recent advances in parameter-efficient fine-tuning (specifically [[LoRA]] — Low-Rank Adaptation, a technique that adapts models by training small additional weight matrices rather than retraining everything) and mixture-of-experts architectures (systems that route inputs to specialized sub-networks). The work also draws on reinforcement learning methods for training agents with sparse rewards, particularly policy gradient approaches that assign credit for outcomes to the actions that caused them.

## Core Contributions
1. **Task-structured decomposition**: Formulates tasks as dependency-aware Directed Acyclic Graphs (DAGs) of subtasks, explicitly assigning each agent a (role, subtask) pair rather than using generic agent prompts.

2. **Dynamic Mixture of (role, subtask) LoRA Experts**: A parameter-level specialization module that gives each agent fine-tuned weights for its specific role-subtask combination, using a prototype-based semantic router to select which expertise to activate based on task context.

3. **Hierarchical group-relative policy optimization**: A credit-assignment algorithm designed for sparse task rewards that separately optimizes expert quality and routing quality, preventing routing variance from corrupting expert training signals.

4. **Empirical validation**: Demonstrates improvements on code-generation benchmarks across multiple LLM backbones, with specialization gains that generalize to held-out task categories and domains.

## Connections to Other Work
This work extends the multi-agent LLM paradigm (e.g., AutoGPT, multi-agent frameworks for complex reasoning) by moving beyond coarse prompt-level differentiation. It complements recent work on [[mixture-of-experts]] scaling for language models and builds on the [[LoRA]] family of parameter-efficient adaptation techniques. The hierarchical credit assignment connects to advances in multi-agent reinforcement learning, particularly methods that disentangle value estimation across agent actions. The task decomposition strategy is related to hierarchical reinforcement learning and planning-based approaches in multi-agent systems.

## Practical Applications
- **Software engineering teams**: Automating code generation tasks by assigning specialized roles (e.g., architect, implementer, tester) to agents, each with domain-specific parameter tuning.
- **Complex data analysis pipelines**: Decomposing analytics tasks into subtasks (data cleaning, feature engineering, modeling) with role-specialized agents.
- **Technical documentation generation**: Separate agents specializing in different doc types (API docs, tutorials, FAQs) with learned role-subtask expertise.
- **Automated testing and debugging**: Teams of agents with specialized knowledge for different code patterns, frameworks, or bug categories.

## Product & Startup Ideas
1. **CodeTeam AI**: A SaaS platform that automatically decomposes coding projects into subtasks and deploys a specialized multi-agent team to handle architecture, implementation, testing, and review with learned role expertise — targeting enterprises with large legacy codebases.

2. **Task Decomposition as a Service**: Infrastructure for organizations to convert their workflows (customer support, data pipelines, content creation) into role-subtask structures and automatically train agent teams with cost-effective specialization.

3. **MoRSE-powered Consulting Agent**: A B2B tool for management consulting firms that decomposes client projects into expert-routed subtasks (strategy, operations, digital transformation), with agents trained on domain-specific examples.

4. **Automated Curriculum Development**: EdTech platform that decomposes complex subjects into subtask DAGs and deploys specialized agent tutors for different learning objectives and student roles.

5. **Enterprise Process Automation**: Internal tool for large organizations to decompose business processes (HR onboarding, procurement, compliance workflows) into role-aware subtasks and deploy cost-efficient agent teams trained on real process data.

## Technical Limitations
- **Task decomposition bottleneck**: The approach assumes tasks can be decomposed into clear, dependency-aware DAGs. Many real-world tasks lack obvious structure or have circular dependencies; manual decomposition is needed and may not be optimal.
- **Prototype-based routing scalability**: The semantic router relies on prototype embeddings for subtasks — unclear how performance scales as task variety explodes or when new subtasks emerge dynamically.
- **Sparse reward training**: While the hierarchical credit assignment helps with sparse rewards, it assumes rewards can be attributed to task completion; partial-credit or continuous reward signals may be needed for true open-ended tasks.
- **Limited to code generation testing**: Evaluation focuses on code-generation benchmarks. Generalization to other domains (e.g., reasoning, creative writing, planning) is untested.
- **Computational and memory overhead**: Each agent maintains role-subtask LoRA weights; memory grows linearly with agent-role-subtask combinations. For very large teams or task spaces, this becomes prohibitive.
- **Coordination assumptions**: The DAG-based task structure assumes agents can execute subtasks in isolation. Tightly coupled, interactive subtasks may not benefit from this decomposition.

## Open Questions
- How does performance scale with DAG complexity and the number of (role, subtask) pairs? Is there a principled way to determine optimal decomposition depth?
- Can the prototype-based router adapt online as new subtasks are discovered, or does retraining degrade previously learned expertise?
- How does this compare to end-to-end multi-task LoRA or other parameter-sharing strategies across agents?
- Do agents develop interpretable, compositional specializations, or do the learned LoRA weights remain opaque?
- Can hierarchical credit assignment extend to tasks with stochastic subtask outcomes or where agent actions have delayed effects?
- How does the approach perform on tasks requiring tight real-time coordination (e.g., dialogue, negotiation) versus loosely coupled code generation?

## Key Takeaway
Specialized multi-agent LLM teams outperform generic ones when agents learn both task roles and parameter tuning for their assigned subtasks.
