# AdaEva: Accelerating LLM-Driven Algorithm Design with Adaptive Partial Evaluation

**Authors:** Tai Nguyen, Fei Liu, Phong Le, Carola Doerr, Nguyen Dang
**Published:** 2026-10-02 | **arXiv:** [2610.03896v1](http://arxiv.org/abs/2610.03896v1)

## Summary
This paper tackles the computational inefficiency of using LLMs to automatically design algorithms. The authors propose AdaEva, a framework that evaluates candidate algorithms on progressively larger subsets of test instances, dropping weak candidates early rather than fully evaluating every candidate—similar to how you'd eliminate bad job applicants after early interview rounds instead of running them through the entire hiring process.

## Theoretical Background
The work builds on two established ideas: *algorithm configuration* (automatically tuning algorithm hyperparameters using adaptive evaluation) and *LLM4AD* (using large language models to generate new algorithms). The paper treats algorithm design as a search problem where an LLM proposes candidate algorithms, and each must be evaluated on a pool of problem instances. The key insight is that instance-wise evaluation creates an opportunity: you don't need to run every candidate on all instances if you can statistically eliminate bad ones early. The framework uses two mechanisms from statistical testing: *successive halving* (repeatedly cut the worst half) and *statistical racing* (eliminate candidates when evidence is strong enough), both borrowed from hyperparameter optimization and model selection literature.

## Core Contributions
1. **AdaEva framework**: A modular, drop-in wrapper for any LLM4AD system that requires no changes to the underlying LLM or evaluation function.
2. **Two instantiations**: AdaEva-S (successive halving) and AdaEva-R (racing), both requiring no prior knowledge of which test instances are harder.
3. **Empirical validation**: Demonstrates consistent speedups across three different LLM4AD frameworks, multiple LLM backbones, and both combinatorial and continuous optimization domains, with improved test-set generalization as a bonus.
4. **Principled evaluation strategy**: Shows that adaptive partial evaluation balances computational load more efficiently than fixed subset strategies.

## Connections to Other Work
This connects to [[Bayesian optimization]] and hyperparameter tuning (where early stopping and successive halving are standard), [[RLHF]] and LLM training (where efficient evaluation is critical), and general [[neural architecture search]] (which faces similar computational constraints). The work is complementary to recent research on using LLMs for code generation and automated reasoning—it doesn't improve the LLM itself, but makes the feedback loop faster.

## Practical Applications
- **Automated algorithm design for combinatorial optimization**: Faster discovery of better sorting, graph, or scheduling algorithms.
- **Neural architecture search acceleration**: Evaluating candidate network designs more efficiently when using LLMs to propose architectures.
- **Scientific computing**: Rapidly iterating on algorithm candidates for physics simulations, PDEs, or numerical methods.
- **Hyperparameter optimization pipelines**: Reducing the cost of tuning machine learning systems when LLMs are used to suggest configurations.

## Product & Startup Ideas
1. **"AlgoAccel" — SaaS platform** for researchers that wraps existing LLM4AD tools and automatically applies AdaEva, selling as a drop-in optimizer for academic and industrial algorithm design workflows.
2. **Optimization algorithm marketplace** where users submit problem instances, LLMs generate candidates, and AdaEva's speedups allow pricing by "algorithm quality per compute dollar" rather than flat fees.
3. **AutoML middleware** that uses AdaEva-style progressive evaluation for neural architecture search, positioned as a cost-reduction layer for enterprise ML teams.
4. **Competitive algorithm discovery tool** for competitive programming platforms: let LLMs propose solutions and use adaptive evaluation to rank them faster, enabling real-time feedback.
5. **Consultancy service** optimizing expensive-to-evaluate simulation-based optimization (e.g., engineering design) by integrating LLM proposals with AdaEva's early stopping.

## Technical Limitations
- **Assumes instance homogeneity**: The framework doesn't explicitly account for heterogeneous instance difficulty; it learns implicitly through ranking. If instances cluster into "easy" and "hard" groups, it may waste evaluations on easy instances.
- **No theoretical guarantees**: The paper provides empirical evidence but no formal guarantees on solution quality or number of evaluations saved (regret bounds).
- **LLM quality dependence**: If the LLM generates many poor-quality candidates upfront, early elimination may discard the eventual best solution before it receives sufficient evaluation.
- **Evaluation cost assumption**: The framework assumes per-instance evaluation costs are comparable and non-trivial. If evaluation is cheap or costs vary wildly, the overhead of ranking may dominate.
- **Limited to ranking-based search**: Doesn't integrate with gradient-based or other continuous optimization strategies that might co-adapt the generation and evaluation.

## Open Questions
- **Can AdaEva be combined with feedback to the LLM?** Current framework only eliminates candidates; what if you could tell the LLM which types of candidates survive longest?
- **How does performance scale with instance-set size?** At what point does the overhead of managing multiple evaluation rounds outweigh the savings?
- **Instance-aware adaptive strategies**: Could you learn or estimate instance difficulty on-the-fly and allocate evaluations more intelligently?
- **Theoretical analysis**: Can you derive sample complexity or convergence guarantees showing when AdaEva provably saves evaluations?
- **Cross-domain transfer**: Do the tuning parameters (halving rates, racing thresholds) transfer across different problem domains, or must they be re-tuned?

## Key Takeaway
Adaptive partial evaluation cuts LLM algorithm design costs by dropping weak candidates early, without changing the LLM or evaluator.
