# RAPID: Robot Agentic Programming from Demonstrations

**Authors:** Yuyao Liu, Jiayuan Mao, David Hsu, Leslie Pack Kaelbling, Tomás Lozano-Pérez
**Published:** 2026-09-24 | **arXiv:** [2609.30249v1](http://arxiv.org/abs/2609.30249v1)

## Summary
This paper presents RAPID, a system that learns to program robots from a single human video demonstration. The key insight is using large language model agents to automatically generate, test, and refine executable robot code—treating robot programming like software debugging. This matters because it bridges the gap between high-level human intent (shown in video) and low-level robot control, making robot learning more practical and generalizable across different objects and environments.

## Theoretical Background
The work builds on two converging ideas: (1) **coding agents** — large language models that can write, execute, and iteratively improve code by treating a compiler or simulator as feedback; and (2) **learning from demonstrations** — inferring task structure from human examples. It also draws on **object-centric relational representations** from program synthesis and robotics, which focus on abstract relationships between objects rather than pixel-level details. The robot execution layer uses **trajectory optimization**, a classical control technique that computes smooth motions satisfying constraints (e.g., "move object A to location B").

## Core Contributions
1. **End-to-end inference pipeline**: Automatically extracts from a single visual demonstration: (i) a formal task specification (what success looks like), (ii) reusable action primitives (motion skills), and (iii) a simulation environment for verification.
2. **Object-centric program representation**: Programs express actions as trajectory-optimization constraints on object relationships rather than robot joint angles, enabling generalization to new poses, shapes, and materials.
3. **Iterative agentic refinement loop**: The LLM agent writes code, executes it in simulation, observes failures, and refines—similar to how human programmers debug.
4. **Empirical validation**: Demonstrated on contact-rich manipulation (nonprehensile tasks like pushing/sliding) and general prehensile tasks, with successful sim-to-real transfer to a physical Franka arm.

## Connections to Other Work
RAPID combines [[agents|agentic reasoning]] (LLMs as code generators/debuggers) with [[reinforcement-learning|robot learning]] and [[computer-vision|visual understanding]]. It relates to prior work on:
- **Program synthesis from demonstrations** — but uses agentic iteration rather than single-shot inference
- **Vision-language models for robotics** — here used to parse demonstrations and generate specs
- **Learning from observation** — inferring task intent without explicit reward signals
- **Sim-to-real transfer** — object-centric abstractions help bridge the gap
The novelty is coupling LLM-based code refinement with trajectory optimization and relational abstractions.

## Practical Applications
1. **Factory automation setup**: Workers show a robot one video of a new assembly task; RAPID generates generalizable code that works with parts of different sizes/materials.
2. **Household robotics**: Single demo of "clear the table" or "sort items by color" generalizes across different kitchens and objects.
3. **Logistics and warehousing**: Learning pick-and-place strategies for novel objects without manual programming.
4. **Medical/surgical assistance**: Inferring contact-sensitive manipulation (e.g., tissue handling) from expert demo videos.
5. **Robot customization**: End users can teach robots new tasks by demonstration rather than writing code or tuning parameters.

## Product & Startup Ideas
1. **"RobotCode Studio"** — A cloud platform where users upload 30-second videos of desired robot behaviors, and the system auto-generates portable, reusable robot programs (licensed per-deploy).
2. **"One-Shot Manufacturing"** — An on-premise system for small manufacturers to retrain robots for new product variants with zero programming; charge per production run or license fee.
3. **"Robotics-as-a-Service (RaaS) marketplace"** — Pre-trained RAPID agents for common tasks (packing, sorting, assembly); manufacturers subscribe and customize via video.
4. **"Sim-to-Real Studio"** — Developer tools for roboticists to create synthetic training environments, generate code via demonstrations, and automatically deploy to physical hardware.
5. **"Robot Programming IDE"** — Visual interface where users record demonstrations, see generated code, tweak it in a GUI, and verify in simulation before deployment—targeting non-ML engineers.

## Technical Limitations
1. **Single demonstration bottleneck**: While one demo is impressive, failure modes (e.g., ambiguous intent from video) are not discussed; unclear how performance degrades with harder-to-interpret tasks.
2. **Simulation fidelity**: Reliance on accurate physics simulation (contact, friction) for verification; sim-to-real gap may grow for tasks with tight tolerances or complex material interactions.
3. **Action primitives ceiling**: The system infers primitives from the demo, but if the demo uses a strategy the LLM hasn't seen before, or requires novel physics reasoning, generation may fail.
4. **Scalability unclear**: Tested on 8 tasks in simulation + sim-to-real transfer; unclear how it scales to 50+ task types or highly diverse domains.
5. **Generalization boundaries**: Claims generalization over pose/shape/material, but likely assumes similar task structure; generalization to fundamentally different task *types* not demonstrated.
6. **Computational cost**: Iterative LLM calls + trajectory optimization + simulation rollouts; wall-clock time and cost per task not reported.

## Open Questions
1. **Multi-demo learning**: How do multiple demonstrations improve robustness? Is there a sweet spot between 1 and N demos?
2. **Failure analysis & recovery**: When does the agentic loop get stuck? Can humans interactively guide refinement, or is it fully autonomous?
3. **Task compositionality**: Can learned programs compose—e.g., learning "move object A" and "move object B" then chaining them? How does this scale?
4. **Out-of-distribution robustness**: What breaks first when you push beyond pose/shape variation? (e.g., new physics, occlusion, lighting)
5. **Comparison to RL baselines**: How does one-shot RAPID compare to, say, 1000 interactive RL steps or 1000 simulated demos?
6. **Human interpretability**: Can humans read and understand the generated programs, or are they opaque? Does this matter for safety-critical robots?
7. **Real-time adaptation**: Can the system refine programs on-the-fly during deployment, or only in the lab?

## Key Takeaway
LLM agents can learn reusable robot programs from single video by automatically generating, testing, and refining code in simulation.
